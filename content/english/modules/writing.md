# Writing｜能力导学与训练模型 v1

> **定位**：Writing 的上位学习资产，也是第一次正式进入考研英语写作前的能力教材。  
> **适用状态**：学习者此前没有系统做过考研作文，需要先建立写作能力，再进入宝贵真题。  
> **用途**：学会“怎样从一个空白题目生成一篇合格作文”，并用合成任务训练关键动作；后续真实训练只在失败时展开必要部分。  
> **不是**：模板大全、范文背诵册、高级替换词表、老师课程目录、真题解析合集。  
> **上位原则**：先定义能力，再设计训练，再重组材料，最后才设计 UI。  
> **真题保护**：默认不使用未见真题做低层技能教学。框架学习、片段训练、受控完整练习优先使用合成题；fresh true exam 保留给后续 clean first attempt、考试适配和 transfer validation。

---

# 0｜先看全图：写作到底在做什么

考研作文最容易被误解成：

> 背几个模板 + 记一些高级词 + 上场往里面填内容。

这不是稳定的写作能力。

真正的任务是：

```text
看懂任务
→ 知道必须完成什么
→ 生成足够且相关的内容
→ 把内容排成清楚的结构
→ 用合适的英语把它实现出来
→ 控制错误和语域
→ 在规定时间里完成
```

可以压成六层：

```text
TASK
→ CONTENT
→ STRUCTURE
→ LANGUAGE REALIZATION
→ ERROR CONTROL
→ TIMED OUTPUT
```

这六层不是让你考试时机械默念的流程，而是**学习和复盘时用来判断“到底哪里坏了”**的地图。

熟练以后，正常状态应该越来越像：

> 看完题 → 很快知道写什么 → 很快知道怎么排 → 直接写。

框架只有在卡住、复盘或某一层反复出问题时才重新展开。

# 1｜什么叫“会写作文”

Writing 不是“能写出没有语法错误的句子”。

一个语法几乎没错、但没有完成任务、内容空、结构乱的作文，仍然不是有效写作。

反过来，一个观点清楚、任务完成、结构稳定，但语言不够漂亮的作文，至少已经具备可继续升级的写作骨架。

因此训练顺序不能反过来。

## 1.1 Task｜任务理解

第一层问题是：

> **这道题到底要我完成什么？**

至少要快速恢复：

- 我是谁 / 以什么身份写；
- 写给谁；
- 写作目的是什么；
- 必须覆盖哪些信息；
- 哪些内容只是可选；
- 语气需要多正式；
- 有没有格式 / 字数 / 图画或材料约束。

如果 Task 错了，后面英语写得再漂亮也救不回来。

训练时优先问：

> **如果把英语全部拿掉，只看任务，我能不能用一句中文说清“我要完成哪几件事”？**

能，才进入下一层。

## 1.2 Content｜内容生成

第二层不是“我要用什么高级词”，而是：

> **我到底有什么值得写？**

内容必须满足三个条件：

1. **相关**：回答题目，而不是写自己最熟悉的万能内容；
2. **足够**：有足够信息把任务做完整，而不是一句空话反复改写；
3. **可展开**：每个主要观点后面至少能继续说清一点“为什么 / 怎么样 / 有什么后果 / 具体是什么”。

内容贫乏是很多“写不出来”的真正原因。

它常被误判成词汇差：

> 脑子里其实没有明确要说的东西，于是感觉“我没有词”。

所以训练时必须先分清：

```text
没东西可写
≠
有东西但不会用英语写
```

这两个问题修法完全不同。

## 1.3 Structure｜结构组织

有了内容以后，要回答：

> **这些内容按什么顺序出现，读者才能一遍看懂？**

结构不是“必须三段”的形式主义，而是信息功能的安排。

一个段落应该有清楚任务。

例如小作文可能是：

```text
开头：建立情境 / 说明目的
中间：完成主要信息任务
结尾：提出期待 / 请求 / 收束
```

大作文可能是：

```text
第一段：准确呈现材料 / 图画核心信息
第二段：解释核心含义并展开
第三段：收束观点 / 提出意义、态度或行动
```

真正要学的不是背段落数，而是：

> **每一段为什么存在？删掉它会缺什么功能？**

## 1.4 Language Realization｜把想法变成英语

第四层才进入语言。

它包括：

- 选择合适词义和搭配；
- 把命题组织成英文句子；
- 选择句间连接；
- 调整语气和正式度；
- 使用自己真正能控制的句型；
- 在必要时表达因果、让步、比较、建议、期待、评价等关系。

核心标准不是“越高级越好”，而是：

> **准确、自然、稳定、够用。**

一个你能稳定写对的普通表达，通常比一个记得模糊、容易用错的“高级替换”更有考试价值。

## 1.5 Error Control｜错误控制

写作不是写完再统一找语法错误那么简单。

高价值错误控制包括：

- 主谓关系；
- 时态 / 时间关系；
- 单复数；
- 冠词；
- 代词指向；
- 句子是否完整；
- 搭配是否自然；
- 并列关系是否一致；
- 逻辑连接是否和真实关系一致；
- 拼写和标点；
- 小作文称呼、结尾、语域等明显执行问题。

但不要在第一句就反复修改十遍。

正常考试写作需要兼顾：

> **持续生成 + 低成本自检。**

## 1.6 Timed Output｜限时完整输出

最终能力不是“给我一个小时我能润色出一篇不错的作文”。

而是：

> **在真实考试时间压力下，仍能完成任务、结构稳定、语言错误受控。**

因此限时能力必须后期单独验证。

前期学习可以慢一点拆动作，但不能永远停在片段训练。

# 2｜Writing 和其他英语能力是什么关系

Writing 是独立能力，但不会凭空工作。

## 2.1 和 Lexical 的关系

Writing 会调用：

- sense；
- phrase；
- collocation；
- construction；
- register；
- confusable / contrast。

如果你明确知道想表达什么，但卡在一个词或搭配上，长期知识应回到 **LexicalOS**。

Writing 不建立第二套词汇数据库。

但 Writing 可以保留这次行为证据：

> “我在真实输出时想调用这个表达，但没能稳定调用。”

这种 production failure 比“我在词表里认识它”更有价值。

## 2.2 和 Reading 的关系

Reading 给 Writing 提供：

- 对自然英文的长期输入；
- 对论证和信息组织的感觉；
- 对语域和搭配的真实接触。

但“读得懂”不等于“写得出”。

Reading 是 recognition / representation，Writing 需要 active generation。

因此不能指望只靠多读范文就自动会写。

## 2.3 和 Translation 的关系

Translation 是：

```text
已有英文
→ 恢复意义
→ 生成中文
```

Writing 是：

```text
任务要求
→ 自己生成意义
→ 自己生成英文
```

Writing 不是 Translation 的反向版本。

如果写作时习惯先在脑中写完整中文，再逐句翻成英文，短期可以救急，但长期容易造成：

- 中文句式过重；
- 英文句子过长；
- 搭配不自然；
- 每句话生成成本过高。

初期可以允许用中文帮助澄清**内容**，但应该逐步把计划压缩成英文关键词 / 简短命题，而不是全文中译英。

# 3｜第一次学习 Writing 的正确顺序

对于“从来没正式练过考研作文”的学习者，直接拿珍贵真题裸写并不是最优起点。

原因不是怕做错，而是：

> **此时很多错误只是因为还没有建立基本动作。**

如果拿 fresh true exam 来教最基础的审题、段落功能和内容展开，相当于拿宝贵诊断资产做启蒙教材。

因此 Cold Start 分四个阶段。

```text
G0｜Framework Learn
↓
G1｜Component Drills（合成片段）
↓
G2｜Guided Full Output（合成完整题）
↓
G3｜Clean True-Exam Attempt
```

## 3.1 G0｜Framework Learn

目标：建立本 Guide 的母模型。

你不需要背术语，只需要真正理解：

```text
Task
→ Content
→ Structure
→ Language
→ Error Control
→ Timed Output
```

并且明白：

> 上游没做好，不要急着修下游。

### G0 出口

给你一道陌生任务时，即使暂时不写正文，你也能回答：

- 我要完成什么；
- 大概写哪些内容；
- 每一段承担什么功能；
- 现在最大的困难是在内容、结构还是语言。

做到这一点就可以进入 G1，不需要把整份 Guide 背完。

## 3.2 G1｜Component Drills

目标：**把完整写作拆成几个可练的动作，但不把这些碎片误当成最终学习单位。**

G1 默认使用合成题，不消耗真题。

重点训练：

```text
Task Parsing
Content Generation
Function Realization
Sentence Pair / Local Coherence
Paragraph Development
Register Control
Description / Interpretation
Error-Control Habits
```

这些片段训练相当于健身里的分动作训练。

它们的目的不是让你永远写片段，而是让第一次完整写作时已经有基本动作。

## 3.3 G2｜Guided Full Output

当组件能够基本执行后，用**合成的完整考试风格 prompt** 做完整作文。

此时可以允许轻量 scaffolding，例如：

- 写前先列 2–4 个 content atoms；
- 标记每段功能；
- 写完后按 checklist 自检。

但不能：

- 给现成段落让你拼；
- 给完整模板让你填空；
- 先展示 model essay 再要求“仿写”。

因为我们仍然需要看到真正的 generation ability。

## 3.4 G3｜Clean True-Exam Attempt

进入真题的条件不是“Guide 看完”。

而是：

> **面对合成完整题，已经能独立生成一篇结构完整、任务基本完成的作文。**

语言可以还不漂亮，时间也可以还不理想。

第一篇真题的价值是：

- 看你的能力是否能迁移到真实题面；
- 看考试任务有没有你在合成训练里没遇到的约束；
- 建立真实 baseline。

因此第一次真题必须尽量 clean：

- 不提前看范文；
- 不提前看老师解析；
- 不提前看写作思路；
- 不提前背针对这道题的模板。

# 4｜最小生成单位：从“一个意思”到“一篇作文”

Writing 的训练不能一上来只谈“整篇”，也不能永远只练句子。

我们需要知道几个层级。

## 4.1 Content Atom｜内容原子

Content atom 是：

> **一个可以独立回答“我要说什么”的最小意思。**

例如任务要求你推荐一个活动，你可能有：

```text
活动是什么
为什么适合对方
什么时候 / 哪里进行
参加后能得到什么
如何报名
```

这些首先是内容，不是句型。

初期训练可以先用中文或极简英文列出来。

重点是：

> 不允许用“万能句”伪装成内容。

例如：

> It is of great importance for us to...

这句话本身几乎没有信息。

## 4.2 Functional Move｜功能动作

小作文尤其依赖 communicative functions。

例如：

- explain purpose；
- invite；
- request；
- recommend；
- apologize；
- thank；
- inform；
- suggest；
- complain / report a problem；
- ask for information；
- express expectation；
- close politely。

学习对象不是“邀请信模板”，而是：

> **当我要完成邀请这个功能时，我有哪些稳定表达方式？**

同一个功能可以出现在不同题型里。

因此我们训练的是可迁移功能，不是背整封信。

## 4.3 Sentence Pair｜句对

很多作文问题不是单句语法，而是两句话之间没有关系。

片段训练必须包含：

```text
claim → reason
fact → implication
problem → consequence
recommendation → benefit
description → interpretation
position → support
```

目标是：

> 第二句为什么跟在第一句后面，读者一眼知道。

不要求每次都用 `Moreover / Therefore / However` 显式连接。

真正重要的是关系存在。

## 4.4 Paragraph｜段落

一个有效段落通常至少包含：

```text
段落任务
+
核心意思
+
必要展开
```

“展开”不是多写一句同义句。

可以通过：

- 原因；
- 机制；
- 后果；
- 例子；
- 对比；
- 具体说明；
- 条件 / 边界；
- 对读者的意义。

## 4.5 Full Composition｜完整作文

完整作文才是最终用户学习单位。

片段训练只是 cold-start 或 repair tool。

所以冻结：

> **正式 Writing Attempt 以一篇作文为一个学习单元。**

内部可以诊断到段、句、短语，但正常训练不能退化成“修了十个句子就等于练了一篇作文”。

# 5｜Small Writing｜小作文真正要学什么

小作文的核心不是“应用文格式很多”。

真正稳定的能力是：

> **在明确对象、目的和情境下，用合适语域完成若干 communicative functions。**

可以压成：

```text
Audience
→ Purpose
→ Required Moves
→ Useful Details
→ Register
→ Clear Close
```

## 5.1 Task Parsing｜先拆任务

每道小作文先回答五个问题：

### A｜Audience：写给谁

对方可能是：

- 朋友 / 同学；
- 老师 / 教授；
- 机构 / 工作人员；
- 陌生人；
- 群体读者。

这决定称呼、礼貌程度和表达距离。

### B｜Purpose：为什么写

一句话说清：

> 我希望这封文字完成什么？

例如：

- 邀请；
- 请求帮助；
- 推荐；
- 提供建议；
- 道歉；
- 感谢；
- 咨询；
- 通知；
- 解释情况。

### C｜Required Moves：题目硬性要求哪几件事

把 prompt 中的要求改写成 2–4 个功能动作。

不要直接开始写。

例如一个合成任务：

> Write to a visiting student, recommend one campus activity, explain why it may suit them, and tell them how to join.

先得到：

```text
1. 推荐什么活动
2. 为什么适合对方
3. 怎么参加
```

这三件事没完成，英语再漂亮也没有意义。

### D｜Useful Details：需要什么具体信息

小作文最怕空。

例如“欢迎参加，非常有意义，希望你喜欢”可以写很多句，但没有实际信息。

所以每个 required move 至少配一个具体 detail。

### E｜Register：应该怎么说

不是简单的“正式 / 不正式”二分。

要问：

- 能不能直接命令；
- 是否需要 soften request；
- 是否适合缩写；
- 是否可以很口语；
- 结尾要不要表达期待 / 感谢。

## 5.2 小作文的骨架应该多薄

我们需要骨架，但不要整篇模板。

一个足够薄的 stable skeleton 是：

```text
OPEN
为什么写 / 建立情境

BODY
按题目要求完成 2–4 个 communicative moves

CLOSE
下一步 / 期待 / 礼貌收束
```

这个 skeleton 几乎不会限制内容。

真正可变的是中间的 moves。

## 5.3 Function Library｜建立功能库，而不是模板库

### 说明写信目的

目标：第一两句让读者知道你为什么出现。

合成训练：

> 你要告诉交换生，本周六原定活动地点改变了。

先只写“purpose sentence”，不要写整封。

要求：

- 直接；
- 不绕；
- 不使用空泛开场。

### Request｜请求

请求至少包含：

```text
你希望对方做什么
+
必要时说明原因 / 时间
+
合适的礼貌程度
```

训练重点：

不要把礼貌误解成堆叠 `I would be extremely grateful if...`。

真正目标是：

> 清楚 + 合适。

### Suggest / Recommend｜建议 / 推荐

高质量建议不是：

> I strongly recommend it because it is very meaningful.

而是：

```text
建议什么
→ 为什么和对方 / 情境匹配
→ 必要时给出具体执行信息
```

### Apologize｜道歉

不只是 `I am sorry`。

通常需要：

```text
承认具体问题
→ 简洁解释（如果必要）
→ 补救 / 下一步
```

### Thank｜感谢

避免整段只是在加强情绪。

更有价值的是：

```text
感谢什么具体行为
→ 它带来了什么具体帮助 / 影响
```

### Invite｜邀请

至少回答：

```text
邀请参加什么
→ 时间 / 地点 / 基本安排
→ 为什么希望对方来 / 下一步
```

### Inform｜通知

重点是信息架构：

```text
发生什么变化
→ 对方需要知道哪些关键事实
→ 对方下一步要不要行动
```

## 5.4 Register Drill｜语域训练

同一个意思练不同对象。

合成内容：

> “请把材料明天下午之前发给我。”

训练 A：写给熟悉同学。  
训练 B：写给不熟悉的项目负责人。  
训练 C：写在面向多人发布的通知里。

目标不是找“最正式词汇”，而是感觉：

> **同一个 communicative intent 怎样随关系改变实现方式。**

## 5.5 Small Writing Cold-Start Exit

在进入第一篇小作文真题前，至少应该能：

1. 30–60 秒内拆出 audience / purpose / required moves；
2. 每个 required move 生成至少一个具体内容点；
3. 不依赖整篇模板完成 3–5 个常见功能动作；
4. 能写一个结构完整的合成小作文；
5. 基本知道哪些语气明显过硬、过随意或空泛；
6. 写完能检查是否漏掉题目要求。

# 6｜Big Writing｜大作文真正要学什么

大作文的核心不是“背三个段落”。

真正能力是：

> **从给定材料中提取准确核心 → 形成一个明确中心信息 → 选择足够内容展开 → 组织成连贯论述 → 用英语实现。**

可以压成：

```text
Observe / Read Prompt
→ Interpret
→ Core Message
→ Content Selection
→ Paragraph Development
→ Language Realization
→ Control
```

## 6.1 第一层：Description ≠ Interpretation

如果题目给出视觉 / 图画 / 材料，第一件事是分开：

```text
我看到了什么
vs
它可能意味着什么
```

很多写作跑题不是英语问题，而是第一步就把解释当事实。

### 合成视觉训练 A

假设画面：

> 两个人站在同一座山脚。一个人看着陡坡说“太难了”，另一个人已经开始往上走。

**Observation** 只能写可见事实：

- two people are at the foot of a steep hill;
- one remains still;
- the other has started climbing。

**Interpretation** 才可以写：

- action matters more than passive fear;
- people respond differently to difficulty。

训练时先强制分两栏，避免一上来套主题。

## 6.2 Core Message｜中心信息

大作文最重要的不是“话题词”，而是：

> **我到底要对这个现象说什么？**

例如主题词是 `persistence`，不够。

更有效的 core message 是：

> Difficult goals become manageable only when people turn intention into sustained action.

它已经包含了一个可论证的关系。

好的 core message 通常满足：

- 回应材料；
- 有明确关系 / 判断；
- 不空泛；
- 后面至少能展开两个支持点。

## 6.3 Content Generation｜怎样避免“第二段没东西写”

给定一个 core message 后，可以从以下方向生成内容：

```text
WHY        为什么成立
HOW        通过什么机制成立
RESULT     会带来什么结果
CONTRAST   相反情况会怎样
EXAMPLE    哪类现实场景体现它
BOUNDARY   在什么条件下成立
ACTION     我们因此应该做什么
```

不需要每篇都用全部。

### 合成训练 B

核心信息：

> Long-term improvement depends more on consistent effort than on occasional bursts of motivation.

只做 content generation，不写作文。

要求生成三个 content atoms：

1. WHY；
2. CONTRAST；
3. RESULT。

例如：

- consistent repetition accumulates small gains;
- motivation fluctuates and cannot guarantee continued action;
- sustained effort gradually turns difficult tasks into routine ones。

这些才是第二段真正可以写的东西。

## 6.4 Paragraph Development｜展开，而不是换句话说

最常见的假展开：

> Persistence is important. It plays an important role in our life. Therefore, we should attach great importance to persistence.

三句话其实只有一个意思。

有效展开要发生**信息增加**。

一个常用但不必机械套用的关系是：

```text
Claim
→ Why / How
→ Consequence / Example / Contrast
→ Link back
```

### 合成训练 C

Claim：

> A clear plan makes difficult tasks easier to sustain.

不要写“计划很重要”的同义句。

往下解释：

> By dividing a distant goal into smaller actions, a plan reduces the need to make the same decision every day.

再给 consequence：

> As a result, progress depends less on momentary motivation and more on a stable routine.

这就叫展开。

## 6.5 第一段：准确描述，不要耗死

大作文第一段的任务通常不是炫语言。

它应该：

1. 准确抓住材料核心；
2. 给后面的 interpretation 留接口；
3. 不为了凑字数描述无关细节。

训练原则：

> **只保留对主题判断有用的视觉 / 材料信息。**

例如一张图里人物穿什么颜色，若不影响主题，就不值得写。

## 6.6 第二段：核心能力段

第二段通常最能暴露真实写作能力。

它需要：

- 一个清楚 core message；
- 至少两个不同的信息推进；
- 不是万能价值判断；
- 不依赖虚构华丽案例才能成立。

前期训练重点应放在这里。

## 6.7 第三段：收束，不是重复

结尾可以：

- 回到核心判断；
- 给行动原则；
- 提出条件 / 期待；
- 把个人层面提升到更一般意义。

但不要：

> 第二段说重要，第三段再说“所以很重要”。

结尾应该完成“那又怎样”的问题。

## 6.8 Big Writing Cold-Start Exit

进入第一篇大作文真题前，至少应该能：

1. 把 observation 与 interpretation 分开；
2. 用一句话写出可展开的 core message；
3. 针对 core message 生成 2–3 个不重复的 content atoms；
4. 把一个 claim 展开成至少 3 句有信息推进的段落；
5. 完成一篇合成完整大作文，不靠整篇模板；
6. 写完能检查自己是否只是重复主题词而没有真正展开。

# 7｜Language Realization｜真正需要建立什么语言能力

Writing 的语言训练不能等同于“积累高级表达”。

真正高价值的是**可调用性**。

## 7.1 从命题开始，不从中文长句开始

写之前先把意思压成简单命题。

例如你想表达：

> 长期坚持之所以有效，是因为它把看起来很大的目标拆成每天可以重复完成的小行动，从而降低了每次重新做决定的成本。

不要一开始就强迫自己翻完整中文长句。

先拆：

```text
consistent effort works
because
large goals become small repeatable actions
therefore
less daily decision cost
```

再生成英文。

这样 Writing 不会退化成逐句中译英。

## 7.2 稳定句型优先于炫技

前期要建立一组真正能自动调用的基础关系：

- A leads to B；
- A makes it easier / harder to do B；
- A matters because...；
- When A happens, B tends to...；
- The problem is not A itself, but...；
- One reason is that...；
- This allows / prevents / encourages...；
- By doing A, people can...。

这里的例子只是**关系实现方式**，不是要求背固定句。

目标是：

> 给你一个关系，你能自己写出一句自然英语。

## 7.3 连接词不是结构本身

`Firstly / Secondly / Moreover / Therefore` 可以用。

但它们不能替代真实逻辑。

先确定：

> 两句话到底是因果、递进、对比、例证还是条件。

再决定要不要显式连接。

## 7.4 复杂句只在有信息需求时使用

不要为了“高级”强行制造从句。

一个复杂句的合理原因可能是：

- 需要说明条件；
- 需要限定一个对象；
- 需要表达让步；
- 需要把两个高度相关命题压在一起；
- 需要避免过度碎片化。

如果两个简单句更清楚，就写简单句。

## 7.5 Personal Reusable Components｜个人可复用组件

长期确实应该形成自己的稳定表达组件，但必须**从真实使用中长出来**。

一个表达进入个人组件库，最好满足：

- 你在真实输出中确实需要它；
- 它跨多个题目可迁移；
- 你已经独立成功用过；
- 它不会强迫所有题目变成同一种内容；
- 你能根据主语、时态、语域和上下文调整它。

这和背“万能句”不同。

万能句是预先塞给你；个人组件是你能力稳定以后压缩出来的。

# 8｜Error Control｜建立一个轻量检查系统

检查不能变成第二次重写。

目标是在有限时间里抓住高收益错误。

## 8.1 写句子时的在线控制

如果一句话写到一半结构失控，不要硬拖。

允许：

- 变短；
- 拆句；
- 换成更稳定的表达；
- 放弃一个自己没把握的复杂结构。

考试目标是可靠得分，不是证明语法胆量。

## 8.2 写完后的短检查

建议按风险而不是按全文逐词扫描：

```text
TASK
有没有漏要求？

STRUCTURE
每段是否完成自己的功能？

HIGH-RISK LANGUAGE
主谓 / 单复数 / 时态 / 句子完整 / 搭配 / 拼写

EXECUTION
称呼、结尾、格式、明显遗漏
```

以后通过真实错误再形成你自己的 personal check list。

不要一开始就背几十条检查规则。

# 9｜Synthetic Drill Bank｜前置片段训练怎么做

这些训练默认由 Chat / 系统即时生成，不需要消耗真题。

每个 drill 只练一个主要动作。

## Drill 1｜Task Parsing Only

给一个合成小作文 prompt。

不写正文，只输出：

```text
Audience:
Purpose:
Required Moves:
Useful Details:
Register:
```

通过标准：没有漏硬性任务，没有把可选内容当必需。

## Drill 2｜Content Atoms Only

给一个主题或 communicative task。

60 秒内生成 3–5 个相关内容点。

禁止写完整句。

通过标准：内容不重复、可直接支撑正文。

## Drill 3｜Function Realization

只练一个功能：请求 / 邀请 / 建议 / 道歉 / 感谢 / 通知等。

同一意图写 2 个版本：

- 对熟悉对象；
- 对较正式对象。

通过标准：意思清楚、语域合适，不追求华丽。

## Drill 4｜Sentence Pair

系统给第一句和关系要求，例如：

> 第一层事实 → 第二句解释原因。

你写第二句。

再练：

- claim → consequence；
- problem → solution；
- description → interpretation；
- recommendation → benefit。

通过标准：第二句真正推进信息。

## Drill 5｜Paragraph Expansion

系统给一个 claim。

要求写 3–4 句，使每句有不同功能。

例如：

```text
Claim
→ Mechanism
→ Consequence
→ Example / Contrast
```

通过标准：不能只是同义改写。

## Drill 6｜Observation vs Interpretation

给一个合成图画文字描述。

先写 2–3 句 observation，再写 1 句 interpretation。

通过标准：事实和推论不混淆。

## Drill 7｜Core Message

给一个合成图画 / 现象。

生成三个候选 thesis，选择最可展开的一个，并说明为什么另外两个太空或太窄。

通过标准：中心信息不是单个主题词，而是可论证的关系或判断。

## Drill 8｜Register Shift

同一内容写三种对象版本。

通过标准：不是简单替换 `can → could`，而是整体语气合理。

## Drill 9｜Compression / Simplification

给一个你写得过长、容易错的句子。

要求在不损失核心意思的情况下改成更稳的表达。

通过标准：信息保留，错误风险下降。

## Drill 10｜Error-Control Sprint

给一段带 4–6 个高价值错误的合成文本。

限定短时间检查。

通过标准：优先抓真实得分风险，而不是纠结风格偏好。

# 10｜Guided Full Output｜第一次完整写作怎么练

完成 G1 后，进入合成完整题。

## 10.1 写前允许做什么

允许 2–4 分钟轻量计划：

```text
Task / Core Message
→ 3–6 content atoms
→ paragraph roles
```

不要先写完整中文稿。

## 10.2 First Draft 必须保留

Writing 的核心证据之一是：

> **第一次独立生成的完整版本。**

它不能被后来的润色版覆盖。

因为 first draft 才能暴露：

- 你最开始是否审对题；
- 内容是自然生成还是被 feedback 补出来；
- 结构是否自己能建立；
- 哪些词 / 句式无法主动调用；
- 哪些错误在时间压力下反复出现。

## 10.3 复盘不要从“逐句润色”开始

先按上游到下游判断：

```text
1. TASK 对了吗？
2. CONTENT 足够且相关吗？
3. STRUCTURE 清楚吗？
4. LANGUAGE 有没有真正阻碍表达？
5. ERROR CONTROL / EXECUTION 有什么高价值问题？
```

只找最重要的第一失败层。

例如：

> 第二段没东西写。

此时不要先改 `important` 为 `significant`。

真正 repair 可能是：

> 学会从一个 core message 生成 WHY / HOW / RESULT。

## 10.4 Rewrite｜重写什么

不默认整篇重写。

修复范围跟失败范围一致：

- Task 错 → 重新做 task plan，必要时整篇重构；
- Content 弱 → 重做 content atoms + 受影响段落；
- Structure 弱 → 重排 paragraph role + 重写相关段；
- Language 局部失败 → 重写句子 / 句对；
- Register 问题 → 重写相关 communicative move；
- Execution 小错 → 修正并形成短 check rule。

解释看懂不算修复。

必须由学习者重新生成。

# 11｜什么时候开始用真题

真题不是禁区，而是**高价值测量资产**。

我们必须最终大量进入真题，但不应该在还不会基本动作时把 clean exposure 消耗掉。

## 11.1 真题进入门槛

### Small Writing

- 能独立拆 audience / purpose / moves；
- 能生成具体 details；
- 常见 communicative functions 能基本实现；
- 完成过至少一篇合成完整小作文；
- 不依赖整篇模板才能开始写。

### Big Writing

- 能分 observation / interpretation；
- 能形成 core message；
- 能生成至少两个真正推进内容的支持点；
- 能展开一个完整核心段；
- 完成过至少一篇合成完整大作文。

达到这些就应该进入真题。

不要因为“还不完美”继续拖延。

## 11.2 第一篇真题的意义

第一篇真题不是考试。

它是：

> **第一次真实基线测量。**

我们要看：

- Guide 学会的动作能不能迁移；
- 真题题面有没有新的 task constraint；
- 真实内容生成是否仍然卡住；
- 时间分配怎样；
- first draft 和合成题相比哪里开始变形。

## 11.3 真题保护规则

未见真题默认：

- 不提前看范文；
- 不提前看主题词总结；
- 不提前看老师模板；
- 不用它做基础句型示范；
- 不因为需要一个片段 drill 就随手消耗。

基础教学优先：

> synthetic / already-exposed material。

真题优先：

> clean attempt / exam fit / later transfer evidence。

# 12｜Writing 的 First Failure Diagnosis

正式复盘时，内部可以很细，但用户不需要填复杂 taxonomy。

建议按顺序问：

## Layer 1｜TASK

- 是否漏任务；
- 是否误判写作目的；
- 是否对象 / 身份错；
- 是否语域方向错；
- 是否图画 / 材料核心读偏。

若这里失败，先修这里。

## Layer 2｜CONTENT

- 是否根本没东西；
- 是否内容与题目弱相关；
- 是否重复一个意思；
- 是否缺必要 detail；
- 是否 core message 太空，无法展开。

## Layer 3｜STRUCTURE

- 段落任务是否清楚；
- 顺序是否合理；
- 是否一个点还没讲完就跳到另一个；
- 是否 observation / interpretation / argument 混在一起；
- 是否句间没有信息关系。

## Layer 4｜LANGUAGE REALIZATION

- 想法清楚但不会用英语表达；
- lexical retrieval 失败；
- construction / collocation 不稳定；
- 句子过载；
- 关系表达错误；
- register 实现不当。

Lexical owner 能解决的，回 LexicalOS。

## Layer 5｜ERROR CONTROL

- 知道正确形式但输出时反复漏；
- 高风险语法错误；
- 拼写 / 单复数 / 主谓等重复失分；
- 修改引入新错误。

## Layer 6｜TIMED EXECUTION

- 规划过久；
- 第二段卡死；
- 后程语言质量塌陷；
- 没时间检查；
- 字数 / 完整性失控。

一次作文可以有很多表面问题，但 repair 默认从**最早一个足以解释主要结果的失败层**开始。

# 13｜什么才算“学会”

Writing 最容易制造假进步。

比如：

> 看了范文 → 改了一遍 → 第二版很好看。

这只能说明你在有帮助时能修好。

证据强度大致是：

```text
看懂 model / feedback
<
同一段在提示后改好
<
同一 prompt 隔一段时间能独立重写
<
新 prompt 中独立调用同一能力
<
多次 unseen task 中稳定自动出现
```

例如今天学会了：

> recommendation 后面必须有“为什么适合对方”的真实内容。

真正强的证据不是把今天这封推荐信改好。

而是下次完全不同的推荐 / 建议任务里，你自然生成了：

```text
what
+
why it fits
+
useful detail
```

这才说明能力迁移了。

# 14｜哪些东西值得进入长期记忆 / 复习

Writing 特别容易产生“收藏癖”。

必须控制。

## 14.1 可以进入长期资产

### Reusable communicative functions

例如你真实输出中反复需要：

- polite request；
- recommendation with fit reason；
- concise apology + remedy；
- expectation / follow-up；
- formal notification。

### Reusable argument relations

例如反复需要：

- claim → mechanism；
- cause → consequence；
- contrast；
- condition；
- concession；
- observation → interpretation。

### Repeated production lexical failure

真正需要但多次无法调用的词 / construction，回 LexicalOS。

### Stable personal methods

例如经过多次写作证明：

> 第二段先写一句可论证的 core message，再生成 WHY/HOW/RESULT，比直接开始写更稳定。

这类可以逐渐形成少量个人方法。

### Recurring execution failure

例如：

- 每次最后都没有时间检查；
- 总在结尾漏 required move；
- 一紧张就开始堆超长句。

## 14.2 不应该自动进入长期复习

- 范文里看起来很漂亮的一句话；
- 一次偶发措辞不够高级；
- model essay 的整段；
- 老师列出的所有万能替换；
- 只适合某一道题的内容；
- 已经在新题里稳定迁移的小问题。

未来真正要留下的不是：

> “这篇作文标准答案怎么写”。

而是：

> **下次遇到同样的生成需求，我应该能自己做什么。**

# 15｜范文和模板到底怎么用

## 15.1 范文的正确用途

范文可以用来：

- 看一种任务如何完成；
- 看一个段落怎样推进；
- 找自然的 communicative realization；
- 比较你的 first draft 哪里缺信息；
- 抽取少量真正可迁移的语言组件。

范文不应该：

- 在 clean attempt 前出现；
- 变成逐句背诵对象；
- 因为比你的作文漂亮，就默认所有差异都要修；
- 取代你自己的内容生成。

## 15.2 模板的正确地位

模板不是敌人。

稳定 skeleton 可以显著降低考试认知负荷。

但我们只保留**非常薄的骨架**。

例如：

```text
Small Writing
purpose → required moves → close

Big Writing
material → core meaning → development → close
```

真正长期可复用的内容应该是：

- functions；
- relations；
- personal stable expressions；
- paragraph moves。

而不是一整篇 180 词固定文本。

## 15.3 Personal Template 应该最后长出来

如果以后你做了多篇题，发现有些结构确实反复成功，可以压缩成 personal template。

顺序必须是：

```text
真实输出
→ 多次成功
→ 发现稳定共性
→ 压缩
```

而不是：

```text
先背模板
→ 强行把所有题塞进去
```

# 16｜第一次完整学习的建议路线

这是从零开始时推荐的顺序，不是长期日程。

## Session 1｜建立母模型

学习：

- Task / Content / Structure / Language / Control / Time；
- 小作文和大作文到底分别在解决什么问题；
- 为什么 first draft 必须保存；
- 为什么真题先保护。

练习：

- 2 个 Task Parsing；
- 2 个 Content Atom；
- 1 个 observation vs interpretation。

## Session 2｜小作文功能动作

学习并练：

- purpose；
- request；
- suggest / recommend；
- invite；
- inform；
- thank / apologize；
- register shift。

不写整篇真题。

## Session 3｜大作文内容和展开

练：

- observation；
- interpretation；
- core message；
- WHY / HOW / RESULT / CONTRAST；
- paragraph expansion。

## Session 4｜语言实现与错误控制

练：

- 把 content atoms 直接变成英文命题；
- sentence pair；
- 复杂句降级；
- register；
- high-risk check。

## Session 5｜第一篇合成小作文

完整写。

保留 first draft。

按 first failure layer 复盘。

只修最关键问题，然后重新生成受影响部分。

## Session 6｜第一篇合成大作文

完整写。

同样保留 first draft。

重点看第二段是否真的有 content development。

## Then｜进入第一批真题

如果两篇合成完整作文已经能够独立完成：

> **停止继续堆启蒙训练，进入 clean true-exam attempt。**

Cold Start 必须短而有效，不能变成新的“先学完课程再做题”。

---

# 17｜未来正式 Writing Attempt 的学习单位

冻结：

> **一篇完整作文 = 一个 learner-facing Writing unit。**

正式训练中：

```text
Prompt
→ Clean Planning
→ First Draft
→ Submit
→ Whole-Essay Review
→ locate first meaningful failure
→ smallest repair
→ learner re-generation
→ later unseen Writing transfer
```

内部 evidence 可以细到：

- task requirement；
- content atom；
- paragraph；
- sentence；
- lexical / construction span；
- revision event；
- timing event。

但 learner–Chat 正常复盘从**整篇作文**开始。

Chat 先判断：

- 多个表面错误是否来自同一上游失败；
- 哪些只是下游连锁反应；
- 哪一个 failure 最值得先修。

不要把一篇作文拆成十几个独立“错题”。

---

# 18｜Writing Cold-Start 的最终出口

在正式进入真题前，不要求你：

- 背完所有作文类型；
- 掌握几十种高级句式；
- 建好万能模板库；
- 看完多本写作书；
- 写出高分范文级语言。

只要求真正具备下面这些基本动作。

### Small Writing

```text
看任务
→ 识别对象 / 目的 / required moves
→ 生成具体信息
→ 用合适语域完成 moves
→ 清楚收束
```

### Big Writing

```text
看材料
→ 分事实与解释
→ 得到 core message
→ 生成可展开内容
→ 组织段落
→ 用稳定英语实现
```

### Shared

```text
写完
→ 能发现主要问题在哪一层
→ 不依赖范文完成第一次修复
→ 保存 first draft
```

达到这里，Writing Guide 就应该退到后台。

接下来真正建立能力的主线变成：

> **完整写作 → 高价值复盘 → 最小修复 → 重新生成 → 新题迁移。**

最终目标不是“记住 Writing Guide”。

而是：

> **面对一个没见过的题，不需要先寻找模板，也知道自己要写什么、怎么组织、怎么用自己能控制的英语完成它。**
