# Writing｜能力地图与高密度学习资产

> **定位**：Writing 的 Current learner-facing 能力资产。  
> **适用状态**：学习者此前没有系统做过考研英语作文，需要先把“从题目生成一篇合格作文”的能力建立起来，再进入宝贵真题。  
> **第一次学习**：先建立整张 Global Map，再连续学习 Core Learning Blocks；不要把第一次学习切成几十个孤立技巧、模板或句型。  
> **后续训练**：用 Skill Map 给失败建立稳定地址；正式 Writing Attempt 仍以“一篇完整作文”为 learner-facing 学习单位，内部 diagnosis 才细到 task / content / paragraph / sentence / lexical span。  
> **Chat 展开原则**：静态资产负责把高频、稳定、真正影响写作能力的主干讲清楚；具体题目的内容选择、真实语域边界、多个问题同时出现、个性化表达与 micro-drill，再交给 Chat 按真实 evidence 展开。`可以问 Chat` 不是把正文做薄的理由。  
> **真题保护**：Framework Learn、片段训练、第一次合成完整写作默认使用 synthetic material；fresh true exam 优先保留给 clean first attempt、exam-fit calibration 和 later transfer。  
> **原则**：能力形成先于材料目录；内容、结构与语言生成先于模板记忆；真正学会以独立生成和后续 fresh transfer 为证据。

---

# A｜Global Map：写作到底是在做什么

考研作文最容易被误解成：

> 背模板 → 换主题词 → 填几个高级表达 → 凑够字数。

这种方式可以制造一篇“像作文”的文本，却不能保证你面对陌生题时仍然知道自己在做什么。

Writing 真正完成的是一次从**任务约束到英文成品**的主动生成：

```text
TASK
看懂必须完成什么
↓
GENERATE
产生足够、相关、可展开的内容
↓
ORGANIZE
把内容排成清楚的信息结构
↓
REALIZE
用自己能控制的英语实现
↓
CONTROL
压住高价值错误与语域风险
↓
DELIVER
在考试时间里完成
```

可以压成六个能力层：

```text
1. Task Model｜题目真正要求什么
2. Content Generation｜我到底要说什么
3. Structure & Development｜这些内容怎样组织并推进
4. Language Realization｜把意思稳定生成成英语
5. Error / Register Control｜避免可预防的高价值失分
6. Exam Execution｜在时间压力下交付完整文本
```

这六层主要用于**学习与故障定位**，不是让你考试时逐项默念。

熟练以后，正常状态应该越来越接近：

> 看完题 → 很快知道要完成什么 → 有内容 → 有顺序 → 直接写。

框架只在第一次学习、卡住、复盘和重复失败时重新展开。

---

## A1｜为什么 Writing 不是“语法 + 高级词汇”

一篇语言很漂亮的作文，如果：

- 漏掉任务要求；
- 内容空泛；
- 第二段一直换句话重复；
- 语域与对象不匹配；

仍然不是稳定写作。

反过来，一篇：

- 任务完成；
- 内容清楚；
- 段落有功能；
- 语言普通但准确稳定；

已经有了可以继续提分的骨架。

所以 Writing 的训练顺序不能倒过来。

高频错误顺序通常应该问：

```text
我写偏了吗？
↓
我有东西可写吗？
↓
这些东西真的在推进吗？
↓
我能把它们稳定写成英语吗？
↓
还有哪些可预防错误？
```

而不是一上来问：

> `important` 能不能换成 `significant`？

---

## A2｜Writing 和其他英语能力是什么关系

### Lexical

Writing 会调用：

- sense；
- phrase；
- collocation；
- construction；
- register；
- contrast / confusable。

如果你**已经知道想表达什么**，但某个词、搭配或 construction 调不出来，长期知识应回到 LexicalOS。

Writing 可以保留行为 evidence：

> 我在真实输出里需要它，但没能主动调用。

这种 production evidence 比“词表里见过”更强。

### Reading

Reading 给 Writing 提供大量自然语言与篇章输入，但：

> 读得懂 ≠ 写得出。

Reading 更偏 representation / recognition；Writing 必须 active generation。

### Translation

Translation 是：

```text
已有英文
→ 恢复意义
→ 生成中文
```

Writing 是：

```text
任务约束
→ 自己生成意义
→ 自己生成英文
```

Writing 不是 Translation 的逆过程。

初学时可以用中文帮助澄清“我要说什么”，但不建议先在脑中写完整中文稿，再逐句中译英。长期这样做容易造成：

- 中文句式过重；
- 英文句子过长；
- 搭配不自然；
- 每句话生成成本过高。

更合理的是逐渐把计划压成：

```text
关键词
+
content atoms
+
简短 propositions
```

然后直接生成英文。

# B｜Core Learning Blocks

第一次正式进入 Writing，主要学习发生在这里。

不是先背“邀请信模板、建议信模板、坚持主题模板、科技主题模板”，而是先连续建立一套真正能迁移的生成能力。

推荐第一次连续学习：

```text
B1 Task Model
→ B2 Content Generation
→ B3 Structure & Development
→ B4 Language Realization
→ B5 Small Writing
→ B6 Big Writing
→ B7 Error Control & Exam Execution
→ B8 Integrated Walkthrough
```

其中 B1–B4 是 Writing 公共主干；B5 / B6 是两种主要考试输出模式；B7 把能力压进考试条件；B8 用 synthetic 完整任务把前面重新合起来。

---

# B1｜Task Model：先知道自己到底要完成什么

## B1.0 核心模型

Writing 第一个问题永远不是：

> 我用什么句型开头？

而是：

> **这道题要求我作为谁，对谁，完成什么 communicative / interpretive job？**

Task Model 至少要恢复：

```text
ROLE / IDENTITY
我以什么身份写

AUDIENCE
谁会读

PURPOSE
整篇文字要完成什么

REQUIRED MOVES
题面硬性要求哪些动作 / 信息

CONSTRAINTS
字数、形式、材料、语域、情境等限制

SUCCESS CONDITION
什么算真正把任务做完
```

如果 Task 错了，后面 Content / Structure / Language 再好，也是在高质量完成错误任务。

---

## B1.1 Prompt → Task Brief｜先把题面压成可执行任务

面对题目时，不要直接开始写正文。

先把 prompt 压成一个短 Task Brief。

### Synthetic Small Writing Prompt

> You are helping organize a weekend campus activity for visiting students. Write to a student who has just arrived. Recommend one activity, explain why it may suit the student, and tell the student how to join.

不要先想开头模板。

先压成：

```text
Role: campus helper / organizer
Audience: newly arrived visiting student
Purpose: recommend one activity and help them join
Required moves:
1. activity
2. why it fits
3. how to join
Register: friendly, helpful, not over-formal
```

这就是 Task Brief。

真正有价值的是：

> 你知道哪些内容是硬要求，哪些只是可选补充。

---

## B1.2 Required Moves｜“题目要求”要翻译成动作

很多小作文并不是因为英语差而失分，而是题面已经写了三个动作，最后只完成两个。

把要求转换成动词最有效：

```text
recommend
explain
inform
request
invite
apologize
thank
suggest
ask
clarify
report
```

每个 Required Move 都应该在成文里有可识别的完成证据。

例如题目要求：

> recommend an activity + explain why + tell how to join

如果正文只有：

> I strongly recommend the activity. It is very meaningful and I hope you will like it.

语言看起来像作文，但实际上：

- 活动是什么？不清楚；
- 为什么适合对方？空泛；
- 怎么参加？没写。

所以 Task completeness 高于语言装饰。

---

## B1.3 Audience & Register｜写给谁会改变整套实现方式

同一个内容，对不同对象不能只替换一个 `can → could`。

要考虑：

- 能否直接命令；
- 是否需要 soften request；
- 是否适合 contraction；
- 是否需要解释更多背景；
- 称呼与收束要多正式；
- 是否适合明显情绪化表达。

例如同一个意图：

> “请明天下午之前把材料发给我。”

对熟悉同学，你可能更直接：

> Could you send me the file by tomorrow afternoon?

对不熟悉的负责人，通常会多一点 context / politeness：

> Could you please send me the file by tomorrow afternoon if possible? I need it to prepare the final schedule.

不是第二句“词更高级”，而是 audience relationship 改变了 communicative realization。

---

## B1.4 Big Writing 的 Task 不是“猜主题词”

大作文常见失败是：

> 看见一个视觉元素 → 立刻套进自己熟悉的价值主题。

Task Model 要先分开：

```text
OBSERVATION
材料明确给了什么

INTERPRETATION
这些事实可能表达什么关系 / tension / message

WRITING JOB
题目究竟要求描述、解释、评论、展开到什么程度
```

如果 Observation 和 Interpretation 一开始混在一起，你可能从第一段就跑偏。

### Synthetic Visual Scenario

画面：

> 两个人站在同一座陡坡前。一个人停在原地说“太难了”，另一个人已经开始往上走。

Observation 只能是：

- two people are at the foot of a steep hill;
- one remains still;
- the other has started climbing.

Interpretation 才可能是：

- people respond differently to difficulty;
- action can matter more than passive fear;
- willingness to start changes how difficult goals are approached.

不能把 interpretation 冒充成画面事实。

---

## B1.5 Task failure 的压缩排查动作

卡住时先退回：

```text
我是谁？
→ 写给谁 / 对什么材料？
→ 我要完成什么？
→ 哪几件事必须出现？
→ 语气和形式有什么限制？
```

### Active Check

Synthetic prompt：

> Write to a professor who agreed to meet you next week. Explain why you need to change the meeting time, suggest another time, and apologize for the inconvenience.

先不写正文，只回答：

```text
Audience:
Purpose:
Required Moves:
Register:
One detail that must be concrete:
```

如果你能稳定拆出来，才值得进入 Content。

### 什么时候值得找 Chat 展开

- 两个 task requirement 的边界不清；
- 不确定某个对象该多正式；
- 大作文材料存在两种合理 interpretation；
- 题目 wording 让你不确定到底要描述还是评价；
- 你能看懂 prompt，但不知道什么算“完成”。

这时 Chat 应该先帮你还原 Task Model，而不是直接给成文。

# B2｜Content Generation：从空白变成“有东西可写”

## B2.0 核心模型

很多人把“写不出来”全部归因为：

> 词汇不够。

但真实卡点经常是：

> **脑子里根本还没有形成明确内容。**

必须先分清：

```text
没有明确内容
≠
有明确内容但英语调不出来
```

前者属于 Content Generation；后者才更接近 Language Realization / Lexical retrieval。

Content 的最小单位是：

> **Content Atom：一个可以独立回答“我到底要说什么”的最小信息。**

它可以先用中文、关键词或极简英文表示。

---

## B2.1 Content Atom｜先生成意思，不要用万能句伪装内容

例如小作文要推荐一个校园活动。

真实 content atoms 可能是：

```text
activity = weekly language exchange
small groups
good for meeting local students
beginners are welcome
registration through student center website
```

而下面这些不是有效 content atom：

```text
it is very meaningful
it is very important
I strongly recommend it
I believe you will benefit a lot
```

这些只是态度壳，没有提供新信息。

一个简单判断：

> **删掉句型以后，还剩下具体意思吗？**

如果没有，就还没真正生成内容。

---

## B2.2 Relevance｜先回答题，而不是写最熟的内容

生成内容后先做 relevance gate：

> 这个点真的帮助完成当前 task / core message 吗？

不要因为某个观点很好写就强行塞进去。

例如任务是：

> 推荐一个适合刚到校交换生的活动。

“这个活动历史悠久、学校领导高度重视”可能很好写，但对“为什么适合这个学生”帮助不大。

更相关的是：

- 能认识本地学生；
- 不要求已有经验；
- 时间安排友好；
- 能快速熟悉校园。

写作中的“可写性”不能凌驾于 relevance。

---

## B2.3 Sufficiency & Specificity｜内容要够，也要落地

小作文尤其需要：

```text
Required Move
+
至少一个具体 detail
```

比如 Request：

> Could you help me with the event?

太宽。

具体一点：

> Could you help me check the final list of participants before Friday afternoon?

读者马上知道要做什么。

大作文里 Specificity 不是必须编故事，而是让抽象 claim 有机制或结果。

例如：

> Planning is important.

信息太弱。

比它更可展开的是：

> A clear plan reduces the number of decisions people need to make repeatedly while pursuing a difficult goal.

这就出现了 mechanism。

---

## B2.4 Generation Operators｜一个观点怎样继续长出内容

当你有一个 Core Message 或 claim 后，可以用少数几个稳定问题继续生成：

```text
WHY       为什么成立？
HOW       通过什么机制发生？
RESULT    导致什么结果？
CONTRAST  相反情况会怎样？
EXAMPLE   哪类场景能体现？
BOUNDARY  在什么条件下成立 / 不成立？
ACTION    因此应该怎么做？
DETAIL    读者还需要什么具体信息？
```

不是每篇全用。

真正目标是：

> 一个中心意思至少能自然长出 2–3 个不重复的信息推进。

### Synthetic Example

Core message：

> Long-term improvement depends more on consistent effort than on occasional bursts of motivation.

可以生成：

```text
WHY:
motivation naturally fluctuates

HOW:
repeated small actions accumulate progress

RESULT:
difficult actions gradually become routine

CONTRAST:
short bursts may create quick starts but not stable continuation
```

这些才是正文第二段真正可写的东西。

---

## B2.5 Selection｜不是想到的都要写

考试写作容量有限。

Content Generation 后还要做选择：

优先保留：

```text
最相关
+
最能推进
+
自己最能稳定表达
+
彼此不重复
```

不要为了显得“内容丰富”塞四个浅观点。

通常两个真正展开的点，比四个口号式观点更有价值。

---

## B2.6 Small Writing 的内容生成

小作文内容不是“论点”，而是**完成功能所需的信息**。

例如推荐任务：

```text
WHAT
推荐什么

FIT
为什么适合这个具体对象 / 情境

DETAIL
时间、地点、形式、条件等必要细节

NEXT STEP
对方怎么行动
```

请求任务可能是：

```text
WHAT I NEED
+
WHY / CONTEXT
+
WHEN / HOW
+
POLITE NEXT STEP
```

道歉可能是：

```text
具体问题
→ 简洁承认 / 解释
→ remedy / next step
```

这些是可迁移的 content logic，不是整篇模板。

---

## B2.7 Big Writing 的内容生成

大作文先形成一个可论证的 **Core Message**，再展开。

主题词不等于 Core Message。

例如：

```text
persistence
```

只是 topic。

更可写的是：

> Difficult goals become manageable when people convert intention into sustained action.

它有：

- 对象：difficult goals；
- 关系：become manageable when...；
- 机制方向：intention → sustained action。

后面自然能生成 WHY / HOW / RESULT。

---

## B2.8 Content Generation 的压缩执行动作

卡住时问：

```text
我真正要回答什么？
→ 先列 3–5 个 content atoms
→ 删掉空话和弱相关
→ 用 WHY / HOW / RESULT / DETAIL 让最重要的点长一层
→ 只留下我能稳定表达的高价值内容
```

### Active Check

主题：

> Universities should help students develop practical skills outside the classroom.

只做 Content，不写正文。

生成三个不同功能的 atom：

```text
WHY:
HOW:
RESULT:
```

要求每个 atom 都比“practical skills are important”多一个真实信息。

### 什么时候值得找 Chat 展开

- 你能理解题，但 60–90 秒后仍只有主题词；
- 想出来的内容明显重复；
- 不知道一个 point 是否偏题；
- 内容很多但不知道选哪些；
- 大作文第二段只能写价值口号；
- 小作文知道 function，却想不到具体 detail。

Chat 此时应该帮助生成 / 筛选 content，不要先替你润色英文。

# B3｜Structure & Development：内容怎样真正变成文章

## B3.0 核心模型

Structure 不是：

> 一定三段；每段固定几句。

真正的问题是：

> **每个信息为什么出现在这里，它怎样帮助读者继续理解？**

结构可以拆成三层：

```text
PARAGRAPH ROLE
这一段完成什么任务

INFORMATION ORDER
几个 content atoms 按什么顺序出现

DEVELOPMENT
后一句怎样真正推进前一句
```

---

## B3.1 Paragraph Role｜每段必须知道自己为什么存在

一个段落至少应有一个清楚 role。

Small Writing 常见的薄骨架：

```text
OPEN
建立情境 / 说明目的

BODY
完成 required moves + useful details

CLOSE
下一步 / 期待 / 礼貌收束
```

Big Writing 常见功能关系：

```text
MATERIAL
准确呈现材料核心

MEANING + DEVELOPMENT
形成中心判断并真正展开

CLOSE
回答“那又怎样”
```

段数是表面形式；role 才是底层对象。

判断一个段落是否必要，可以问：

> **删掉它以后，任务会缺哪个功能？**

答不出来，说明这个段落可能只是形式占位。

---

## B3.2 Information Order｜顺序应该服务理解成本

有几个内容点时，优先选择自然依赖关系：

```text
背景 → 请求
问题 → 原因 → 补救
推荐 → fit reason → joining detail
事实 → interpretation
claim → mechanism → result
现象 → 原因 → consequence
```

不要为了背结构，把本来有关联的内容拆散。

也不要把读者最需要的关键信息拖到最后。

小作文尤其应该考虑：

> 对方读到这里时，下一件最需要知道什么？

大作文则更关注：

> 后一句是否在回答前一句自然产生的问题？

---

## B3.3 Local Coherence｜连接词不是结构本身

`Firstly / Secondly / Moreover / Therefore / However` 都可以用。

但它们不能凭空制造逻辑。

真正的 local coherence 是：

```text
Sentence A
→ 读者自然产生一个问题 / 预期
→ Sentence B 回答或推进它
```

例如：

> A clear plan makes difficult tasks easier to sustain.

下一句自然可以回答：

> Why?

于是：

> By dividing a distant goal into smaller actions, a plan reduces the need to make the same decision every day.

第三句自然可以问：

> So what?

于是：

> As a result, progress depends less on momentary motivation and more on a stable routine.

这才是真正的 coherence。

---

## B3.4 Paragraph Development｜展开 = 信息增加

最常见的假展开：

> Persistence is important. It plays an important role in our life. Therefore, we should attach great importance to persistence.

三句话只有一个信息：

> persistence is important。

真正的展开必须发生 **information gain**。

可以用：

```text
Claim
→ Why / Mechanism
→ Consequence
→ Example / Contrast / Boundary
→ Link back
```

不要求机械五步。

最小标准是：

> 后一句增加了一个新信息维度，而不是给前一句换词。

---

## B3.5 Development Diagnostics｜怎么判断自己在“绕圈”

写完一个段落后，可以快速检查每句话的功能：

```text
S1 = claim
S2 = ?
S3 = ?
S4 = ?
```

如果出现：

```text
claim
→ same claim
→ stronger wording of same claim
→ moral slogan
```

这不是发展。

如果出现：

```text
claim
→ mechanism
→ result
→ implication
```

信息真正向前了。

---

## B3.6 Opening｜开头只需要完成入口任务

小作文开头通常只需：

- 建立必要情境；
- 说明写作目的。

大作文开头通常只需：

- 准确呈现与主题判断有关的材料；
- 给 interpretation 留接口。

不要为了“高级开头”花过多认知资源。

尤其避免长篇：

> With the rapid development of society...

如果它和当前 task 没有真实关系，就只是噪音。

---

## B3.7 Closing｜结尾要完成“下一步 / 那又怎样”

Small Writing 结尾可以完成：

- next step；
- expectation；
- thanks；
- polite close。

Big Writing 结尾可以完成：

- 回到核心判断；
- 提出行动原则；
- 指出条件或意义；
- 从具体材料收束到更一般的判断。

不要：

> 第二段说 important，第三段再说 therefore important。

结尾应该有功能，而不是字数保险。

---

## B3.8 Structure 的压缩执行动作

```text
先给每段一个 role
→ 把 content atoms 放进最自然的位置
→ 每个段落找一个核心推进
→ 检查相邻句之间真实 relation
→ 删掉只换词不加信息的句子
```

### Active Check

给定 claim：

> Regular feedback helps learners improve more efficiently.

下面两个第二句哪个是真正 development？

A.
> Regular feedback is very important for improvement.

B.
> It allows learners to identify ineffective habits before those habits become difficult to change.

关键不是 B 更“高级”，而是 B 增加了 mechanism。

### 什么时候值得找 Chat 展开

- 你有内容点，但不知道排序；
- 第二段写了很多却感觉都一样；
- 不知道某一句该不该单独成段；
- 两句话都对但衔接很突兀；
- 小作文 required moves 全有，但读起来像清单；
- 大作文 core message 有了，但 paragraph development 仍然薄。

---

# B4｜Language Realization：把已经明确的意思稳定生成成英语

## B4.0 核心模型

Language Realization 的前提是：

> **你已经大致知道自己要说什么。**

真正任务不是寻找“最高级的表达”，而是：

```text
CONTENT / RELATION
→ SIMPLE PROPOSITION
→ STABLE ENGLISH
→ APPROPRIATE REGISTER
```

优先级：

```text
meaning clear
>
grammatically stable
>
natural enough
>
flexible
>
ornamental sophistication
```

考试写作的语言能力首先是**可调用性**。

---

## B4.1 Proposition First｜先生成命题，不先翻完整中文长句

例如你想表达：

> 长期坚持之所以有效，是因为它把看起来很大的目标拆成每天可以重复完成的小行动，从而降低每次重新做决定的成本。

不要直接把整句中文翻成一个巨大英文句。

先压成：

```text
consistent effort works
because
large goals become small repeatable actions
therefore
less daily decision cost
```

然后可以生成：

> Consistent effort works partly because it turns a distant goal into smaller actions that can be repeated every day. This reduces the need to decide again and again whether to continue.

这不是“降低水平”，而是把意义变成自己能控制的英语。

---

## B4.2 Stable Sentence｜稳定句优先于高风险复杂句

复杂句只有在信息需要时才值得使用。

合理原因包括：

- 需要限定对象；
- 表达条件；
- 表达让步；
- 把两个高度相关命题连接；
- 避免全文全是碎句。

不合理原因：

> 想证明自己会高级语法。

如果一句写到一半失控，可以：

```text
拆句
缩短 modifier
换回常见 construction
减少并列层数
保留核心 proposition
```

考试目标是可靠表达，不是语法冒险。

---

## B4.3 Relation Realization｜先知道逻辑，再选表达

常用关系：

```text
CAUSE
A happens because B
B leads to A
One reason is that...

RESULT
A therefore makes B more likely
As a result, ...

CONTRAST
A..., whereas B...
The problem is not A itself, but B...

CONDITION
When / If A happens, B tends to...

CONCESSION
Although A, B...
Even when A, B...

MECHANISM
By doing A, people can B
A allows / prevents / encourages B

EXAMPLE
For example, ...
This can be seen when...
```

这些不是背诵句库，而是关系到英文的几种稳定实现路径。

目标是：

> 给你一个 relation，你能自己生成一句合适英文。

---

## B4.4 Lexical Retrieval｜“认识”不等于写作时能调用

Writing 的 lexical failure 常表现为：

- 知道中文意思，却想不起英语；
- 想起词，但不确定 collocation；
- 熟悉 expression，却不会根据语法环境调整；
- 为追求高级替换，反而选错 sense / register。

原则：

```text
能稳定调用的普通表达
>
记忆模糊的高级替换
```

真正多次需要、却无法主动调用的 lexical object，回 LexicalOS。

Writing 不重复建立词汇知识库。

---

## B4.5 Register Realization｜正式不是“越长越客气”

语域控制包括：

- directness；
- politeness；
- emotional distance；
- contraction；
- vocabulary choice；
- sentence shape；
- opening / closing convention。

例如请求：

> Send me the file tomorrow.

对朋友也许只是略硬；对教授就明显不合适。

但另一极端：

> I would be exceedingly grateful if you could possibly spare your valuable time to kindly...

也未必更好。

目标仍然是：

> **clear + appropriate + economical**。

---

## B4.6 Sentence Load｜一条句子能承载多少信息

句子失控常见原因不是语法知识缺失，而是一次塞太多：

```text
一个主命题
+
两个原因
+
一个让步
+
一个例子
+
一个长定语
```

如果一句话需要你在脑中“保住太多未闭合结构”，就应该降载。

一个简单 stop signal：

> 写到中间已经不确定主语、谓语或从句边界，就不要继续加层。

拆成两句通常比硬撑更可靠。

---

## B4.7 Personal Reusable Components｜组件应该从真实使用中长出来

长期确实应该形成自己的稳定表达组件。

但一个组件最好满足：

- 真实写作中反复需要；
- 跨多个题可迁移；
- 你已经独立成功使用；
- 能根据主语 / 时态 / 对象 / register 调整；
- 不会强迫不同题变成同一种内容。

例如你多次稳定用：

> A matters because it allows people to...

这可以成为个人 component。

但它不是“万能句”，因为真正内容仍然由当前 task 决定。

---

## B4.8 Language Realization 的压缩执行动作

```text
先把意思压成短 proposition
→ 选自己能控制的句子骨架
→ 明确 relation
→ 调 lexical / construction
→ 检查 register
→ 句子失控就降载
```

### Active Check

意思：

> 一个清楚的计划能帮助人们坚持长期目标，因为它让每天要做的事情变得具体。

不要追求一个“高分长句”。

先恢复：

```text
clear plan
→ daily actions become concrete
→ easier to sustain long-term goal
```

只要能自己生成一到两句准确自然的英文，就算完成本动作。

### 什么时候值得找 Chat 展开

- 内容很清楚，但某个 relation 不知道怎么自然表达；
- 一句话有几种写法，不知道哪种更稳定；
- 某个词“好像对”但 collocation / register 没把握；
- 总把简单意思写成长难句；
- 想保留自己的表达，而不是让 Chat 整段重写。

Chat 应该帮你比较局部 realization，而不是用 model essay 覆盖 first draft。

---

# B5｜Small Writing：把 communicative task 做完整

## B5.0 核心模型

Small Writing 的核心不是：

> “有多少种应用文，我分别背哪个模板？”

真正稳定的能力是：

> **在明确对象、目的和情境下，用合适语域完成若干 communicative functions。**

压成：

```text
AUDIENCE
→ PURPOSE
→ REQUIRED MOVES
→ USEFUL DETAILS
→ REGISTER
→ CLEAR CLOSE
```

题型表面可以变，底层 functions 可以复用。

---

## B5.1 Thin Skeleton｜只保留很薄的骨架

```text
OPEN
建立情境 / 说明目的

BODY
完成 2–4 个 required moves + useful details

CLOSE
下一步 / 期待 / 礼貌收束
```

Skeleton 的作用是降低认知负荷，不是预先填满正文。

真正可变的是：

- moves；
- details；
- register；
- information order。

---

## B5.2 Explain Purpose｜第一两句要让读者知道你为什么出现

不要用和 task 无关的空泛开场。

Synthetic situation：

> 原定周六活动地点改变，你要通知一位刚到校的交换生。

高价值 opening 应快速完成：

```text
发生了什么
+
为什么写给你
```

而不是先写：

> I am very delighted to write this letter to you...

如果没有实际信息，这种开场只是消耗字数和时间。

---

## B5.3 Request｜请求不是“礼貌词越多越好”

请求至少需要：

```text
WHAT
你希望对方做什么

CONTEXT
必要时为什么 / 什么时候

REGISTER
直接程度合适

NEXT STEP
如果需要，对方如何回应
```

Synthetic example：

> Could you check the final participant list before Friday afternoon? I need to send the confirmed schedule that evening.

这里礼貌主要来自 sentence choice 和 context，而不是堆叠夸张礼貌公式。

---

## B5.4 Suggest / Recommend｜建议必须有 fit reason

低信息版本：

> I strongly recommend this activity because it is very meaningful.

更完整的功能结构：

```text
WHAT
建议什么
→
FIT
为什么适合当前对象 / 情境
→
DETAIL
必要执行信息
```

Synthetic example：

> I would recommend the weekly language exchange. Since the groups are small and no previous experience is required, it is an easy way to meet local students during your first few weeks on campus.

重点不是背句子，而是：

> recommendation 后面必须有真实 fit information。

---

## B5.5 Invite｜邀请要让对方知道“来什么、什么时候、怎么办”

常见信息结构：

```text
EVENT
→ TIME / PLACE / BASIC ARRANGEMENT
→ WHY YOU WANT THEM THERE / WHY IT MAY SUIT THEM
→ NEXT STEP
```

只写：

> I sincerely invite you to attend our activity.

形式完成了“邀请”，但沟通任务仍然可能不完整。

---

## B5.6 Inform / Notify｜通知首先是信息架构

问：

```text
什么变了？
对方必须知道哪些事实？
对方需要做什么？
```

通知不需要很多情绪语言。

顺序优先考虑接收者的信息需求。

---

## B5.7 Apologize｜道歉后必须处理问题

高价值结构：

```text
承认具体问题
→ 简洁道歉
→ 必要时解释
→ remedy / next step
```

只写三句 `I am terribly sorry` 并不会增加 communicative completeness。

---

## B5.8 Thank｜感谢要具体

更有价值：

```text
感谢什么具体行为
→ 它带来了什么帮助 / 影响
```

而不是不断加强情绪程度。

---

## B5.9 Ask / Inquire｜咨询需要让问题可回答

不要写：

> Could you give me more information?

如果情境允许，更具体：

```text
想知道哪几件事
→ 为什么需要
→ 希望如何回复
```

让对方知道怎样完成回应。

---

## B5.10 Report a Problem / Complain｜重点是可处理，不是发泄

可以组织为：

```text
发生了什么
→ 具体影响
→ 已做过什么 / 当前情况
→ 希望怎样解决
```

register 应克制、具体、可行动。

---

## B5.11 Register Shift｜同一功能随对象变化

同一 intent：

> “能不能把报名截止日期告诉我？”

对同学、活动负责人、正式机构，词和句长可以不同，但真正变化的是：

- directness；
- context；
- politeness；
- opening / closing distance。

第一次学习时应该做几次**同义图不同对象**的 synthetic drill，比背“正式信万能句”更有迁移价值。

---

## B5.12 Small Writing 的自检

写完只扫高价值问题：

```text
TASK
每个 required move 都完成了吗？

DETAIL
是否有足够具体信息？

REGISTER
对象关系合适吗？

NEXT STEP
读者知道接下来要做什么吗？

FORM
称呼 / 结尾 / 必要格式有没有明显问题？
```

### Active Check

Synthetic prompt：

> Write to a new classmate who missed an orientation session. Tell the classmate what was covered, recommend one useful next step, and offer help if needed.

不要写整篇。

只生成：

```text
Purpose:
Move 1 + detail:
Move 2 + fit reason:
Move 3:
Register:
```

如果这些稳定，完整小作文就有了内容骨架。

---

# B6｜Big Writing：从材料到可展开的中心判断

## B6.0 核心模型

Big Writing 的核心不是：

> 背“三段式” + 套一个社会主题。

真正能力是：

```text
OBSERVE / READ
材料明确给了什么
↓
INTERPRET
它在呈现什么关系 / tension / phenomenon
↓
CORE MESSAGE
我真正要说什么
↓
GENERATE
产生可展开内容
↓
DEVELOP
让信息持续推进
↓
REALIZE
用稳定英语完成
```

---

## B6.1 Observation ≠ Interpretation｜先分事实和解释

Synthetic visual：

> 一个人站在一堆学习计划前，不断修改计划；另一个人已经在按一个简单清单执行第一项任务。

Observation：

- one person keeps revising several plans;
- another person has begun working through a short list.

Interpretation：

- excessive planning can become a substitute for action;
- useful planning should reduce friction rather than delay execution.

如果一开始直接写：

> The picture tells us that action is the key to success.

可能没有错，但你已经跳过了“这个材料具体表现了什么关系”的判断。

---

## B6.2 Core Message｜不要只得到一个主题词

`discipline / persistence / technology / cooperation` 都只是 topic label。

可写的 Core Message 通常是一个**关系或判断**：

> A useful plan should make action easier, rather than becoming another task that delays action.

它比“planning is important”更强，因为：

- 回应材料；
- 有 contrast；
- 可继续解释 mechanism；
- 后面能自然谈 consequence / action。

Core Message 的四个 gate：

```text
1. grounded in material
2. specific enough to say something
3. broad enough to develop
4. not dependent on memorized theme slogans
```

---

## B6.3 Interpretation Boundary｜不要无限上纲

一幅图可以支持多个 interpretation，但不是任何主题都可以。

判断一个 interpretation 是否合理：

```text
材料里的关键关系能否直接支撑？
如果删掉我自己的背景知识，材料本身还成立吗？
我是不是只因为某个词很熟就把题硬塞进去？
```

不要为了写熟悉主题，把小材料上升成巨大社会结论。

---

## B6.4 Development｜第二段是核心能力段

第二段最能暴露：

- 有没有真正 core message；
- content generation 是否稳定；
- 是否只会口号；
- relation realization 是否可靠。

一个高价值展开可以是：

```text
Core claim
→ Mechanism
→ Consequence
→ Contrast / Example / Boundary
```

Synthetic example：

> A simple plan can improve persistence by lowering daily decision costs.

Mechanism：

> When the next action is already clear, people spend less effort deciding where to begin.

Consequence：

> This makes progress less dependent on temporary motivation.

Contrast：

> By contrast, a complicated plan that requires constant revision may create the feeling of control without producing actual progress.

这四句每一句都有新信息。

---

## B6.5 Example｜例子不是必须的人名故事

如果需要 example，可以用：

- general scenario；
- common experience；
- category example；
- simple hypothetical situation。

不需要为了“有例子”硬编一个名人故事。

只要例子真正说明 mechanism 即可。

---

## B6.6 First Paragraph｜描述只写对 interpretation 有价值的事实

第一段不是视觉物品清单。

只保留：

> **对后面 core message 有解释价值的 material information。**

人物衣服颜色、画面角落细节、无关数字，如果不改变 interpretation，就不值得占字数。

第一段最终要建立一个接口：

```text
material fact
→ reader can understand why the following interpretation follows
```

---

## B6.7 Closing｜回答“所以呢”

Big Writing 结尾可以：

- 回到 core message；
- 提出行动原则；
- 指出 boundary；
- 提炼材料的实际意义。

但不要只是：

> Therefore, we should attach great importance to this issue.

如果它没有新增任何 practical implication，就只是重复。

---

## B6.8 Big Writing 的压缩执行动作

```text
分 Observation / Interpretation
→ 用一句话形成 Core Message
→ 生成 3–5 个 atoms
→ 选 2–3 个最强推进
→ 给段落 role
→ 先写清楚，再考虑语言升级
```

### Active Check

Synthetic material：

> 两个学生都想提高英语。一个不断换新的学习工具；另一个每天固定做少量阅读、复盘和写作。

不要写作文。

只输出：

```text
Observation:
Interpretation:
Core Message:
HOW atom:
RESULT atom:
CONTRAST atom:
```

如果这些已经清楚，正文才值得开始。

### 什么时候值得找 Chat 展开

- 材料可能有两个合理主题；
- core message 太大或太空；
- 第二段只有“重要、应该、需要”；
- 不知道哪个 support point 更有展开价值；
- 例子和核心判断关系弱；
- 想比较两个段落发展路径，而不是直接要范文。

---

# B7｜Error Control & Exam Execution：稳定交付，而不是无限润色

## B7.0 核心模型

Writing 最终不是：

> 有无限时间时能不能写好。

而是：

> **在真实时间压力下，仍然完成任务、内容够用、结构清楚、语言风险可控。**

执行可以压成：

```text
bounded planning
→ continuous drafting
→ recover when stuck
→ high-value check
→ stop when sufficient
```

---

## B7.1 Planning｜计划必须降低后续成本

计划的目的不是把作文先在草稿里写一遍。

只保留：

```text
Task / Core Message
+
3–6 content atoms
+
paragraph roles
```

如果规划越来越细，却迟迟不开始写，它已经失去作用。

真正的 planning success 是：

> 开始正文后，不再每句话重新决定“下一步写什么”。

---

## B7.2 Online Error Control｜写的时候只控制高风险点

高价值在线控制：

- sentence boundary；
- subject–verb；
- basic tense / time relation；
- singular / plural；
- obvious article / pronoun issue；
- collocation you are unsure about；
- relation word 是否和真实逻辑一致；
- sentence load 是否失控。

不要每写一句就回头改三遍。

持续生成本身是考试能力的一部分。

---

## B7.3 Recovery｜卡住时优先保住任务和内容

当一句表达突然写不出来：

```text
1. 保留核心 proposition
2. 换成更简单的词
3. 拆句
4. 删除低价值 modifier
5. 换一个自己会的 relation realization
6. 继续写
```

不要为了一个“漂亮词”停一分钟。

如果一个 detail 不是 Required Move，也不影响核心论证，必要时可以放弃。

---

## B7.4 High-risk Check｜检查不是第二次写作

写完按风险扫：

```text
TASK
有没有漏 required move / core job？

STRUCTURE
每段 role 是否完成？

LANGUAGE
主谓 / 单复数 / 时态 / 完整句 / obvious collocation / spelling

REGISTER / FORM
对象语气、称呼、收束、格式

EXECUTION
有没有明显未完成或改坏的句子？
```

以后通过真实 learner evidence 再形成个人 check list。

初学不需要背 30 条规则。

---

## B7.5 Stop Rule｜什么时候应该离开这篇作文

满足以下条件，就不应无限润色：

```text
任务完成
核心内容足够
段落角色清楚
没有明显高风险语言错误
语域基本合适
字数 / 完整性满足要求
```

如果只是：

> “这个词还能不能更高级？”

通常已经不是最高价值问题。

考试能力的一部分就是：

> **知道什么时候够好。**

---

## B7.6 Timed failure 什么时候值得进入未来训练

一次偶发时间紧不等于 weakness。

更值得关注的是反复出现：

- planning 过长；
- 第二段持续卡住；
- 后半篇 sentence control 明显下滑；
- 经常漏 required move；
- 总没时间检查；
- 一紧张就堆超长句；
- 为了找高级词停止生成。

这类才可能升级为 execution pattern。

---

# B8｜Integrated Walkthrough：完整写作是怎样长出来的

这里使用 synthetic task，不消耗真题。

目的不是让你背下面的成文，而是让 Global Map 的每一层同时可见。

---

## B8.1 Synthetic Small Writing Walkthrough

### Prompt

> You are a student volunteer. Write to a visiting student who wants to meet local students. Recommend one campus activity, explain why it may be suitable, and tell the student how to join.

### Step 1｜Task Brief

```text
Role: student volunteer
Audience: visiting student
Purpose: recommend a useful activity
Moves:
1. recommend activity
2. explain fit
3. explain how to join
Register: friendly + helpful
```

### Step 2｜Content Atoms

```text
activity = weekly language exchange
small mixed groups
easy to meet local students
no prior registration experience needed
sign up through student center website by Thursday
```

### Step 3｜Structure

```text
OPEN: answer the request + state recommendation
BODY: fit reason + concrete detail + joining method
CLOSE: offer help / expectation
```

### Step 4｜Language Realization

一种可能成文：

> Hi Alex,  
> If you would like to meet more local students, I would recommend the weekly language exchange organized by the student center. The groups are small, so it is easier to have real conversations rather than simply attend a large event. New students are welcome, and you do not need any previous experience. You can sign up on the student center website before Thursday. If you have trouble finding the registration page, feel free to send me a message and I can show you where it is.  
> Best,  
> Kian

### Step 5｜为什么这篇能工作

不是因为它有“高级句型”，而是因为：

- task 三个 moves 全完成；
- fit reason 是具体的；
- register 与对象匹配；
- 每句话承担功能；
- 没有为了模板加入无关内容。

### Active Rewrite

把 audience 改成：

> 一位不熟悉的国际项目协调员。

活动内容不变。

思考：哪些 sentence / opening / closing 需要改变？

这才是 register transfer。

---

## B8.2 Synthetic Big Writing Walkthrough

### Visual Scenario

> 两个人都面对一个长期目标。一个人不断设计越来越复杂的计划，但没有开始行动；另一个人只写下三项简单步骤并开始执行第一项。

### Step 1｜Observation

```text
Person A keeps revising a complicated plan.
Person B has a short list and has already started the first action.
```

### Step 2｜Interpretation

```text
planning can help action
but excessive planning can become a substitute for action
```

### Step 3｜Core Message

> A useful plan should reduce the difficulty of taking action rather than become another task that delays action.

### Step 4｜Content Atoms

```text
HOW:
a simple plan clarifies the next action

RESULT:
less daily decision cost → easier continuation

CONTRAST:
constant redesign creates control feeling without progress

ACTION:
keep planning simple enough to support execution
```

### Step 5｜Paragraph Roles

```text
P1: material + contrast
P2: core message + mechanism + consequence + contrast
P3: practical implication / close
```

### Step 6｜One Possible Realization

> The picture shows two people facing the same long-term goal in very different ways. One keeps revising an increasingly complicated plan, while the other has written down only a few concrete steps and has already begun the first one.  
>  
> The contrast suggests that planning is valuable only when it makes action easier. A simple plan can clarify what should be done next and reduce the need to make the same decision every day. This makes progress less dependent on temporary motivation. By contrast, constant redesign may create a strong feeling of control while producing little real movement toward the goal.  
>  
> For this reason, a useful plan does not need to be perfect. It only needs to be clear enough to guide the next meaningful action and flexible enough to be adjusted after real progress provides new information.

### Step 7｜为什么这篇能工作

- Observation 与 Interpretation 分开；
- Core Message 是一个具体关系，不是 topic word；
- 第二段每句产生 information gain；
- language 主要服务 mechanism；
- 第三段回答“那又怎样”，没有机械重复“planning is important”。

### Active Compression

如果考试中第二段最后一句写不出来，不需要硬造复杂句。

你只要能保住：

> too much planning can feel productive without producing progress

然后用自己稳定的英文实现即可。

# D｜Starter Skill Content：关键节点怎样继续向下学习

Skill Content 不要求所有节点长成同一种卡片。

但一个真正值得占用学习时间的 Writing Skill Content，至少要做到：

```text
建立可执行 mental model
+
解释它怎样改变真实输出
+
给出典型 failure / boundary
+
有代表性 synthetic example
+
有一次主动生成或判断
+
能立即返回完整 Writing task
```

如果一个节点只有定义和术语，它只是索引，不算 Learning Asset。

下面先冻结一批高价值 starter leaves。

---

## D1｜T4 Required Moves｜别让语言好看掩盖任务没做完

### Mental Model

Required Move 是：

> **题目明确要求你完成的 communicative action。**

它不是“建议写什么”，而是 task completion 的组成部分。

### Failure Pattern

最常见：

```text
题面要求 A + B + C
正文写得很顺
但只真正完成 A + B
```

因为 B / C 常被空泛句替代。

### Executable Action

写前：

```text
把 prompt 中的要求改写成 2–4 个动词短语
```

写后：

```text
每个 move 在正文里找到一处实际完成证据
```

### Synthetic Probe

Prompt：

> Recommend a workshop, explain why it suits first-year students, and tell them how to register.

只回答：

```text
Move 1:
Move 2:
Move 3:
```

不要写正文。

### Return to Task

一旦 Moves 清楚，马上回完整写作，不需要继续学“应用文分类大全”。

---

## D2｜G4 Specificity｜“有话写”常常来自更具体，而不是更多观点

### Mental Model

Content weakness 经常不是观点数量少，而是每个观点太空。

对一个 vague atom：

> this activity is useful

继续问：

```text
Useful for whom?
Useful for what?
How exactly?
What changes because of it?
```

### Before / After

Before：

> The language exchange is very useful for visiting students.

After：

> The language exchange gives visiting students a low-pressure way to meet local students in small groups during their first few weeks on campus.

第二句不只是更长，而是多了：

- for whom；
- mechanism；
- context。

### Micro Drill

把下面 atom 变具体，但不要变成完整段落：

> Regular feedback is helpful.

至少补一个：

```text
how
or
what problem it prevents
```

---

## D3｜G8 Core Message｜主题词不是中心思想

### Mental Model

Core Message 必须是一个可展开的关系 / 判断。

弱：

```text
cooperation
technology
persistence
planning
```

强：

> Cooperation becomes especially valuable when a task requires information or skills that no single person can provide alone.

### Four Gates

```text
grounded
specific
developable
not slogan-dependent
```

### Micro Drill

把 topic：

> self-discipline

生成两个不同 Core Message。

要求：

- 两个关系不同；
- 每个都能继续写 HOW / RESULT。

---

## D4｜S4 Information Gain｜每一句都必须比前一句多一点东西

### Mental Model

Development 的最小判据：

> **下一句新增什么信息？**

### Bad Chain

```text
A is important.
A plays an important role.
We should value A.
```

信息几乎没有移动。

### Better Chain

```text
Claim
→ why/how
→ result
→ implication
```

### Micro Drill

第一句：

> Clear instructions reduce confusion in group work.

第二句必须写 mechanism；第三句必须写 result。

禁止只是重复 `clear instructions are important`。

---

## D5｜L1 Proposition → English｜先把一个意思写稳

### Mental Model

复杂中文意图先压成 1–3 个简单 proposition。

例如：

> 及时反馈能让学生尽早发现错误做法，从而避免长期重复同一种低效方法。

先压：

```text
feedback comes early
students notice ineffective methods
bad habits do not continue for long
```

再写英文。

### Why This Matters

它直接降低：

- sentence overload；
- 中译英腔；
- relation 丢失；
- 句子写到中间失控。

### Micro Drill

意思：

> 明确下一步行动可以降低开始任务时的心理成本。

只允许最多两句英文。

目标：准确、自然、稳定，不追求高级。

---

## D6｜L2 Relation Realization｜连接词不是逻辑本身

### Mental Model

先确定关系：

```text
cause
result
contrast
condition
concession
example
mechanism
```

再选择 expression。

### Failure Pattern

常见错误：

> 只要句首加 Therefore / Moreover，段落就自动有逻辑。

实际上如果两句话没有真实 relation，连接词只是装饰。

### Micro Drill

给定：

```text
A: a simple plan clarifies the next action
B: people spend less time deciding where to start
```

先判断关系，再用两种不同英文方式连接。

---

## D7｜SW3 Recommend + Fit Reason｜推荐不是表达强烈态度

### Mental Model

推荐功能的高价值信息是：

```text
WHAT
+
WHY IT FITS THIS PERSON / CONTEXT
+
USEFUL DETAIL
```

### Failure Pattern

> I strongly recommend it because it is meaningful.

态度很强，信息很弱。

### Synthetic Probe

对象：刚到校、不太认识人的交换生。  
活动：small-group language exchange。

只写 2–3 句 recommendation move。

必须出现：

- fit reason；
- 至少一个 concrete detail。

---

## D8｜SW11 Register Shift｜同一个 intent 怎样随对象改变

### Mental Model

Register 不是单词等级，而是关系管理。

变化可能出现在：

```text
directness
context
politeness
contraction
word choice
opening / closing
```

### Micro Drill

Intent：

> “我需要把会议改到周四下午。”

分别写给：

1. 熟悉同学；
2. 不熟悉教授。

要求内容相同，但 register 合理变化。

---

## D9｜BW3 Core Message → Development｜不要从图片直接跳到万能价值观

### Mental Model

Big Writing 中间必须有：

```text
material relation
→ interpretation
→ core message
→ development
```

如果从 material 直接跳到：

> We should attach great importance to persistence.

中间的 reasoning 很可能空掉。

### Synthetic Probe

Material：

> 一个人不断收集学习资料却很少开始；另一个人用少量资料持续练习。

先生成：

```text
Observation:
Interpretation:
Core Message:
Mechanism:
```

不写成文。

---

## D10｜E3 Recovery / Simplification｜考场卡住时怎样不崩

### Mental Model

卡住时的优先级：

```text
TASK / MEANING
>
COMPLETENESS
>
STABLE LANGUAGE
>
STYLE
```

### Recovery Actions

```text
换简单词
拆长句
删低价值 modifier
用熟悉 construction
保住 required move
继续输出
```

### Synthetic Probe

你本来想写：

> The excessive dependence on constantly changing external sources of motivation may undermine an individual's ability to maintain a stable routine over an extended period.

如果中途失控，允许降级为：

> People may find it difficult to maintain a stable routine if they always depend on changing sources of motivation.

只要核心意思保住，降级就是正确执行，不是失败。

---

# E｜Synthetic Training Assets：第一次学习怎样主动练，而不消耗真题

这些训练不是长期学习单位。

它们用于：

- 第一次建立动作；
- 某个 failure 的 targeted repair；
- 不值得消耗 unseen exam 的 transfer probe。

正式 Writing Attempt 仍以完整作文为单位。

---

## E1｜Task Parsing Probe

输入：synthetic prompt。  
输出：

```text
Role / Audience
Purpose
Required Moves
Constraints
Register
```

通过标准：

- 没漏硬要求；
- 没把可选内容当硬要求；
- register 方向合理。

---

## E2｜Content Atom Probe

输入：task / core message。  
输出：3–5 atoms。

限制：

- 不写完整段；
- 不允许空泛万能句；
- 每个 atom 必须有真实信息。

---

## E3｜Specificity Probe

输入：一个 vague atom。  
任务：通过 `for whom / how / what changes / useful detail` 让它具体一层。

---

## E4｜Relation Pair

输入：Sentence A + 指定 relation。  
任务：自己生成 Sentence B。

关系可轮换：

```text
claim → mechanism
fact → implication
problem → consequence
recommendation → benefit
observation → interpretation
position → support
```

---

## E5｜Paragraph Development

输入：一个 claim。  
要求写 3–4 句：

```text
claim
→ mechanism
→ result
→ example / contrast / implication
```

通过标准：每一句有 information gain。

---

## E6｜Observation vs Interpretation

输入：synthetic visual description。  
先写 2–3 个 observation，再写 interpretation。

通过标准：事实与推论分开。

---

## E7｜Core Message Candidates

输入：synthetic material。  
生成三个候选 Core Message。

然后判断：

- 哪个太空；
- 哪个太窄；
- 哪个最可展开。

---

## E8｜Function Realization

只练一个 communicative function：

- request；
- invite；
- recommend；
- apologize；
- inform；
- thank；
- inquire。

先不写整篇。

---

## E9｜Register Shift

同一 intent 给不同 audience，生成不同 realization。

通过标准：

> 不只是替换一个情态动词，而是整体 relationship 合理。

---

## E10｜Compression / Simplification

输入：一个过长 / 高风险句。  
任务：保留核心意思，降低 sentence load。

---

## E11｜Error-Control Sprint

输入：synthetic short draft，包含少量高价值错误。  
限定短时间，只抓：

- sentence boundary；
- subject–verb；
- number / tense；
- obvious collocation；
- spelling；
- register / task omission。

不纠结风格偏好。

---

## E12｜Guided Full Synthetic Output

在真正碰真题前，各完成至少一次：

```text
one synthetic Small Writing
one synthetic Big Writing
```

轻量 scaffolding 允许：

```text
Task / Core Message
→ content atoms
→ paragraph roles
```

但禁止：

- 给完整模板填空；
- 先看 model essay 再仿写；
- 给现成段落让学习者拼装。

必须保留 first draft。

---

# F｜Material Routing：以后各种写作资料往哪里放

Writing 不按老师课程目录生长。

不同材料只按它们在能力形成中的功能归位。

---

## F1｜Canonical Learning Asset

当前 Writing owner 保存稳定的：

- Global Map；
- Core Learning Blocks；
- Skill Map；
- Chat-approved starter Skill Content；
- synthetic training semantics；
- learner-facing learning sequence；
- Runtime semantics。

---

## F2｜Teacher / Method Material = Repair Reservoir

老师作文课、写作书、模板书默认身份：

> **Repair Reservoir**

它们可以贡献：

- 一个更好的 task model；
- 一个高价值 communicative function；
- 一个 argument development method；
- 一组真实自然的 relation realization；
- 一个 register boundary；
- 一个 execution / checking strategy。

但不因为某老师有“30 类小作文”“40 个大作文主题”，就自动成为 KianOS 的学习顺序。

---

## F3｜Model Essay 的身份

Model essay 可以用于：

- 看一个 task 怎样完整完成；
- 看一个段落怎样产生 information gain；
- 比较 first draft 哪里缺内容；
- 找一种自然 realization；
- 抽取少量高迁移 component。

Model essay 不应该：

- 出现在 clean attempt 前；
- 默认逐句背诵；
- 因为比 learner draft 漂亮，就让所有差异都进入 repair；
- 取代 learner content generation；
- 成为唯一 surface-form authority。

---

## F4｜Template 的身份

模板不是敌人。

真正有价值的是非常薄的 stable skeleton：

```text
Small Writing
purpose → required moves → clear close

Big Writing
material → core meaning → development → implication / close
```

长期 personal template 应该按这个顺序长出来：

```text
真实输出
→ 多次成功
→ 发现稳定共性
→ 压缩成 reusable skeleton / component
```

而不是：

```text
先背固定 150–180 词
→ 强行把所有题塞进去
```

---

## F5｜Training Material

训练材料分成：

```text
synthetic
用于 framework / component drill / micro-probe

exposed exam material
已经做过，可用于普通 repair / rewrite / comparison

protected unseen
保留 clean first attempt / exam fit / strong transfer value
```

未见真题是有限 diagnostic capital。

不要为了展示一个句型、一个 register 例子或一个 paragraph move 随手消耗。

---

## F6｜Lexical Material

Writing 只保留：

> 这次真实输出发生了 lexical production failure。

长期：

- sense；
- phrase；
- construction；
- collocation；
- contrast；
- confusable；

继续由 LexicalOS canonical owner 管理。

---

## F7｜Personal Runtime Evidence

个人：

- task plan；
- first content response；
- first structure；
- first draft；
- revision trajectory；
- timing；
- personal note；
- later transfer；

属于 learner runtime，不写进共享 Writing canonical content。

未来视觉上可以让 Skill Node 同时看到：

```text
Canonical knowledge
+
My evidence
```

但底层 owner 必须分开。

---

# G｜HOW YOU LEARN IT：第一次怎样学，之后怎样练

这是学习 Writing 的方法，不是 Writing 的第五种 skill。

---

## G1｜Cold Start

对于此前没有系统写过考研作文的学习者，不建议直接拿 fresh true exam 当启蒙教材。

Cold Start：

```text
Global Map
↓
Core Blocks B1–B4
↓
Small Writing B5
↓
Big Writing B6
↓
Execution B7
↓
Integrated Synthetic Walkthrough B8
↓
Synthetic component probes
↓
one full synthetic Small + one full synthetic Big
↓
Clean True-Exam Attempt
```

这不是要求先学很久再做题。

它的目的只是：

> **先把最基础的生成动作装上，再用真题测真实能力。**

---

## G2｜第一次学习不要求背 Skill Map

第一次学完后，只要真正理解：

```text
Task
→ Content
→ Structure
→ Language
→ Control
→ Deliver
```

并能自己做几次 synthetic active check，就够了。

Skill IDs 是未来定位用的，不是考试术语。

---

## G3｜第一次完整输出以后，Guide 应该退到后台

进入真实 Writing 以后，正常主线变成：

```text
完整 Attempt
→ Whole-Essay Review
→ first meaningful failure
→ smallest repair
→ learner re-generation
→ later fresh transfer
```

不要每篇作文都重新学习整份 Guide。

---

## G4｜同题 Rewrite 不是 mastery

同一个 prompt：

```text
看反馈
→ 改好
```

只能说明 repair 生效。

更强证据：

```text
new prompt
→ 同一种 underlying demand
→ 独立成功生成
```

例如今天修了：

> recommendation 缺 fit reason。

真正 transfer 是下次另一道推荐 / 建议 task 中，你自然写出：

```text
what
+
why it fits
+
useful detail
```

# H｜第一次网页学习的内容—展示—交互语义

这一节不是前端实现说明，而是静态资产应该怎样被未来网页消费。

目标：

> **未来打开 Writing Learn，一次性完成能力建模；网页负责降低认知负荷，不重新发明教学顺序。**

---

## H1｜第一次进入先看 Global Map，不先看目录树

首屏应该优先展示：

```text
TASK
→ GENERATE
→ ORGANIZE
→ REALIZE
→ CONTROL
→ DELIVER
```

再告诉学习者：

> 下面会连续学这些动作怎样形成。

Skill Map 默认不是第一学习入口。

---

## H2｜Core Blocks 连续学习，不拆成几十个页面任务

B1–B8 应作为一个连续 Learning Route。

每个 Block 内部建议保持：

```text
Core Model
→ Mechanism
→ Good / Bad Contrast
→ Synthetic Example
→ Active Check
→ Reveal / Explanation
→ Compression Action
```

不是每个 Block 都必须机械六格，但学习动作应该完整。

---

## H3｜Active Check 先尝试，再揭示

像：

- Task Parsing；
- Content Atom；
- Observation vs Interpretation；
- Core Message；
- Paragraph Development；
- Register Shift；
- Proposition → English；

都适合：

```text
先让 learner 做
→ 再展开一个参考判断 / possible realization
```

不要一开始把答案、成文、model essay 全摆出来。

---

## H4｜Synthetic 练习是教学材料，不是长期题库

初学网页可以内嵌少量高价值 synthetic probe。

不需要：

- 建几百道 micro drill；
- 给每个叶子节点造 20 题；
- 把 Writing 做成碎片刷卡系统。

需要时 Chat 可以继续生成针对性 probe。

---

## H5｜Small / Big Writing 要看到共享主干，也看到真实分叉

未来页面不能把 Small / Big 做成两门完全独立课程。

应该先共享：

```text
Task
Content
Structure
Language
Execution
```

然后明确分叉：

```text
Small Writing
→ audience / purpose / moves / register / useful detail

Big Writing
→ material / interpretation / core message / development
```

这样不重复学习公共能力。

---

## H6｜Skill Map 是后续导航，而不是首次进度表

第一次学完后，Skill Map 可以成为：

- Browse / Explore；
- repair 定位；
- Chat handoff locator；
- personal evidence overlay 的地址层。

不要显示成：

> R1 100%、R2 80%、G4 60%……

除非后续真实 learner evidence 证明这种显示有学习价值。

---

## H7｜“问 Chat”必须出现在合适边界

适合问 Chat：

- 具体 task 有歧义；
- 两个 content direction 难选择；
- 一个 paragraph 不知道为什么空；
- 两个 register realization 都似乎合理；
- 某句想保留自己的意思但不会稳定实现；
- 真实作文多个表面问题可能来自同一个上游 failure。

不适合把正文替换成：

> “这里问 Chat。”

高频主干必须由静态资产自己承担。

# I｜True-Exam Entry Gate：什么时候值得消耗第一篇真题

真题不是禁区，而是高价值测量资产。

进入真题的标准不是：

> Guide 全背完。

而是：

> **面对合成完整题，已经能独立生成一篇结构完整、任务基本完成的作文。**

---

## I1｜Small Writing Gate

至少能：

1. 快速拆 audience / purpose / required moves；
2. 每个 move 生成一个具体 detail；
3. 基本完成常见 communicative functions；
4. register 大方向合理；
5. 独立完成一篇 synthetic Small Writing；
6. 不依赖整篇模板才能开始写。

---

## I2｜Big Writing Gate

至少能：

1. 分 Observation / Interpretation；
2. 形成一个可展开 Core Message；
3. 生成 2–3 个不重复 support atoms；
4. 把一个 claim 展开成有 information gain 的段落；
5. 独立完成一篇 synthetic Big Writing；
6. 不依赖预先知道主题模板才能开始。

达到这些就应该进入真题。

不要因为“还不完美”继续堆启蒙材料。

---

## I3｜第一篇真题的意义

第一篇真题主要测：

- synthetic skill 是否能迁移到真实 prompt；
- 真题 task constraints 有没有新边界；
- content generation 在真实题面下是否仍稳定；
- first draft 和 synthetic 相比哪里开始变形；
- 时间 / execution 如何。

第一次真题尽量保持 clean：

- 不提前看范文；
- 不提前看主题总结；
- 不提前看针对该题的写作思路；
- 不提前背该题相关模板。

---

# J｜Writing Runtime v1 — FROZEN

**Status:** FROZEN  
**Frozen on:** 2026-09-12  
**Parent authority:** `content/english/LEARNING_CONTRACT.md`  
**Relationship to Objective Runtime:** shares English-wide evidence / repair / transfer philosophy, but Writing keeps its own cognitive object, evidence units, repair actions, and learner-facing interaction.

本节服务真实 Writing Attempt / Chat review / future UI。第一次学习不要求背 runtime 状态。

---

## J1｜Learning Unit：一篇完整作文 = 一个正式 Writing Unit

冻结：

> **正式 Writing Attempt 以一篇完整作文为 learner-facing 最小学习单位。**

内部 evidence 可以细到：

- task requirement；
- planning atom；
- core message；
- paragraph；
- sentence；
- lexical / construction span；
- revision event；
- timing event。

但正常 learner–Chat review 从**整篇作文**开始。

Chat 先判断：

- 多个表面错误是否来自同一个上游 failure；
- 哪些只是 cascading downstream effects；
- 哪个 failure 最值得先修。

不要把一篇作文拆成十几个独立“错题”。

---

## J2｜First Meaningful Evidence 必须保留

正式 Attempt 至少保护：

```text
prompt
+
first meaningful plan / content response
+
first draft
```

后续 revision 不能覆盖 first draft。

原因：最终润色版无法告诉我们：

- 最初 Task 是否理解正确；
- Content 是自己生成还是 feedback 补出来；
- Structure 是否自己建立；
- 哪些表达真实无法调用；
- 哪些错误在时间压力下出现。

---

## J3｜Runtime State Machine

```text
ATTEMPT
↓
PASS / ACCEPTABLE
or
REPAIR_NEEDED
↓
FIRST_FAILURE_LAYER
├─ Task
├─ Content
├─ Structure / Development
├─ Language Realization
├─ Error / Register Control
└─ Timed Execution
↓
SMALLEST_REPAIR
↓
RE-GENERATE
↓
TRANSFER_PENDING
↓
later fresh / unseen Writing evidence
↓
CLOSED
```

解释：

- **ATTEMPT**：clean planning + first draft；
- **PASS / ACCEPTABLE**：没有足以影响当前得分可靠性的 meaningful failure；
- **FIRST_FAILURE_LAYER**：找最早一个足以解释主要结果的失败层；
- **SMALLEST_REPAIR**：只修到能重新生成；
- **RE-GENERATE**：学习者自己重写受影响 scope；
- **TRANSFER_PENDING**：当前已修，但尚缺 fresh evidence；
- **CLOSED**：后续新 Writing task 中有足够独立迁移证据。

同 prompt rewrite 成功只证明 repair / retention，不证明 mastery。

---

## J4｜Cascade / Dependency Collapse：下游错误不重复计债务

典型链：

```text
Task 误解
→ Content 选偏
→ Structure 看起来奇怪
→ Language 也很难写
```

或：

```text
Core Message 太空
→ 第二段没有可展开内容
→ 开始堆万能句
→ 语言显得重复
```

这些不能简单记成四个 weakness。

冻结：

> **把最早一个足以解释主要下游表现的 failure 作为 primary repair target。**

只有上游修复后，下游问题仍独立存在，才创建新的 repair object。

---

## J5｜Repair Scope：不默认整篇重写

Repair 范围必须跟 failure 范围一致。

```text
Task failure
→ 重做 Task Brief；必要时整篇结构重建

Content failure
→ 重做 atoms；重写受影响 paragraph

Structure failure
→ 重排 paragraph role / sentence relation；重写相关段

Language failure
→ 重写 sentence / sentence pair / local span

Register failure
→ 重写相关 communicative move

Execution failure
→ 修复 planning / recovery / check behavior
```

解释看懂不算修复。

必须由 learner 自己重新生成。

---

## J6｜Model / Reference Reveal：延迟出现

正常顺序：

```text
first draft
→ whole-essay diagnosis
→ minimal repair / cue
→ learner re-generation
→ model / comparison when useful
```

不要在 learner 重新生成前直接给完整 model essay，除非当前学习目的就是显式 study model，而不是 clean repair。

Model essay 是：

- reference；
- comparison source；
- realization example。

不是唯一 authority。

---

## J7｜PASS / ACCEPTABLE Semantics

Writing 不要求和 model essay 长得像。

如果当前文本：

```text
task completed
+
content relevant and sufficient
+
structure readable
+
meaning clear
+
language acceptable
+
register / execution adequate
```

就可以快速通过。

以下不自动触发 repair：

- 某个词不够“高级”；
- 和 model 不同但同样自然；
- 一次风格偏好；
- 可以润色但对得分可靠性影响很小的差异。

---

## J8｜Evidence Hierarchy

```text
看懂讲解 / model
<
同一段在 cue 后改好
<
同一 prompt 隔一段时间独立重写
<
targeted fresh synthetic probe 上成功
<
new prompt 中独立调用同一能力
<
repeated independent transfer across unseen Writing tasks
```

真正强的 mastery evidence 是：

> 新任务下仍然能主动生成正确动作。

---

## J9｜Memory Admission

优先进入长期观察 / 复习的对象：

- 可迁移 communicative function；
- recurring Task failure；
- recurring content-generation bottleneck；
- repeated paragraph-development failure；
- stable relation-realization problem；
- repeated production lexical failure（长期知识回 LexicalOS）；
- recurring grammar / execution failure；
- transfer evidence 持续弱或矛盾的对象。

不要因为：

- 一次措辞普通；
- model 里出现漂亮句子；
- 一次语法小错；
- 同 prompt 改好；

就自动制造长期复习债务。

---

## J10｜Runtime Interaction Boundary

至少保存：

```text
prompt
+
first plan / content response when meaningful
+
first draft (immutable evidence)
+
current revision
```

正常复盘：

```text
完整作文
→ Chat 找 primary failure
→ 只展开最小必要 evidence slice
→ learner re-generates
→ 必要时 model / comparison
→ TRANSFER_PENDING
```

禁止为了实现方便：

- 把 Writing 变成逐句独立 Chat review；
- 每句话强制选择 error taxonomy；
- 把所有语言差异做成 permanent cards；
- 用 model essay 覆盖 first draft；
- 把 Small / Big Writing 做成模板填空器；
- 复制 Reading / Objective 的 A–D 式 UI 或 wrong-reason taxonomy。

---

## J11｜Frozen Exit Rule

> **Repair 解决这篇作文；fresh transfer 才关闭能力问题。**

完整闭环：

```text
完整 Writing Attempt
→ preserve first meaningful plan + first draft
→ whole-essay review
→ locate smallest primary failure
→ collapse downstream effects
→ smallest repair
→ independent re-generation
→ optional targeted synthetic probe
→ TRANSFER_PENDING
→ later unseen Writing success
→ CLOSED
```

除非新的真实 learner evidence materially contradicts 这套模型，否则不要因为 UI 便利、老师模板分类、资料目录或 Objective Runtime 的形式不同而重新打开 Writing Runtime v1。

---

# K｜第一次学习出口

完成 Global Map + Core Blocks 后，不要求：

- 背完所有应用文名称；
- 背几十类主题；
- 记大量高级替换；
- 掌握所有复杂句；
- 把 Skill Map 全部背下来。

真正要求的是能自然完成下面动作。

### Shared

```text
看题
→ 形成 Task Model
→ 生成真实 content atoms
→ 给内容安排 role / order
→ 用自己能控制的英语实现
→ 高价值检查
```

### Small Writing

```text
识别 audience / purpose / required moves
→ 生成 useful details
→ 用合适 register 完成 functions
→ 给读者清楚 next step / close
```

### Big Writing

```text
分 Observation / Interpretation
→ 形成 Core Message
→ 生成 WHY / HOW / RESULT / CONTRAST
→ 让核心段产生 information gain
→ 用稳定英语完成
```

### Repair Awareness

```text
知道 Task / Content / Structure / Language 不是一回事
→ 出错时先找 first meaningful failure
→ 不用 model 覆盖自己的 first draft
```

达到这里，Writing Learning Asset 就应该逐渐退到后台。

真正建立能力的主线变成：

> **完整写作 → 高价值复盘 → 最小修复 → 重新生成 → 新题迁移。**

最终目标不是“记住这份 Writing Guide”。

而是：

> **面对一个没见过的题，不需要先寻找模板，也知道自己要完成什么、写什么、怎样推进，并能用自己真正掌握的英语把它交付出来。**
