# Objective Tasks｜第一次学习框架与高密度能力资产

> **定位**：English I 客观题（Cloze / Reading A / Reading B）的 Current learner-facing first-learning asset。  
> **第一次学习**：先建立 Objective Global Map，再分别连续学习对应题型的 Core Learning Blocks；不要从题型标签、错题卡或几十个 Skill 节点开始。  
> **后续训练**：Skill Map 负责稳定地址与诊断；真实题目负责提供 evidence；Runtime 负责 Attempt / Review / Repair / Transfer。  
> **Chat 展开原则**：静态资产负责高频、稳定、真正改变做题能力的主干；复杂边界、多个机制同时作用、真实选项竞争、个性化 micro-drill，优先在真实遇到时交给 Chat。`可以问 Chat` 不是把正文做薄的借口，也不是提前写完所有长尾的理由。  
> **原则**：先形成题型认知模型，再大量做题；Skill Map 是地址，不是第一次学习课程目录；真实 transfer 比重复同题更能证明学会。

---

# A｜Objective Global Map：客观题到底在训练什么

客观题不是：

> 看文章 → 凭感觉从四个答案里挑一个。

真正共同的决策骨架是：

```text
INPUT
文章 / 局部上下文 / 题目 / 候选
↓
REPRESENT
先把当前需要理解的语言和关系搭准
↓
DEMAND
现在到底缺什么、问什么、要求什么结构角色
↓
CANDIDATES
真正有哪些竞争假设
↓
EVIDENCE / CONSTRAINTS
什么证据能排除或支持它们
↓
ADJUDICATE
找到真正决定答案的差异
↓
EXECUTE
在考试时间里做出稳定决定并离开
```

三种客观题共用这个抽象骨架，但认知对象不同：

```text
Cloze
Slot Demand → Constraints → Candidate Competition → Best Fit

Reading A
Question Demand → Decisive Evidence → Option Proposition → Adjudication

Reading B
Discourse Skeleton → Position Demand → Candidate Role → Global Reconciliation
```

## A1｜先区分能力层和题型层

一个错误首先要问：

> **最早哪一层已经坏了？**

如果是：

- 词义、搭配、构式、熟词新义、confusable → **Lexical**；
- 句意、scope、reference、逻辑关系、篇章推进没有搭准 → **Reading**；
- 语言表示已经够用，但不会完成该题型的决策动作 → 才属于 **Cloze / Reading A / Reading B task-specific procedure**。

因此客观题不是三套独立知识库。

```text
Lexical / Reading = 可迁移能力 owner
Cloze / Reading A / Reading B = 决策训练器
```

## A2｜为什么不能从“题型分类”开始学

老师常见目录可能是：

```text
细节题
推断题
主旨题
态度题
词义题
……
```

这些标签可以描述题目，却不一定解释你为什么做错。

例如同样一题“推断题”，真正 failure 可能分别是：

- 没读懂句子；
- 找错证据范围；
- 把 `may` 当成 `must`；
- 把局部例子扩大成作者总体观点；
- 证据和选项都理解了，但没有比较真正竞争的两项。

所以第一次学习要先形成**做题认知动作**，题型标签只留作辅助地址。

## A3｜正确题不是自动学习债务

第一次学习资产负责建立 mental model；真实训练负责验证它。

一篇 / 一组题全部稳定做对时：

```text
PASS → next
```

不需要为了“学完整”强迫打开每题解析。

只有 wrong / unanswered / uncertain 或高质量行为 evidence 才进入 repair。

<a id="cloze"></a>
# B｜Cloze：Slot Constraint → Best Fit

## B0｜Global Model

完形不是二十道独立词义题。

真正的任务是：

```text
PASSAGE CONTEXT
↓
SLOT DEMAND
这个位置需要什么？
↓
ACTIVE CONSTRAINTS
哪些限制正在起作用？
↓
REAL COMPETITORS
真正有竞争力的是哪两三个候选？
↓
DECISIVE CONSTRAINT
哪一条证据把它们分开？
↓
BEST FIT
不是“能放”，而是“最合适”
```

第一次学习 Cloze，不要求你做到“遮住选项就猜出原词”。

需要形成的是：

> **在看到四个候选之前，脑中已经对 slot 有一个足够有用的需求模型。**

---

## B1｜Core Block 1：Slot Demand｜先问这个空需要什么

### 核心模型

看到空时，不要先问：

> A/B/C/D 哪个中文意思顺？

先问：

```text
这里语法上允许什么？
这里语义上缺什么角色？
和前后文是什么关系？
如果只用一个粗糙概念描述，这里应该补什么？
```

Slot Demand 不等于精确预测答案。

例如：

> The policy looked efficient on paper, ___ it created unexpected costs in practice.

在看选项前，最有价值的 demand 不是猜出 `but / yet / however` 中某一个，而是：

> **这里需要一个把“理论上高效”与“实际产生意外成本”连接起来的 contrast / concession relation。**

这已经足够大幅减少候选空间。

### 常见错误

- 看到选项才开始理解句子；
- 用四个中文释义互相试填；
- 只看空前两个词；
- 把“我能想到一个词”误当成 Slot Demand。

### Active Check

看到：

> People often remember striking examples, ___ they may forget the broader statistical pattern.

先不猜具体连接词，只回答：

1. 两个命题之间是什么关系？
2. 这个 slot 更像在补 content word，还是 relation marker？
3. 如果选项里同时有因果和转折表达，哪一类先被排除？

---

## B2｜Core Block 2：Constraint Stack｜答案是被多层限制共同逼出来的

### 核心模型

完形的约束不是只有“词义”。

可以按五层看：

```text
L1 Lexical / Collocation
词义、搭配、语义偏好

L2 Syntax / Construction
词性、支配、构式、固定结构

L3 Sentence Proposition
放进去后整句到底断言什么

L4 Inter-sentence Relation
和前后句是什么逻辑/信息关系

L5 Global Discourse
是否符合整篇主题、立场、推进方向
```

不是每一空都要显式检查五层。

真正熟练以后，大量限制会自动完成；卡住时再问：

> **现在真正分胜负的是哪一层？**

### 一个重要边界

如果两个候选都“语法正确、中文也说得通”，这不代表题目模糊。

你需要继续寻找：

- 哪个更符合 collocation；
- 哪个更符合当前 proposition；
- 哪个 relation 与前后文一致；
- 哪个只有局部可行、全局却不成立。

### Active Check

如果两个近义动词都能作谓语，优先不要继续查“它们中文分别是什么”，而问：

```text
它们各自通常和什么对象搭？
当前主语/宾语是否满足这种 semantic preference？
整句真正需要的是动作、状态，还是评价？
```

---

## B3｜Core Block 3：Candidate Competition｜不要平均分析四个选项

### 核心模型

真实做题时，大多数空不是“四选一”，而更像：

```text
4 candidates
↓ 快速淘汰明显不合适项
2 real competitors
↓ 找决定性差异
1 best fit
```

所以高价值动作不是：

> 给 A/B/C/D 每个写一段解析。

而是：

> **找出你真正会犹豫的竞争项，并说出什么 constraint 能把它们分开。**

### Near-synonym competition

近义项最容易诱导“中文都差不多”。

要转成：

```text
两项共同覆盖的意义是什么？
它们真正不同的使用条件是什么？
当前 slot 正好触发了哪一个区别？
```

例如一个词强调“结果发生”，另一个强调“主动促成”；中文都可能译成“导致”，但当前主语的语义角色可能只允许其中一个。

### Local possibility ≠ Best Fit

完形尤其要区分：

```text
possible
≠
best supported
```

一个选项能组成合法句子，只说明它没有立刻出局。

最终 authority 是当前上下文全部有效约束的联合结果。

---

## B4｜Core Block 4：Passage Execution｜整篇完成，而不是被一个空拖死

### 核心模型

考试执行可以压成：

```text
快速建立 passage direction
→ 每空先形成 demand
→ 简单空直接走
→ 真竞争空找 decisive constraint
→ 局部证据不足时扩大上下文
→ 仍不确定则保留 uncertain 并继续
→ 完成整篇后再回看高价值冲突
```

### 什么时候该扩大上下文

值得扩大：

- relation 依赖上一句或下一句；
- pronoun / topic continuity 不清；
- 两个候选局部都成立；
- 当前词义依赖篇章主题。

不值得扩大：

- 一个清晰 collocation 已经决定答案；
- 语法构式已排除其余项；
- 只是中文措辞感觉不够漂亮。

### Stop Rule

当你已经有：

```text
clear slot demand
+
one decisive constraint
+
best candidate clearly outranks rivals
```

就应该离开。

不要为了证明自己“分析完整”把一个简单空做成语言学论文。

---

## B5｜Cloze Skill Map：后续诊断地址，不是第一次学习清单

```text
CL1 Slot Demand
   ├─ lexical/content demand
   ├─ relation demand
   └─ grammatical-role demand

CL2 Lexical Constraint
   ├─ sense competition
   ├─ collocation
   ├─ semantic preference
   └─ confusable

CL3 Construction Constraint
   ├─ government
   ├─ phrase / frame
   └─ syntax compatibility

CL4 Proposition Fit

CL5 Discourse Relation
   ├─ contrast / concession
   ├─ cause / result
   ├─ condition
   ├─ example / specification
   └─ continuation / progression

CL6 Candidate Competition
   ├─ near-synonym contrast
   ├─ local-possible vs best-fit
   └─ decisive-constraint selection

CL7 Execution
   ├─ context expansion
   ├─ uncertainty triage
   └─ stop rule
```

### Starter Skill Content｜CL6.2 Local-possible vs Best-fit

**Mental model**：不要问“这个能不能放”，要问“在所有有效约束下，它是不是比竞争项更有证据”。

**Boundary**：如果一个候选只靠“中文顺”成立，而另一个同时满足 collocation + proposition + discourse relation，前者不应因为“也说得通”继续保留同等权重。

**主动判断**：当你说“两个都可以”时，必须补一句：

> 哪个额外 constraint 还没有检查？

如果找不到，就把这一空保留 uncertain，而不是随意凭语感结束。

<a id="reading-a"></a>
# C｜Reading A：Evidence Adjudication

## C0｜Global Model

Reading A 不是“读懂文章以后凭印象选最像的”。

真正的工作链是：

```text
TEXT REPRESENTATION
当前相关文本到底说了什么
↓
QUESTION DEMAND
这道题要求判断什么 proposition
↓
DECISIVE EVIDENCE
哪一段文本真正决定答案
↓
OPTION PROPOSITIONS
每个候选到底在断言什么
↓
BOUNDARY / CONTRAST
谁越界、偷换、强化、缩小或答非所问
↓
ADJUDICATION
选择证据支持最充分的一项
```

Reading A 的难点经常不在“文章完全没读懂”，而在：

> **文本只说到这里，选项却偷偷多走了一步。**

---

## C1｜Core Block 1：Question Demand｜先把题目压成一个判断任务

### 核心模型

题干不是标签，而是对 evidence 的需求说明。

做题前先把问题压成：

```text
我要判断谁 / 什么？
判断的是事实、原因、态度、目的、关系还是推断边界？
答案必须覆盖什么范围？
```

例如：

> What can be inferred from paragraph 3?

不要只在脑中贴上“推断题”。

更有效的是：

> **我要找一个 paragraph 3 没有逐字说出、但被其证据充分支持，而且不能超出证据强度的 proposition。**

这会直接改变你后面对选项的判断标准。

### Question type 的正确身份

DETAIL / INFERENCE / ATTITUDE / MAIN IDEA 等可以帮助预期 evidence 形状，但不能替代实际 question demand。

两个同属 inference 的题，可能一个主要考 scope，一个考 cause boundary。

---

## C2｜Core Block 2：Decisive Evidence & Boundary｜定位不是“找到相关词”

### 核心模型

真正的 decisive evidence 是：

> **没有这段证据，就不能可靠决定选项；有了它，就能让竞争项分出胜负。**

定位有三个层次：

```text
TOPIC MATCH
找到了同一个主题
<
RELEVANT REGION
找到了相关句群
<
DECISIVE EVIDENCE
找到了真正限制答案边界的最小证据
```

很多“定位错”其实不是完全没找到，而是：

> 找到了相关段落，却没有缩到真正决定答案的 relation / scope / qualification。

### Evidence Boundary

文本支持程度可以粗略想成一个边界：

```text
text says X
```

选项可能变成：

```text
X
X + stronger degree
X + broader scope
X + new cause
X + new attribution
X + universal claim
```

只有第一个或真正被文本许可的扩展才能留下。

### Active Check

原文如果说：

> The approach may help some users under limited conditions.

那么以下变化都要高度警惕：

- `will help users`：modality 强化；
- `helps all users`：quantity / scope 扩大；
- `works in most situations`：condition 范围扩大；
- `is preferred by researchers`：新增 attribution。

---

## C3｜Core Block 3：Option Proposition｜把选项当成命题，而不是一句英文

### 核心模型

一个选项至少可以拆成：

```text
ENTITY / SUBJECT
谁或什么

PREDICATE
发生什么 / 被判断为什么

SCOPE
适用范围多大

DEGREE / MODALITY
说得有多满

RELATION
因果、比较、条件、归属是什么

TIME / CONDITION
什么时候成立
```

因此真正比较选项时不要问：

> 哪一句“像原文”？

而要问：

> **这个 option proposition 和 decisive evidence 相比，哪一个字段发生了变化？**

### 常见 Option Shift

```text
ENTITY SHIFT      主体换了
SCOPE SHIFT       范围扩大 / 缩小
DEGREE SHIFT      程度变强 / 变弱
MODALITY SHIFT    可能 → 必然
CAUSE SHIFT       相关 / 条件 → 因果
ATTRIBUTION SHIFT 谁持有这个观点变了
TIME SHIFT        时间条件变了
LOCAL → GLOBAL    局部描述扩大成总体结论
EXAMPLE → CLAIM   例子被抬成一般规律
```

这些 code 是后续 Skill Map 地址，不要求第一次学习时逐项背名字。

第一次真正要学会的是：

> **选项也是一个需要精确理解的 proposition。**

---

## C4｜Core Block 4：Adjudication & Execution｜真正分胜负的是竞争项

### 核心模型

正常路径：

```text
理解 question demand
→ 找 decisive evidence
→ 快速淘汰明显越界项
→ 找出 2 个真实竞争项
→ 说清决定性差异
→ 选择
```

不要为了“严谨”平均分析四个选项。

### 改答案规则

如果第一次选择已有明确证据支持：

> **没有新的决定性 evidence，不从已经合理的答案改走。**

“突然觉得另一个更像”不是新 evidence。

### 什么时候需要回文章

回去：

- 两个选项只差 scope / degree / attribution；
- 你说不出决定答案的文本依据；
- 一个 inference 看起来合理，但不确定是否越界；
- reference / relation 会改变 proposition。

不必回去：

- 当前 evidence 已经直接 contradiction 一个选项；
- distractor 明显答非所问；
- 只是记不清原文用的是哪个同义词，但 proposition 已稳定。

### Stop Rule

当你能说出：

```text
question demand
+
decisive evidence
+
winning difference between real competitors
```

就离开这题。

---

## C5｜Reading A Skill Map：稳定地址，不是题型课程目录

```text
RA1 Question Demand
   ├─ requested entity / proposition
   ├─ evidence range
   └─ inference requirement

RA2 Evidence
   ├─ relevant-region locating
   ├─ minimal decisive evidence
   └─ evidence boundary

RA3 Option Representation
   ├─ entity / object
   ├─ scope
   ├─ degree / modality
   ├─ relation / cause
   ├─ attribution
   └─ time / condition

RA4 Option Competition
   ├─ supported vs merely plausible
   ├─ true-but-irrelevant
   ├─ local-to-global
   ├─ example-as-claim
   └─ over-inference

RA5 Discourse
   ├─ stance
   ├─ paragraph function
   └─ cross-sentence relation

RA6 Execution
   ├─ evidence return
   ├─ answer switching
   ├─ uncertainty triage
   └─ stop rule
```

### Starter Skill Content｜RA2.3 Evidence Boundary

**Mental model**：答案必须待在文本证据许可的区域内。一个现实中“很可能是真的”选项，只要文本没有给够支持，就仍然不能选。

**Boundary test**：把选项最强的词圈出来——`all / only / must / mainly / cause / always / completely` 等——问文本是否真的承担得起这个强度。

**主动判断**：当两个选项都“有点像”时，不要继续找相同点，改问：

> 哪一个比文本多说了什么？

### Starter Skill Content｜RA3.3 Degree / Modality Shift

**Mental model**：`may / can / tend to / often / some` 都是在控制 proposition strength。

文本说“可能”，选项说“必然”；文本说“一些”，选项说“普遍”，即使主题完全一致，仍然已经换了命题。

**主动判断**：每次被两个近似选项卡住，先比较它们说得有多满，而不是只比较主题词。

<a id="reading-b"></a>
# D｜Reading B / Part B：Discourse Reconstruction

## D0｜Global Model

Part B 不是关键词配对。

真正的任务是：

```text
WHOLE MATERIAL
↓
DISCOURSE SKELETON
文章整体在怎样推进
↓
POSITION DEMAND
这个位置现在缺什么功能
↓
CANDIDATE ROLE
每个候选在篇章里承担什么角色
↓
LOCAL FIT
前后是否能接上
↓
GLOBAL RECONCILIATION
放进去以后整张图是否仍然成立
```

一个候选与前一句有相同关键词，只是 evidence；不是 authority。

最终 authority 是：

> **discourse role + backward fit + forward fit + global consistency。**

---

## D1｜Core Block 1：Discourse Skeleton｜先看文章往哪里走

### 核心模型

第一次扫材料，不需要给每段贴正式标签。

只要能形成一个粗骨架：

```text
提出问题
→ 解释原因
→ 给例子
→ 转折 / 限制
→ 提出方案
→ 总结 / 推论
```

具体文章当然可能不同。

Skeleton 的目标不是 taxonomy 完整，而是：

> **知道每一块信息为什么出现在这里，以及下一块大概率需要承担什么功能。**

### 高价值线索

- topic continuity；
- claim → evidence；
- general → example；
- problem → solution；
- cause → consequence；
- contrast / concession；
- chronology；
- question → answer；
- old information → new information。

---

## D2｜Core Block 2：Position Demand｜先判断这里缺什么角色

### 核心模型

看到一个 gap 时，先暂时不看候选。

问：

```text
前面刚完成了什么？
后面接下来在做什么？
这个位置必须完成怎样的桥接？
```

例如：

- 前面提出一个一般观点，后面直接进入具体案例 → gap 可能需要 example introduction；
- 前面连续讲优点，后面开始限制 → gap 可能承担 contrast / qualification；
- 前面描述问题，后面列出措施 → gap 可能完成 problem → solution transition。

Position Demand 不要求预测原句。

只要先锁定**功能角色**，候选池就会从“很多句子”变成“哪些候选能承担这个角色”。

---

## D3｜Core Block 3：Candidate Role & Cohesion｜候选不是关键词袋

### 核心模型

每个 candidate 都可以先压成：

```text
它在说什么
+
它在篇章里想干什么
```

例如：

- 提出 claim；
- 解释原因；
- 举例；
- 否定前文；
- 转折；
- 总结；
- 承接一个 reference；
- 引出 solution。

### Cohesion evidence

局部连接可以看：

- pronoun / reference；
- lexical chain；
- repetition / synonymy；
- connective；
- topic continuity；
- tense / chronology；
- definite / given information。

但要记住：

> **cohesion 能证明“接得上”，不能单独证明“这里就是最佳位置”。**

一个候选可能和前一句接得很好，却会让下一段断掉，或者让剩余 candidate map 无法完成。

---

## D4｜Core Block 4：Global Reconciliation｜Part B 必须回到整张图

### 核心模型

每完成一个高置信 placement，都要更新全局约束：

```text
这个 candidate 已经被使用
↓
剩余 positions 的需求发生变化
↓
剩余 candidates 的可行位置被压缩
↓
之前的低置信 placement 可能被证伪或加强
```

这就是为什么 Part B 不能被当成 5 道独立选择题。

### Coupled Error

典型情况：

```text
Position 2 选 B
Position 4 选 D
formal map 恰好相反
```

如果原因是你把 B / D 的 discourse role 理反了，这不是两个独立弱点，而是：

> **1 个 coupled role-contrast failure。**

### Cascade

如果最早一个 structural transition 看错，后面三个位置都被迫在错误骨架里安排：

```text
1 primary structure failure
+
3 dependent placements
```

不是四个长期错题。

### Final Global Check

完成后最后问：

```text
每个 position 都完成了它需要的 role 吗？
前后链条有没有突然断裂？
是否有 candidate 只能靠关键词勉强挂住？
剩余 map 是否整体自洽？
```

## D5｜Reading B Skill Map：后续重建地址

```text
RB1 Discourse Skeleton
   ├─ claim / evidence
   ├─ general / example
   ├─ problem / solution
   ├─ cause / consequence
   └─ contrast / qualification

RB2 Position Demand
   ├─ backward requirement
   ├─ forward requirement
   └─ bridge role

RB3 Candidate Role
   ├─ function compression
   ├─ reference chain
   ├─ lexical cohesion
   └─ topic continuity

RB4 Fit Testing
   ├─ backward fit
   ├─ forward fit
   └─ local vs global fit

RB5 Global Reconciliation
   ├─ candidate elimination
   ├─ coupled placement
   ├─ swap detection
   └─ cascade / dependency

RB6 Execution
   ├─ confidence ordering
   ├─ provisional placement
   └─ final global check
```

### Starter Skill Content｜RB4.3 Local Fit vs Global Fit

**Mental model**：一句放在这里读着顺，只证明局部可行；正确 placement 还必须让后文继续成立，并让整套剩余映射可解。

**三向检查**：

```text
Backward：它接得住前面吗？
Forward：它为后面准备对了吗？
Global：放完后整篇和剩余候选还自洽吗？
```

**主动判断**：如果你说“这个句子和前面关键词很多，所以应该放这里”，必须追加：

> 那它如何解释后一句？剩余候选会因此变得更清楚还是更矛盾？

### Starter Skill Content｜RB5.2 Coupled Placement

**Mental model**：两个位置共享候选约束时，不能各自独立判断。

如果 A 放 Position 2 会迫使 B 只能去 Position 4，那么这两个判断本质上是一组联合假设：

```text
(A→P2, B→P4)
vs
(B→P2, A→P4)
```

真正要比较的是哪一整组 map 更能满足角色与全局一致性，而不是分别问“A 在 P2 顺不顺”。

# E｜第一次学习以后，Skill Map 和 Runtime 怎样接上

第一次学习完成后，不要把 Skill Map 变成新的待办清单。

正确关系是：

```text
Global Map + Core Blocks
= 你已经有一张可以做题的认知模型

真实 Attempt
= 检验这张模型能不能执行

wrong / uncertain evidence
= 暴露最早 meaningful failure

Skill Map
= 给 failure 一个稳定地址

Selective Skill Content / Chat
= 只补真正需要的局部机制

later fresh transfer
= 检验能力是否真的迁移
```

## E1｜一次题目可以涉及很多 Skill，但 repair 不必全修

例如一篇 Reading A 同时出现：

- reference；
- scope；
- evidence boundary；
- option degree shift；
- answer switch。

这不意味着你要建立五个复习对象。

Chat / Runtime 应该找：

> **哪一个最早、最小、足以解释结果的 failure？**

下游 dependent errors 只保留为 evidence。

## E2｜静态学习资产与 Chat 的边界

静态资产负责：

- 第一次必须形成的 mental model；
- 高频机制；
- 稳定边界；
- 可执行判断动作；
- 少量高价值 examples / active checks。

Chat 负责：

- 真题里两个候选都很强时的精确竞争；
- 多个机制同时作用；
- 罕见结构；
- 你的个人 error pattern；
- 针对当前 failure 的 micro-drill；
- transfer relevance / closure 判断。

## E3｜不要把第一次学习资产和 Runtime 混在一起

学习资产回答：

> **这种题到底应该怎么思考？**

Runtime 回答：

> **现在这一次 attempt 怎么记录、复盘、修复和验证？**

因此正常顺序是：

```text
First Learning
Global Map → Core Blocks → Skill Map
↓
Practice
clean Attempt
↓
Repair only when needed
↓
Transfer on fresh material
```

不是：

```text
先做大量题
→ 错了再从错题中零散拼出方法
```

也不是：

```text
先背完整技巧 taxonomy
→ 再开始做题
```

真正目标是：

> **先建立足够强的生成模型，再让真实题目不断校准它。**
