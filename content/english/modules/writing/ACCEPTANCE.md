## R — accepted runtime boundary

Formal learner unit remains one complete essay.

Accepted route:

```text
complete clean attempt
→ immutable first plan/direct-mode evidence + first draft
→ semantic review during calibration
→ PASS / ACCEPTABLE
   or
→ first meaningful failure
→ smallest repair
→ learner re-generation
→ repair check
→ REPAIR_COMPLETE
→ optional transfer admission only for reusable/high-value targets
```

Accepted invariants:

- direct mode does not manufacture an explicit plan;
- PASS creates no repair/transfer debt;
- cosmetic sophistication does not justify repair;
- repair scope may be smaller than the essay while review context remains whole-essay;
- changed repair clears stale re-generation before re-execution;
- same-prompt repair cannot masquerade as mastery;
- independent downstream failure may become another repair only after the upstream repair succeeds;
- protected true-exam tasks reuse the same Runtime rather than a second architecture.

Current protected true-exam gate uses actual terminal Runtime evidence from the current synthetic Small/Big calibration tasks. Manual First-Learning checkboxes are not qualification authority, and engineering validation does not submit a protected true-exam attempt.

## E — accepted evidence boundary

Private Evidence semantics remain:

- only an explicit reusable completed repair candidate enters the durable ledger;
- origin first draft / final diagnosis / regeneration / completed repair evidence is preserved;
- same task/prompt cannot count as transfer;
- later different first-draft evidence may SUPPORT or CLOSE;
- duplicate identical evidence is idempotent and conflicting reuse fails;
- later contradiction may REOPEN the same identity;
- IRRELEVANT evidence does not confirm/refute;
- no counter-based mastery rule;
- evidence stays browser-local/private.

Fresh FFV reconciliation also demoted the learner surface:

```text
pending target
≠ learner owes a transfer session
```

`WritingEvidencePanel` is hidden unless current completed work naturally supplies an eligible prior target. The backend ledger remains rich without creating attention debt.
