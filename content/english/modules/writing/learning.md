# Writing｜第一次学习主干

> **目标**：面对陌生题目，能独立写出一篇相关、完整、能推进、语言可控，并且按时交付的英文文本。  
> **怎么用**：先看 Global Map。会的部分直接跳；只有真实不稳的地方才往下学。  
> **Small / Big Writing**：共用同一条能力主干，只是任务形态不同。  
> **更深内容**：长例子、边界情况和细分训练保存在 `learning.reference.md`，真正卡住时再下钻。

---

# A｜Global Map：一篇作文到底是怎么长出来的

Writing 不是“背一个模板，再换几个主题词”。

真正的主干只有六步：

```text
TASK / GENRE FULFILLMENT
先弄清楚：我要完成什么任务？
↓
CONTENT GENERATION
决定：我到底要说什么？
↓
ORGANIZATION / DEVELOPMENT
安排：这些内容怎么一步步往前走？
↓
ENGLISH REALIZATION
实现：怎样用自己能控制的英语写出来？
↓
REGISTER + HIGH-VALUE ERROR CONTROL
控制：哪些地方真的会影响任务、意义和可读性？
↓
TIMED DELIVERY
交付：怎样在考试时间里写完、检查、离开？
```

把它压成一句话：

> **先知道要完成什么，再决定说什么、怎么推进、怎么用稳定英语实现，最后只检查真正会掉分的地方。**

考试时不需要逐项默念。框架越熟，显式步骤越少。

# B｜Six Core Primitives：六个真正值得学的能力块

下面不是六节必须打卡的课，而是六类不同的问题。

例子全部是 synthetic，只用于建立动作，不消耗真题新鲜度。

## B1｜Task / Genre Fulfillment｜先把题目变成“任务”

### 核心问题

> **我是谁？写给谁？为什么写？必须完成哪些动作？**

不是先问：

> “这个题用什么开头？”

### 一眼模型

```text
ROLE        我以什么身份写？
AUDIENCE    写给谁？
PURPOSE     想完成什么？
REQUIRED    必须覆盖哪些信息 / 动作？
CONSTRAINT  有什么形式、材料、语域限制？
SUCCESS     写完以后，什么才算任务真的完成？
```

### Small Writing｜任务是 communicative job

假设任务是：你是学生组织者，给国际学生写邮件，邀请他们参加校园文化活动，并说明时间、地点和参加价值。

把题目压成：

```text
身份      student organizer
对象      international students
目的      invite them to attend
必须写    活动是什么 / 时间地点 / 为什么值得参加 / 明确邀请
语域      friendly + polite
```

如果正文只写“活动很精彩、校园很美”，却没有时间和地点，语言再漂亮也没有完成任务。

### Big Writing｜任务是 interpretive job

假设材料表现：两个人拥有同样的工具，一个只收藏，一个持续使用并改进成果。

弱压缩：

```text
主题 = perseverance
```

更好的任务理解：

```text
观察      same resource, different use
关系      possession ≠ value
解释      value comes from active use
任务      说明这种关系为什么重要，并展开它的后果
```

### 真正的边界

Task reading 负责确定“必须完成什么”，不是提前把正文写成模板。

常见偏移：

- 把题型名称当成任务；
- 漏 required move；
- 写了很多相关内容，却没完成 communicative job；
- Big Writing 一看到材料就跳到一个大而空的主题词；
- 为了套模板，把题目真正要求改掉。

> **带走：写前先把题目压成任务，不要把题目翻译成模板。**

## B2｜Content Generation｜从“主题词”变成真正可写的内容

### 主题词为什么不够

`technology / cooperation / persistence / health` 只是 topic，不是 paragraph content。

真正可写的单位至少多一个关系：

```text
TOPIC
↓
CLAIM      我到底在断言什么？
↓
WHY / HOW 为什么成立、怎样发生？
↓
RESULT     会带来什么？
↓
BOUNDARY   什么情况下不成立 / 会反转？
```

不需要每次把五层全部写满，但至少要从“名词”走到“命题”。

### 同一个主题，两种写法

弱：

```text
Technology is important.
Technology changes our life.
We should use technology well.
```

看似三句，其实几乎没有新增信息。

更可展开：

```text
CLAIM      digital tools can reduce routine decision costs
HOW        they organize information and remove repetitive steps
RESULT     users can spend more attention on judgment-heavy work
BOUNDARY   the benefit falls when users trust automated outputs blindly
```

现在每一句都知道下一步可以往哪里走。

### Small Writing 不需要“思想深度”

它更在乎 **useful completeness**。

例如投诉邮件，真正有用的 atoms 可能只是：

```text
what happened
when / where it happened
why it matters
what remedy you want
how the reader can respond
```

多写两句空泛礼貌话，不如补一个真正帮助对方行动的 detail。

### 选择标准

考试容量有限，优先保留：

```text
最相关
+ 最能推进
+ 自己最能稳定表达
+ 彼此不重复
```

> **带走：不要问“还能说什么”，先问“下一句能新增什么”。**

## B3｜Organization / Development｜让文章真正往前走

### 核心问题

> **下一句到底新增了什么？**

Structure 的底层不是“三段式”，而是：

```text
PARAGRAPH ROLE
这一段负责什么？
+
INFORMATION ORDER
为什么现在说这一句？
+
INFORMATION GAIN
它比上一句多了什么？
```

### 假推进 ↔ 真推进

| 假推进：字变多了 | 真推进：信息变多了 |
| --- | --- |
| Practice is important. | Practice turns abstract knowledge into usable skill. |
| Practice is very important for everyone. | Repeated retrieval exposes unstable understanding. |
| Without practice, success is impossible. | Feedback then corrects weak or mistaken patterns. |
| Therefore, we should value practice. | Later performance becomes faster and less cue-dependent. |

左边四句都围着“practice 很重要”打转；右边则真的出现了 **mechanism → correction → result**。

### 一段话常见的有效角色

```text
提出判断
↓
解释为什么
↓
说明怎样发生
↓
给出结果 / 例子
↓
补边界 / 对照
↓
落到 implication / action
```

不是每段都全走，但每一步都应该有存在理由。

### Big Writing 的 Material → Meaning bridge

最危险的跳跃：

```text
看到材料
→ 直接喊大主题
```

真正需要的是：

```text
OBSERVATION
材料里真实出现了什么关系？
↓
INTERPRETATION
这个关系说明了什么？
↓
DEVELOPMENT
为什么重要？怎样发生？会导致什么？
```

### 一个极简单的判断线

```text
删掉下一句
↓
读者几乎没少知道东西？
├─ 是 → 大概率没有推进
└─ 否 → 它提供了真实 information gain
```

> **带走：结构的本质不是段数，而是信息增量。**

## B4｜English Realization｜把内容变成自己能控制的英语

Writing 不是 Translation 的逆过程。

目标不是先在脑里造一整句漂亮中文，再逐词搬成英文；更稳定的是：

```text
CONTENT ATOM
↓
PROPOSITION
把意思压成一个清楚断言
↓
RELATION
确定 cause / result / contrast / condition...
↓
STABLE ENGLISH
用自己能控制的结构实现
```

### 从复杂意图到稳定表达

脑中的中文可能是：

> 在信息极其丰富而且工具越来越智能的今天，人们真正缺少的并不总是更多信息，而是判断哪些信息值得相信并据此行动的能力。

先压成 propositions：

```text
information is abundant
tools are becoming smarter
the bottleneck is often judgment, not access
people must decide what to trust and act on
```

然后再实现：

> Information is increasingly easy to obtain. The harder task is often deciding what deserves trust and what should guide action.

信息保住了，句法风险却明显下降。

### Relation first

```text
cause       because / since / X leads to Y
result      therefore / as a result / X makes Y possible
contrast    while / whereas / however
condition   if / when / unless
concession  although / even if
mechanism   by doing X / through X
example     for example / one case is...
```

关系先明确，再选结构。不是为了“用从句”而用从句。

### 一旦负荷失控，就降载

```text
句子写到一半失去主谓？
→ 拆句

modifier 越挂越长？
→ 只留必要修饰

某个 construction 不确定？
→ 换稳定表达

为了高级词停住？
→ 换简单但准确的词
```

如果长期总卡在某个词义、搭配或构式，那是词汇本身需要补，不在 Writing 里再背第二套词库。

> **带走：先保证命题能稳定落地，再谈句子有多高级。**

## B5｜Register + High-Value Error Control｜只控制真正值钱的风险

### Register 不是“越正式越长”

同一个意思，关系不同，语言也应该不同。

给同学提醒活动：

> Just a reminder that the event starts at 2 p.m. on Friday. I hope you can join us.

如果写成：

> Please be informed that your esteemed presence is sincerely requested...

语法未必错，但人际距离和场景完全跑偏。

给机构正式询问：

> Could you please let me know whether registration is still open?

通常比：

> I want to know if I can still sign up.

更符合 audience relation。

### 最后检查不是“重写整篇”

优先级可以直接画成：

```text
任务有没有漏？
↓
意义 / relation 有没有写反？
↓
句子是否完整、主谓是否稳定？
↓
明显 tense / number / pronoun / article 风险？
↓
明显 collocation / word choice / spelling 错误？
↓
register 是否和 audience 冲突？
↓
纯风格润色 —— 最后才考虑
```

例如：

> Although online tools are convenient, **so** users should remain cautious.

真正的问题不是“不够高级”，而是 relation structure 冲突。

修这种错误，比把 `important` 换成 `indispensable` 更值。

> **带走：先修会让读者误解、卡住或直接失分的错误。**

## B6｜Timed Delivery｜在考试时间里交付，而不是无限润色

Writing 最终测的是：有限时间内能不能把东西写完。

### 主线

```text
BOUNDED PLANNING
只计划到足以开始写
↓
CONTINUOUS DRAFTING
优先保持输出连续
↓
RECOVER WHEN STUCK
卡住就降载，不把整篇停住
↓
HIGH-VALUE CHECK
只扫高风险点
↓
STOP WHEN SUFFICIENT
够好就离开
```

### Planning 什么时候该停

计划只需要：

```text
Task / Core Message
+ 2–4 useful atoms
+ paragraph roles
```

如果还在不断补关键词、句型和“高级表达”，但正文没有开始，planning 已经开始伤害 execution。

### 卡住时怎么恢复

```text
想不起高级词？
→ 换简单词

句子越写越长？
→ 在稳定 proposition 边界拆开

不知道下一句写什么？
→ 回到 paragraph role：下一步需要 WHY / HOW / RESULT / EXAMPLE / CONTRAST 哪一个？

时间不够？
→ 先保 required move / conclusion / complete sentence
→ 放弃低价值 ornament
```

### 交付优先级

```text
TASK / MEANING
>
COMPLETENESS
>
STABLE LANGUAGE
>
STYLE
```

### Stop line

```text
任务完成？
核心内容够？
段落有真实推进？
没有明显高风险语言错误？
register 基本合适？
文本完整？

全部大体成立
→ STOP
```

> **带走：完整稳定的成品，优先于未完成的高级版本。**

# C｜Task-Mode Specialization：Small / Big Writing 的不同形状

两种写作共用同一条主干：

```text
Task → Content → Organization → English → Control → Delivery
```

不同的是，它们最容易失手的地方不一样。

## C1｜Small Writing｜先完成沟通动作

核心是 **communicative completeness**：

```text
AUDIENCE
写给谁
↓
PURPOSE
为什么写
↓
REQUIRED MOVES
必须完成哪些动作
↓
USEFUL DETAILS
对方真正需要什么信息
↓
REGISTER
关系多直接 / 多正式
↓
NEXT STEP / CLOSE
让沟通自然结束
```

request / recommend / invite / inform / apologize / thank / inquire / report problem 只是表面 function。

长期稳定的问题只有三个：

> 这个读者需要什么？我要完成什么动作？我该用多直接的语气？

### Mini walkthrough

任务：向课程负责人申请延期，并解释原因、提出新的提交时间。

```text
purpose        request a short extension
reason         concise + relevant + credible
proposal       specific new deadline
close          appreciation + willingness to comply
```

这已经足够开始写，不需要先背一整封“申请信模板”。

## C2｜Big Writing｜从材料关系走到可展开判断

核心链：

```text
OBSERVE / READ
↓
INTERPRET
↓
CORE MESSAGE
↓
GENERATE
↓
DEVELOP
↓
REALIZE
```

材料：一个团队拥有很多数据，却因为成员各自保存、互不共享而反复做同样工作。

弱 Core Message：

> Cooperation is important.

更可展开：

> Resources create value only when a group can coordinate their use; isolated possession can increase duplication rather than efficiency.

它更强，不是因为“高级”，而是因为保留了材料里的 **resource + coordination + duplication** 关系。

后面自然可以继续：

```text
why coordination matters
→ how isolation creates duplication
→ what this costs
→ what a better practice looks like
```

> **Big Writing 的主题不是你想出来的词，而是材料关系允许你建立的判断。**

# E｜Synthetic Practice：只练真正的动作

Synthetic Practice 的价值，是在不消耗 fresh true-exam 的情况下，把某个动作先练会。

按问题选练法：

| 你不稳的地方 | 最小练法 |
| --- | --- |
| 题目总拆不准 | **Task Brief**：30–60 秒压 audience / purpose / required moves |
| 内容太空 | **Atom upgrade**：topic → claim + HOW / RESULT |
| 段落绕圈 | **Information gain**：判断下一句是否真的新增信息 |
| 大作文拔高 | **Observation vs Interpretation**：先事实，再允许的含义 |
| Core Message 太空 | **Core-message competition**：比较哪个最 grounded + developable |
| 英文落不下来 | **Proposition → English**：先压命题，再写稳定版本 |
| 语域不稳 | **Register shift**：同一请求分别写给同学 / 教师 / 机构 |
| 长句失控 | **Recovery drill**：拆句但不丢 proposition |
| 需要整合 | **完整 synthetic Small / Big** |

完整 Writing Attempt 仍然是一篇完整作文，不把 Writing 变成几百道 micro-drill。

Cold start 时，通常值得先各做一篇 synthetic Small / Big；目的是确认你能独立从 prompt 走到成文，不是完成某个打卡仪式。

# F｜更深内容什么时候再看

`learning.reference.md` 保存更长的 examples、Small / Big function detail、starter skills、edge cases 和更多 synthetic drills。

主文没有把它们删掉，只是不要求第一次学习全部背负。

什么时候值得下钻：

```text
真实作文连续暴露同类问题
或
当前主干解释不了一个高价值失败
或
需要更细的 contrast / edge case 才能分清
```

什么时候不用：

```text
只是想“学得更完整”
只是和参考范文措辞不同
只是为了增加高级表达数量
```

Model essay 也一样：先有自己的 first draft，再拿来比较 task completeness、development、natural realization 和少量可复用表达。

模板只保留薄 skeleton；不要让模板接管生成。

# G｜HOW YOU LEARN IT：主线永远回到真实写作

第一次进入 Writing：

```text
Global Map
→ 快扫六个能力
→ 会的直接跳
→ 不稳的看对应模型 / 例子
→ 必要时做 synthetic probe
→ real Writing
```

之后：

```text
完整作文
→ 快速判断：够不够好？
├─ 够 → 离开，做下一篇
└─ 不够 → 找最有价值的问题
          → 修最小范围
          → 自己重新生成
          → 回到真实写作
```

稳定、合格的作文不欠“为了完整而完整”的修改。

同题改好说明 repair 有效，但不等于已经 mastery；真正更强的证据来自以后独立题目里的稳定表现。

# H｜内部边界：第一次学习可以跳过

下面开始不再是“该学什么”，而是系统怎样保护真实学习证据。

这部分保留，是为了防止以后页面和运行逻辑把 Writing 重新做成打卡课；正常第一次学习可以直接跳到结尾。

核心边界只有几条：

- 正式 attempt / review unit = **一篇完整作文**；
- first meaningful plan + first draft 要保留，后改不能覆盖第一次证据；
- PASS 是真实出口，不制造无意义修改；
- 深诊断先看整篇，再缩到最小独立问题；
- repair 的目标是自己重新生成，不是让 Chat 代写；
- same-prompt rewrite = repair evidence，不是 mastery；
- 长期词汇知识回 LexicalOS；
- 没有当前价值的后台状态不应该抢注意力。

---

# I｜True-Exam Entry：保护 fresh material，不制造 ceremony

Fresh true-exam 是有限的 diagnostic capital。

Cold start 推荐进入真题前至少证明一次：

- **Small Writing**：能自己拆 audience / purpose / required moves，生成 useful detail，并完成一篇 synthetic；
- **Big Writing**：能从 material 形成 grounded Core Message，产生真实 information gain，并完成一篇 synthetic。

真正的判断不是“Guide 是否读完”，而是：

> **没有 model / template takeover 时，我能不能从完整 synthetic prompt 独立生成一篇基本完整文本？**

会，就可以进入真题；不会，就回到最早失效的能力块。

不要为了系统测试消耗 protected unseen true-exam。

# J｜Writing Runtime v2：内部运行语义，学习时可跳过

**Parent authority:** `content/english/LEARNING_CONTRACT.md`

## J1｜完整作文是正式上下文

一篇完整作文是 learner-facing attempt / review unit；内部 evidence 可以更细到 requirement、paragraph、sentence、lexical span、revision 或 timing event。

> Evidence granularity can be smaller than review granularity.

## J2｜状态只服务于真实学习

```text
ATTEMPT
↓
PASS / ACCEPTABLE
or
MEANINGFUL REPAIR
  ↓
smallest useful repair
  ↓
learner re-generation
  ↓
REPAIR_COMPLETE
```

只有 reusable / recurring / high-cost / still-unstable target 才值得形成后续观察。

`TRANSFER_PENDING` 如果存在，只是后台 observation state：

```text
pending target ≠ learner owes an action
```

## J3｜因果优先，不把一个问题拆成很多债务

如果 Task failure 已经解释了后面的 Content / Structure 问题，就先修 Task。

修完以后仍然独立存在的高价值 downstream failure，才值得单独保留。

两个真正独立的问题可以有两个 repair，不为了形式统一强行合并。

## J4｜重新生成必须来自 learner

Repair 之后，learner 重新生成受影响 scope。

Model essay / reference 可以帮助比较，但不能覆盖 first draft，也不能替 learner 完成修复。

## J5｜Evidence hierarchy 不是 scheduler

```text
看懂 feedback
< same-prompt learner regeneration
< later independent success
< fresh prompt success on same demand
< repeated stable timed performance
```

证据越强，不代表系统必须主动安排一轮新测试。

## J6｜Resume

Resume 只把 learner 带回真正没完成的高价值动作：unfinished attempt / active repair / regeneration。

Passed work、Guide position、dormant pending claims 不应该把 learner 拖回去。

---

# 最后压缩｜Writing 只带走这六件事

```text
1. 先把题目变成任务。
2. 从主题词生成真正可写的命题。
3. 让每一段、每一句都产生信息增量。
4. 先压 proposition，再用稳定英语实现。
5. 只控制真正影响任务、意义和可读性的风险。
6. 在考试时间里完整交付，然后离开。
```

如果这六件事已经能稳定做到，就不要继续“学 Writing 框架”。

去写。
