## CBA spine

English is not “a folder of task files”; it is an exam-learning product family with task-native subproducts.

```text
NEED / OUTCOME
→ English exam capability and score need
→ LEARNING_CONTRACT.md
→ exact task/module owner

CREATE
→ exact Source / Content / task Learning owner
→ static-web/ENGLISH_PRODUCT_BRIEF.md
→ exact task/surface design when one exists
→ accepted meaning / product behavior / visual intent

BUILD
→ CURRENT.md
→ exact module CURRENT when applicable
→ actual Projection / Runtime / Website consumer
→ local/native proof
→ Candidate Human Gate for material learner-facing UI

AUDIT
→ ACCEPTANCE.md
→ exact module Acceptance
→ independent reality attack only for the claim that actually needs it
→ unchanged accepted Source / Knowledge / Learning evidence is reused

REAL USE
→ actual English learner/runtime Resume, attempts and private evidence
→ genuine learner feedback may reopen only the earliest responsible owner
```

Rules:
- CREATE decides what Reading / Cloze / Part B / Translation / Writing / Vocabulary should do; BUILD does not invent task meaning from current code.
- A module may have its own Learning/Product details without creating a second English-wide architecture.
- Vocabulary's learner-facing product lives under English; canonical lexical semantic truth remains under `content/lexical/`.
- closed audit artifacts and old implementation history are not part of the normal CBA recovery path.

## Zones

### Core owners

- LEARNING_CONTRACT.md — English-wide learning Rule / Model.
- manifest.json — Current English content/source map.
- provenance.json — provenance support.

### Modules

- modules/objective/ — Reading A / Cloze / Part B.
- modules/translation/ — Translation.
- modules/writing/ — Writing.

Each independently continued module keeps its own CURRENT / ACCEPTANCE where applicable.

### External Reading

- external/ — External Reading content/runtime boundary and its Current routing.
- source/ — admitted English source assets.

### Acceptance / evidence

- ACCEPTANCE.md — English-wide acceptance claim.
- CURRENT.md — engineering cursor + router.
- Closed audit construction artifacts live in Git history unless a current Acceptance/diagnostic owner explicitly requires retained cold evidence on main.

### Lexical boundary

Learner-facing Vocabulary belongs under English, while canonical lexical backend truth lives in sibling content/lexical/.

## Placement rule

Task semantics stay in the exact module owner. Do not duplicate Reading / Translation / Writing / Lexical meaning into a shared English summary merely for convenience.

Historical audit artifacts stay off the normal read path unless CURRENT.md or an exact Acceptance owner routes to them.

## Compact rule

**English is one product family with task-native modules; each task keeps its own cognition while shared routing stays thin.**
