## Inherited root quality / acceptance

Skills inherit the repository-wide causal construction and acceptance system from `LEARNING_ASSET_STANDARD.md` and `LEARNING_ACCEPTANCE.md`. Do not create a second Skill-specific acceptance framework. New/materially changed learner Content must close its bounded AI self-attack before learner release; real learner use remains U evidence and may reopen the earliest responsible owner.

## Boundary

- Run the bounded Ecosystem Scan only when reuse could materially change learner design or maintenance.
- Do not make every Personal interest a Skill.
- Do not build one Astro implementation per Skill.
- New Skill content should normally require no Visual/Runtime code changes.
- Source Review is content quality evidence, not learner evidence.
- File existence is not learning completion.
- Incomplete books stay out of the public `content/skills/manifest.json`; content may be prepared ahead of learner demand without creating learner debt.
- Website owns Framework / Unit reading / stable reference / reading resume. Chat owns deeper cognition and adaptation.
- Build mature Skills one by one. The first bounded cross-Skill pass now lives in `CORE_INTERFACES.md`; extend it only when more mature books expose genuinely reusable structure. Do not prebuild a giant ontology.
- Health/medical Skills must preserve professional-evaluation boundaries and must not become diagnosis products.
