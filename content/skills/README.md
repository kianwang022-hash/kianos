Role: **static orientation for content/skills/**. Live engineering routing is owned by CURRENT.md. This README owns no Skill semantic truth, Personal capability demand, Acceptance status or learner state.

## Zones

### Shared Skill rules

- LEARNING_CONTRACT.md — shared cognition / learning rule for promoted non-exam Skills.
- UNIT_CONTRACT.md — minimum design contract for one material Skill Unit.
- CORE_INTERFACES.md — bounded cross-Skill ownership/handoff map.
- ECOSYSTEM_SCAN.md — conditional reuse/ecosystem scan when explicitly needed.
- manifest.json — registered Skill inventory / portfolio state.

### Skill domains

Each directory such as decision-quality/, information-research/, adaptive-learning/, health-physical/, business-product/ etc. owns only its exact promoted capability assets and manifest-defined state.

A Personal interest or research topic does not automatically become a Skill.

### Product / Runtime boundary

Generic learner-facing Skills presentation/runtime belongs to the exact static-web Skills consumer. Skill Content stays under content/skills/ and should normally reuse the shared reader/runtime unless the cognition genuinely requires a different product surface.

### Acceptance / learner evidence

Skills inherit root LEARNING_ASSET_STANDARD.md and LEARNING_ACCEPTANCE.md. File existence, reading history or page completion never manufactures learner capability.

## Placement rule

New promoted capability work should reuse the existing Skill/Unit structure. Do not create a new learning framework, acceptance ladder, global Skill ontology or custom Runtime merely because a new topic exists.

Raw/reference material may remain outside KianOS until promotion/internalization is justified.

## Compact rule

**Personal owns why the capability matters; Skill Library owns the promoted learner asset; exact Skill owners hold meaning; shared standards own construction and acceptance.**
