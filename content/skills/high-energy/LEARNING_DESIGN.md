# High Energy Learning Design

Status: CURRENT INTERNAL LEARNING OWNER  
Role: U1–U5 的学习设计与 Chat Evidence 判定边界。

## Core rule

采用 **PERFORMANCE_FIRST / ACTION_FIRST / REAL_USE_CALIBRATION**。

~~~text
识别有意义的掉状态
→ 选高收益动作
→ 用足够剂量
→ 回真实任务
→ 必要时升级 / 降档
→ 长期提高容量与任务效率
~~~

正式 Reconstruct / Verify / Transfer 仍用于真正需要独立验证时；已经在真实讨论 / 使用中清楚展示出的能力，不因为缺少仪式化答题就重新从头考。

## U1｜掉状态判断
- Target：判断 local vs combined vs system-level drop；只有会改变动作时才进一步区分原因。
- PASS：不会强行单标签；抓住最决定动作的信号，并知道什么时候判断已经够了。
- Repair：过度分类；把主观抗拒当容量不足；忽略综合掉状态；忽略医疗边界。
- Compression：局部 / 综合 / 系统性 + “只区分会改变动作的因素”。

## U2｜高效恢复
- Target：选择高收益动作与最小充分恢复剂量，并在失败时及时升级。
- PASS：动作匹配主要限制；不会无限重复小休；回原任务验收；能区分恢复和临时刺激。
- Repair：动作不匹配；恢复剂量不足；只看舒服；忽略后续代价。
- Compression：动作族 + 起始剂量 + 升级规则 + re-entry。

## U3｜日内精力配置
- Target：把任务认知需求和真实容量窗口匹配，并在现实变化后动态重排。
- PASS：保护高价值高认知工作；不会用固定钟点代替真实容量。
- Compression：任务需求 × 当前容量 × 时段模式 × 后续代价。

## U4｜周尺度负荷 / 恢复
- Target：识别反复救火、drop latency 提前、recovery latency 变慢和多日失配。
- PASS：判断局部波动还是趋势；优先修最大失配，不制造 readiness score。
- Compression：drop latency / recovery latency / rescue frequency + 最大失配。

## U5｜容量增长
- Target：识别最值得提高的容量杠杆，并用真实表现判断是否变强。
- 四类容量：physiological capacity / cognitive tolerance / regulation capacity / task efficiency。
- PASS：不会把硬撑当认知训练；一次只增加一个负荷维度；知道熟练会降低任务认知成本；不把实验性 BET 当默认方案。
- Compression：四类容量 + 一个瓶颈 + 一个可验证增长动作。

## Chat adjudication

1. 真实使用中的清晰 demonstration 可以作为能力证据；不要为了流程重新考试。
2. 只有错误原因会改变修法时才诊断。
3. Repair 只修最小失败对象。
4. 口语化 / 简短不是失败。
5. 不用健康推断替代证据。
6. 医疗边界只判断是否退出自我优化，不诊断疾病。
7. 学习流程开始妨碍真实使用时，优先降低流程摩擦。
