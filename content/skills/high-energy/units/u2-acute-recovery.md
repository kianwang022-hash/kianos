# U2｜瞬时恢复：现在第一步该做什么？

U1 解决“最可能是什么问题”。U2 解决：

> **在当前最可能解释下，哪个动作最值得先试？**

目标不是收集恢复技巧，而是把动作选择变成一个低成本、可逆、可验证的决策。

---

## 1｜动作选择的四条规则

| 规则 | 含义 |
| --- | --- |
| **Match** | 动作要匹配最可能的限制因素 |
| **Smallest** | 先做最小足够动作，不一上来重置半天 |
| **Reversible** | 优先低风险、可撤回、不会制造新负担的动作 |
| **Re-entry** | 动作后必须回真实任务验证；舒服 ≠ 恢复 |

最差的策略通常不是“选错一个动作”，而是：

> **不判断原因 → 随机休息 / 刺激 → 感觉稍好 → 继续硬顶 → 下一次更难判断。**

---

## 2｜状态 × 第一动作矩阵

| Leading hypothesis | 第一优先动作 | 为什么 | 不要先做什么 |
| --- | --- | --- | --- |
| **真实困倦 / 睡眠不足** | 有条件时优先创造真实睡眠机会；不能睡时降低高风险/高认知要求 | 睡眠和警觉问题不能被“意志力”彻底替代 | 把咖啡当作已经恢复 |
| **认知饱和** | 停止继续叠加同一高认知输入；可试短休息、换低认知负荷或短暂走动 | 需要减少持续高认知输入，让系统从同一负荷脱开 | 刷短视频、继续高刺激输入 |
| **注意碎片化** | 移除通知/手机/多窗口，只保留一个任务入口 | 容量可能没坏，控制权被竞争 | 额外休息但继续保留刺激源 |
| **启动阻力 / 低唤醒** | 直接做一个极短真实起步块，必要时先短暂活动 | 最有信息量的是“开始后功能会不会回来” | 因为“不想做”就判定需要长休息 |
| **压力 / 过度唤醒** | 降低输入、把担忧/下一步外化、缩小当前任务、短暂脱离高压 cue | 目标是把资源从结果模拟拉回当前任务 | 用更强刺激继续顶高唤醒 |
| **身体 / 环境限制** | 直接修正最具体变量：姿势、活动、饥饿、口渴、温度、噪声、疼痛 | 直接原因优先于抽象解释 | 把一切归为“心理状态差” |

这张表不是处方。它只是一个**第一动作路由器**。

## 3｜工具不是按“好不好”分类，而是按功能分类

| Tool family | 真正作用 | 适合什么时候 | 主要边界 |
| --- | --- | --- | --- |
| **Sleep / nap** | 真实睡眠机会 | 明显 sleepiness、睡眠不足背景 | 可能有睡眠惯性；不定义统一时长 |
| **低输入休息** | 停止继续给同一认知系统加输入 | 认知疲劳 / 高负荷后下降 | 主观舒服不等于性能恢复 |
| **走动 / 活动** | 提高唤醒、打断久坐、改变身体状态 | 低唤醒、久坐、轻度 认知疲劳 | 平均收益小；不是万能恢复 |
| **注意力重置** | 减少竞争刺激 | 注意碎片化 | 不需要额外制造“休息仪式” |
| **降负荷 / 换任务类型** | 临时降低任务认知需求 | 高认知容量下降但仍需继续一天 | 不能长期把核心任务全推迟 |
| **咖啡因** | 提高警觉性 | 明确需要短期 alertness 且后续睡眠成本可接受 | 是刺激，不是恢复；剂量/时间影响睡眠 |
| **环境 / 基础供给修正** | 修正直接身体/环境变量 | 饿、渴、闷、噪、姿势不适 | 避免把普通变量神秘化 |

## 4｜三个最容易被误用的恢复工具

### A｜休息

短休息对主观疲劳和活力有小幅、相对稳定的改善，但高认知表现并不保证同步回来。现有证据也不足以证明某一种 break 内容对所有高认知任务都最优；这里把休息当作一个可逆 probe，而不是固定处方。

所以：

> **休息完成 ≠ 恢复完成。**

真正的结束条件是 回到真实任务验证。

### B｜运动 / 走动

单次活动对认知平均有小幅收益，也能改变低唤醒和久坐状态。

但如果最可能的问题是真实困倦：

> **运动最多暂时改变唤醒，不等于补回睡眠。**

### C｜咖啡因

咖啡因是最典型的“表现工具 ≠ 恢复工具”。

判断它是否值得，不只看现在一小时，还要看：

- 当前提高警觉性的收益有多重要；
- 距离计划睡眠还有多久；
- 剂量是否可能影响后续睡眠；
- 是否正在形成“睡少 → 咖啡 → 更难睡”的循环。

不使用一个固定 clock cutoff 代替个人 calibration。

## 5｜Re-entry：恢复动作真正的测试

动作后回到**原本重要的真实任务**，观察：

| 维度 | 看什么 |
| --- | --- |
| **启动** | 能不能自然进入，而不是继续拖延 |
| **持续** | 能不能维持一个完整工作块 |
| **加工** | 重读、卡顿、推理断裂有没有下降 |
| **准确** | 错误/犹豫是否回到平时水平 |
| **主观成本** | 同样任务是否仍异常费力 |

结果有三类：

```text
明显回来
→ 第一判断暂时得到支持

感觉好一点但性能没回来
→ 不算恢复；重新判断

完全没回来 / 更差
→ 最初判断或动作匹配可能错误
```

## 6｜动作选择最常见的失败

| Failure | 实质 |
| --- | --- |
| 一累就刷刺激 | 用高输入伪装恢复 |
| 一抗拒就休息 | 把 motivation 当 capacity |
| 一困就运动/咖啡硬顶 | 用 alertness 覆盖 sleep need |
| 一疲劳就换科目无限延后 | 把 load switch 变成逃避 |
| 做完恢复动作不回原任务 | 没有 回到真实任务验证，就没有信息 |
| 同一动作反复无效仍继续 | 没有更新 hypothesis |

---

## 7｜U2 的停止线

U2 不要求你背 20 种恢复法。

只要求你能完成：

```text
当前最可能限制因素
→ 选一个最匹配的低成本动作
→ 明确它不解决什么
→ 回真实任务验证
→ 根据结果更新判断
```

如果动作选择开始服从状态，而不是服从习惯，U2 就开始形成能力。
