# High Energy Operating Model｜总压缩候选

这不是 U1–U5 的目录，而是以后真正调用的总模型。

~~~text
状态下降
→ 先问：现在怎样最快恢复真实可用功能？

第一层：停止继续制造无谓负荷
→ 降低当前认知 / 精神 / 身体负荷
→ 去掉明显干扰与恢复破坏因素

第二层：补回容量
→ 睡眠 / 低输入休息 / 活动 / 基础供给
→ 只选当前最可能有效、代价最低的动作

第三层：回真实任务验证
→ 功能回来：结束恢复，继续任务
→ 只舒服但功能没回来：不算恢复
→ 没回来：降档 / 换动作 / 扩大时间尺度
~~~

## 最小负荷地图

只有当不同解释会改变动作时才继续区分：

~~~text
综合负荷
├─ 恢复债：缺觉 / 节律 / 连续恢复不足
├─ 认知负荷：高强度思考 / 长时间专注 / 切换
├─ 精神负荷：压力 / 担忧 / 持续紧绷
└─ 身体负荷：训练 / 体力 / 久坐不适 / 身体状态
~~~

环境、通知、咖啡因、饮食、补水等都是影响负荷或容量的变量，不单独占顶层。

## 恢复效率

恢复动作不是按“健康不健康”排序，而按：

~~~text
真实功能恢复量
÷
时间成本 + 后续代价
~~~

目标不是恢复得最舒服，而是：

> **用最小必要恢复，让真实功能重新可用。**

## 时间尺度升级

~~~text
一次掉状态
→ 先做最小恢复

同一天反复掉
→ 调整任务负荷与日内配置

连续几天都掉
→ 看累积负荷与恢复是否失配

长期反复救火
→ 提高 baseline / 容量，减少恢复债

持续异常、影响生活、普通恢复解释不了
→ 停止生产力优化，进入医疗评估边界
~~~

## 整项 Skill 的证据循环

~~~text
状态下降
→ 恢复动作
→ 回真实任务
→ 看真实功能变化
→ 更新个人恢复策略
~~~

最终目标不是记住疲劳分类，而是越来越快地知道：**现在该减什么负荷、补什么容量，以及什么时候已经恢复够了。**
