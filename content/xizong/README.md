## Zones

### Learning / learner model

- LEARNING_CONTRACT.md — durable Xizong learning logic.
- LEARNER_OBJECT_CONTRACT.md — shared learner-object boundary.
- EXTENSION_ASSET_CONTRACT.md — optional additive support asset boundary.

### Program / routing

- CURRENT.md — engineering cursor + narrow router.
- CONTENT_MAINLINE.md — cross-lane content coordination only.

### Canonical content / source-derived assets

- knowledge/ — System / Block / learner knowledge owners.
- questions/ — official Question Truth.
- explanations/ — learner-facing reviewed question explanations.
- question-relations/ — reviewed Question → Knowledge relations.
- source-snapshots/ — bounded source snapshots/provenance support.
- humanities/ — clinical-humanities content lane.

### Projection / product input

- projection/ — derived Xizong projections; never a second medical owner.

### Acceptance / maturity

- ACCEPTANCE.md — Xizong-wide claim-scoped acceptance router.
- MATURITY_PACKAGE.md — subject-maturity package; not a work cursor.

## Placement rule

New Xizong work should enter the narrowest existing zone. Do not add a new top-level Contract, Current, ledger or status file when an existing owner can hold the meaning.

Historical PRs, migration notes and closed audit campaigns are evidence only unless CURRENT.md or an exact owner explicitly routes to them.

## Compact rule

**Medical truth lives with exact content owners; Current routes work; Projection derives; Runtime consumes; Acceptance proves only the named claim.**
