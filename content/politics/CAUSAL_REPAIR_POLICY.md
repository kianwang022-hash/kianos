# Politics Causal Repair / Discrimination Policy

Status: **FREEZE-CANDIDATE SYSTEM POLICY**

Role:

> Turn Wrong / Uncertain / weak Recall / weak Analysis output into the smallest justified Repair without confusing an observation with its cause.

This policy is a Chat decision aid and evidence contract. It is **not** a second scheduler, mastery score, review calendar or learner ledger.

## 1. Observation is not diagnosis

Observed signals may include:

- Objective WRONG;
- Objective UNCERTAIN;
- repeated option-boundary errors;
- FORGOT / FUZZY Recall;
- Analysis BROKEN / PARTIAL dimension;
- slow or incomplete timed output;
- learner-reported confusion;
- source ambiguity;
- transport/execution failure.

None of these alone names the cause.

Plausible cause families include:

1. relation / model missing;
2. exact retrieval instability;
3. actor / scope / chronology / condition boundary confusion;
4. multiple-choice proposition-control failure;
5. prompt / task-form misunderstanding;
6. material-binding failure;
7. timing / fatigue;
8. source ambiguity or source corruption;
9. contaminated familiarity / exposure;
10. execution / transport artifact.

## 2. Smallest discriminating check

If two plausible causes imply materially different Repairs, Chat should first choose the cheapest check that can separate them.

Examples:

| Observation | Competing causes | Smallest useful discriminator |
| --- | --- | --- |
| one multiple-choice miss | knowledge gap vs option-boundary slip | ask which option proposition failed and why |
| repeated exact wording miss | concept missing vs retrieval-only | explain relation in own words before exact recall |
| Analysis names right topic but scores weak | skeleton gap vs material-binding gap | request skeleton and material links separately |
| apparent timed collapse | knowledge failure vs execution cost | compare untimed structure with timed completion |
| strange isolated error | cognition vs bad source/key | verify source/answer-key identity before Repair |
| strong same-item correction | real transfer vs familiarity | changed-context material with distinct identity |

When the same cheap, reversible action fits all plausible causes, explicit discrimination may be skipped.

## 3. Repair routing

### Relation / model missing
Use:
- Chengfeng / canonical Current source;
- smallest relation reconstruction;
- then changed wording / changed-context verification.

Do not reopen a whole Natural Unit from one isolated symptom unless the discriminator supports a relation-level gap.

### Exact retrieval instability
Use:
- source-grounded selective Memory / Precision;
- delayed retrieval;
- later task use.

Do not convert every exact-looking item into permanent Memory debt.

### Option-boundary failure
Use:
- decisive proposition / actor / scope / condition;
- compare the minimum contrast that caused the miss;
- changed-context verification.

Do not replay a full question bank for one boundary mechanism.

### Task-form / prompt interpretation
Use:
- IDENTIFY / segmentation;
- smallest cue-to-owner exercise.

Do not answer with a full essay merely to diagnose the prompt.

### Analysis skeleton failure
Use:
- 3–5 answer moves only;
- no full prose unless delivery itself is the tested problem.

### Analysis material-binding failure
Use:
- correct principle/skeleton + a new material;
- require explicit cue-to-move binding.

A correct memorized template with generic material use does not close the Repair.

### Timing / fatigue
Use:
- phase-appropriate timed replay on a fresh task or authentic modality;
- preserve the distinction between knowledge quality and execution degradation.

Do not reopen stable content solely because timing failed.

### Source ambiguity / corruption
Use:
- primary-source or strongest authoritative corroboration;
- block affected learner truth while unresolved.

Do not Repair the learner against a possibly wrong key.

### Exposure / contamination
Use:
- classify evidence as exposed/repair/unknown;
- select a distinct exact material identity and, when FRESH is claimed, an unseen material family.

Do not count same-prompt correction as Transfer.

### Transport / runtime artifact
Use:
- preserve learner observation;
- repair transport separately;
- do not manufacture cognitive debt from a failed import, timer, checkpoint or stale plan.

## 4. Compression

Multiple symptoms may compress into one Repair only when shared cause is supported.

Valid compression example:

~~~text
several multiple-choice misses
→ same actor/scope distinction repeatedly fails
→ one boundary Repair cluster
~~~

Invalid compression:

~~~text
several misses on one topic
→ assume one knowledge gap
~~~

when the misses could instead be timing, wording, source ambiguity or different option mechanisms.

## 5. Evidence after Repair

Repair completion is not stability.

Evidence ladder:

~~~text
observation
→ discriminator when needed
→ Repair
→ changed-context / delayed / fresh verification
→ only then Maintain / Stable when representative evidence supports it
~~~

Rules:

- same-item improvement proves Repair understanding at most;
- fresh transfer requires valid exposure/material identity;
- important exact retrieval needs delayed evidence;
- final execution claims require timed/authentic modality when phase-relevant;
- untested dimensions remain UNKNOWN.

## 6. False-Secure / false-Unstable protection

Reject false Secure when:

- the root cause was never distinguished and materially different Repairs were plausible;
- only the repaired item improved;
- exposure/identity makes the verification contaminated;
- a required current-year source is missing;
- Analysis material binding or timed delivery remains materially UNKNOWN.

Reject false Unstable when:

- newer representative evidence is stable;
- the only remaining symptom is stale/duplicate evidence;
- a source/runtime artifact explains the failure;
- heavy Build would add no new decision value.

## 7. Interaction with Forecast and Chat

Repair evidence may update:

- open Review pressure;
- expected repair-cluster compression;
- single/multiple asymmetry;
- Memory burden;
- capability risk.

It must not automatically create:

- a next action;
- a priority score;
- a fixed due date;
- a permanent daily quota.

Chat remains the strategy owner. Cross-subject opportunity cost remains owned by the Exam Orchestrator boundary.

## 8. Reopen / stop rule

Reopen deeper scope only when:

- the smallest discriminator points to a deeper cause;
- repeated changed-context evidence contradicts the current model;
- a source revision invalidates the prior Repair basis;
- a Protect-70-critical mechanism remains unstable.

Stop the Repair when:

- the causal question relevant to action is resolved;
- the smallest responsible intervention is complete;
- appropriate verification is stable enough for the current phase;
- further diagnosis would not change the learning decision.

Real learner evidence may revise this policy's practical thresholds, but not the distinction:

> **observation != cause != Repair != stable capability**
