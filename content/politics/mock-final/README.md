# Politics Mock / Final

Status: **READY STRUCTURE — current-year paper/final-source content remains source-gated**

Role: define how Politics transitions from ordinary later-stage learning into realistic exam execution and last-mile compression.

This is a **Learning / GitHub asset lane**, not a required Website product.

---

## 1 | Core model

```text
Consolidation
= repair knowledge / discrimination / precision gaps

Analysis Output
= train material → principle → skeleton → selective full delivery

Mock
= test the whole Politics capability under exam-like constraints

Final
= compress only high-value admitted knowledge + real weak points
```

Hard rule:

> **Mock detects problems; it does not become a new teaching course. Final compresses debt; it does not replay the whole curriculum.**

---

## 2 | Surface ownership

Politics Mock does not require a dedicated Website.

Primary execution may be:

- an authentic / exam-like paper or PDF;
- an approved question source;
- paper-and-pen or another surface that preserves realistic timing and answer delivery.

Chat owns:

- whether a full Mock is worth the time now;
- what evidence from the Mock matters;
- diagnosis of the first meaningful failure;
- routing each failure back to its correct owner;
- deciding what enters the final high-value queue.

Website may later assist with timing, answer capture or evidence transport if that materially lowers friction, but no Mock Website is required for L closure.

---

## 3 | Mock purpose

A full Mock earns its time only when it can reveal something that ordinary practice cannot answer reliably.

Mock should test at least four execution questions:

1. **Objective reliability**  
   Can current Knowledge / discrimination / Precision produce stable objective decisions under normal exam pressure?

2. **Analysis transfer**  
   Can the learner identify what a material is testing, retrieve the right skeleton/formulation and complete an answer under time pressure?

3. **Pacing / switching**  
   Can the learner allocate time, switch between objective and analysis tasks and avoid one problem consuming the whole paper?

4. **Completion / delivery**  
   Can the learner finish the required paper with usable answer quality rather than knowing the content but failing to deliver it?

Mock is not mainly for discovering one more isolated fact.

---

## 4 | Mock entry rule

Do not schedule a full Mock merely because the calendar says “Mock phase”.

Use a full Mock when at least one of these is true:

- whole-paper timing / switching is still uncalibrated;
- a previous Mock exposed a meaningful execution weakness that needs fresh verification;
- current-year analysis-output material is mature enough that a realistic full-paper attempt can change study allocation;
- the learner needs a current estimate of completion reliability under exam-like conditions.

Earlier or narrower timed sets are allowed when the real question is local, for example:

- objective section pacing;
- one analysis-question family under time pressure;
- a small mixed set to test switching.

Do not spend a full-paper block to answer a question that a smaller timed task can answer.

---

## 5 | Clean first attempt

Mock evidence is useful only if the first attempt is preserved.

Default:

```text
fresh / exam-like paper
→ one clean timed attempt
→ no mid-paper semantic coaching
→ preserve first responses + timing
→ then review
```

Do not pause the Mock to repair every wrong/uncertain item as it appears.

If the source itself is already heavily exposed, it may still be useful for execution rehearsal but must not be treated as fresh performance evidence.

---

## 6 | Mock diagnosis

After the Mock, classify the **first meaningful failure**, not every downstream symptom.

Use the smallest responsible lane:

### Objective failure

```text
knowledge / boundary / hat / identity gap
→ Consolidation / Precision owner

question discrimination problem
→ targeted question review / smallest K repair

time-only decision failure
→ pacing / execution repair
```

### Analysis failure

```text
cannot identify what material tests
→ Analysis Output IDENTIFY

knows topic but cannot produce structure
→ SKELETON

structure exists but exact formulation is missing
→ source-grounded EXACT

knows content but cannot complete under time
→ DELIVER / timed execution
```

### Whole-paper failure

```text
bad time allocation / switching / unfinished paper
→ Mock execution repair
```

Do not create a new generic “Mock weakness” object when the failure is already explained by an upstream Knowledge / Consolidation / Analysis Output owner.

---

## 7 | Repair rule

After Mock:

```text
Mock evidence
→ Chat diagnosis
→ smallest responsible owner
→ repair
→ return to ordinary learning
```

The normal path is **not**:

```text
Mock 1
→ review every question deeply
→ Mock 1 again
→ memorize the paper
```

Same-paper correction proves repair understanding at most. It does not prove future exam transfer.

When a repair claim matters, fresh later material is stronger evidence.

---

## 8 | Mock frequency principle

More full Mocks are not automatically better.

A Mock is high-cost and should be used when its result can change:

- study allocation;
- pacing strategy;
- confidence in whole-paper completion;
- a real repair decision.

Stable execution does not owe another full Mock merely to accumulate a count.

---

## 9 | Final compression

Final review begins from a **small admitted queue**, not from the whole Politics Content tree.

Eligible inputs:

```text
admitted high-value Precision / Memory
+ current-year exact overlays
+ high-frequency Analysis Output skeletons
+ repeated / still-relevant Wrong / Uncertain
+ Mock-exposed real weaknesses
+ critical source refreshes
```

Default exclusions:

- already-stable chapter content with no current evidence of fragility;
- candidate-only Memory that never passed admission/freshness;
- historical answer wording that lacks current-year support;
- rich explanation/reference content that is reconstructable and not worth exact retention;
- complete Xiao1000 / full chapter replay by default.

Hard rule:

> **Final compression is a queue of things worth carrying into the exam, not a miniature fourth round.**

---

## 10 | Final learning loop

Chat owns the final queue and may change it as new evidence arrives.

Typical loop:

```text
select a very small batch
→ retrieve / identify / skeleton / exact as appropriate
→ stable: remove or lower attention
→ unstable: smallest repair
→ fresh evidence may re-open
```

Different objects use different retrieval shapes:

- broad concept relation → quick reconstruction;
- fixed hat/list/timeline → exact recall;
- analysis topic → material cue → skeleton;
- current-year formulation → exact source-grounded wording;
- repeated objective trap → decisive boundary + one representative check.

Do not force one universal card format.

---

## 11 | Final source freshness

Final review is the strictest place for current-source hygiene.

Before carrying an exact item into the exam:

- Xi / current-affairs high-delta wording must be current-year grounded;
- legal/normative wording must pass current-source recheck;
- historical stable facts may remain stable unless a real source update changes them;
- candidate-only items remain excluded until admitted.

No source support → no final exact-memory claim.

---

## 12 | Relationship to Chat / GitHub / learner state

### GitHub Current

Stores reusable durable assets:

- Mock/Final learning rules;
- canonical Knowledge;
- admitted Precision/Memory;
- analysis-output hooks;
- current-year source overlays / freshness status;
- approved mock-source metadata if later needed.

### Chat

Owns:

- Mock timing/selection judgment;
- failure diagnosis;
- routing to the smallest repair owner;
- final queue selection;
- what to drop / keep / re-open;
- final-day prioritization.

### Private learner state

Stores:

- real Mock answers / timing;
- W/U events;
- unfinished paper evidence;
- personal final queue / current weak points;
- today’s Chat decisions.

Real learner state must not enter shared GitHub Current.

---

## 13 | No Website requirement

Mock / Final L does not require:

- a dedicated Mock page;
- a Politics final-review dashboard;
- a fixed scheduler;
- a Website-generated final queue;
- Website semantic grading of analysis answers.

A future helper may be justified by real friction, but it is downstream and optional.

The Learning lane must remain fully usable with:

```text
GitHub durable assets
+ source paper / PDF
+ Chat
+ private learner evidence
```

---

## 14 | Acceptance

Mock / Final L may close when the learning rule is sufficient for Chat to:

1. decide when full Mock vs smaller timed practice is worth the cost;
2. preserve a clean first attempt;
3. distinguish objective / analysis / execution failure;
4. route failure to the smallest existing owner rather than create Mock-specific debt;
5. treat same-paper correction as repair evidence, not fresh transfer;
6. build a final queue only from admitted/high-value/current items and real weakness evidence;
7. keep current-year/high-freshness exactness source-gated;
8. remove stable work instead of replaying the whole Politics curriculum;
9. run final preparation without requiring a dedicated Website.

Real learner U remains separate.
