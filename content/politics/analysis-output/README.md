# Politics Analysis Output

Status: **CURRENT CANDIDATE — Chat-primary later-stage learning lane**

Role: define the durable GitHub asset boundary for Politics analysis-question preparation.

This is **not** a Website / Runtime lane.

The learner surface is Chat.

---

## 1 | Core model

```text
GitHub Current
= durable source-grounded analysis-output assets

Chat
= training surface + adaptive coach
  selects topic / material / depth,
  diagnoses the learner response,
  decides whether full writing is worth the time

Website
= no required role
```

Politics analysis-output preparation must remain usable even if no dedicated Analysis Output page is ever built.

---

## 2 | Canonical topic owner

Do not create a second analysis-answer database.

The canonical topic-level owner is the existing:

```text
content/politics/learning/<subject>/<chapter>.json
→ later_stage_knowledge.analysis_output_hooks[]
```

A hook may own, when source-supported:

- stable `id`;
- topic/title;
- material cues;
- owning Knowledge refs;
- retrieval target;
- small answer skeleton;
- historical output refs;
- Precision refs when relevant;
- current-year freshness status.

Those hooks are the durable bridge from Politics K to analysis-output learning.

A separate index/website copy must not become competing semantic Truth.

---

## 3 | Chat learning loop

Default analysis-output learning is deliberately low-cost:

```text
material cue
→ learner identifies what is being tested
→ learner states a small answer skeleton
→ Chat checks ownership / missing logic
→ retrieve only required source-grounded formulation
→ connect back to material
→ stop
```

Full prose is selective, not the default.

Use complete written answers mainly when:

1. the learner is first calibrating an important question family;
2. material → principle → skeleton conversion is unstable;
3. time-bounded delivery itself needs evidence;
4. Mock/final practice explicitly requires full output.

A stable topic may be trained with identification + skeleton only.

---

## 4 | What GitHub stores

GitHub stores durable reusable assets only:

```text
topic identity
material cues
owning principle / political position
answer skeleton
source-grounded exact formulations
current-year overlay refs
source/freshness status
```

GitHub does **not** store:

- Kian's real practice answers;
- today's Chat diagnosis;
- personal weakness ranking;
- temporary next-step decisions;
- learner score/progress;
- free-form Chat transcripts.

Those remain private learner/Chat context.

---

## 5 | Current-year overlay rule

Historical output material may provide a scaffold, but high-delta current wording must remain replaceable.

Use:

```text
stable topic / principle owner
+ historical output scaffold when useful
+ current-year designated source overlay
→ Chat-ready current answer asset
```

Do not rewrite the stable topic owner merely because annual wording changes.

When a 2027/current designated recitation or current-affairs source is bound, add only the source-grounded delta needed for:

- exact formulation;
- current policy wording;
- current examples/material;
- current-year answer emphasis.

No source support → no exact formulation claim.

Xi/current-affairs and legal/normative material use the strongest freshness gate.

## 6 | Subject behavior

The five Politics subjects do not need symmetric Output banks.

### Marxism
Primary skill:
```text
material
→ choose the exact principle
→ state only the minimum relevant principle
→ explain the material relation
→ method / implication when warranted
```

Avoid universal "write every dialectics principle" templates.

### Mao / theory development
Do not invent a dedicated Output bank for symmetry.

Create/promote hooks only where Current Knowledge + designated output source justify them.

### Xi / New Thought
Primary skill:
```text
material
→ locate policy/theory level
→ stable conceptual skeleton
→ current-year exact wording/delta
→ material connection
```

Current-year overlay is essential.

### History
Primary skill:
```text
material/event
→ locate historical stage
→ cause / development / turning point / evaluation
```

Do not reduce analysis answers to meeting-name lists.

### Ethics / Law
Primary skill:
```text
situation
→ identify normative/legal layer
→ principle / right-duty / rule-of-law relation
→ judgment
→ connect back to conduct/material
```

Current legal/normative exactness remains source-gated.

## 7 | Chat depth policy

Chat decides the current depth.

Useful levels:

```text
IDENTIFY
= what is this material testing?

SKELETON
= what 3–5 answer moves belong here?

EXACT
= which source-grounded wording must be retrieved accurately?

DELIVER
= produce complete prose under the requested time constraint
```

These are Chat training depths, not Website states and not mandatory stages for every topic.

Default:

```text
IDENTIFY + SKELETON
```

Add `EXACT` only where source/current-year wording matters.

Add `DELIVER` only where full written output earns its time cost.

---

## 8 | Source / freshness guard

A hook may be structurally useful before current-year exact wording is available.

Therefore distinguish:

```text
topic/skeleton usable
≠ exact formulation current
```

Examples:

- `STABLE_HISTORICAL` may support immediate structural practice;
- `HISTORICAL_OUTPUT_BASELINE_CURRENT_YEAR_RECHECK_REQUIRED` supports skeleton practice but not frozen exact wording;
- `VERY_HIGH_DELTA_REFRESH_REQUIRED` blocks current-year exact phrasing until refreshed;
- legal/current normative exactness requires current-source recheck.

Chat must respect the hook's current-year status before requesting exact wording.

---

## 9 | No Website requirement

Analysis Output L is Chat-primary.

There is no requirement to create:

- Analysis Output page;
- dedicated Runtime;
- answer-template dashboard;
- per-topic progress UI;
- scheduler;
- Website grading.

If later real use proves that a small Website helper materially reduces friction, that is a separate downstream decision.

The default is:

> **GitHub stores the assets; Chat teaches and tests them.**

---

## 10 | Acceptance

Analysis Output L may close only when the accepted hooks and learning rule are sufficient for Chat to:

1. select a source-grounded topic;
2. generate or use a suitable material cue;
3. judge material → principle identification;
4. judge the learner's answer skeleton;
5. retrieve only legitimate exact/current wording;
6. request full prose selectively;
7. repair the smallest real output failure;
8. avoid inventing unsupported topic banks or annual wording.

Website/Runtime acceptance is not required for this lane.

Real learner U remains separate.
