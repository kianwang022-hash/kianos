## 0. Planning rule

Politics maturity is **ability-gated first, calendar-aware second**.

Dates may constrain capacity, but calendar cutoffs do not manufacture readiness.

The sequence is:

```text
current ability/evidence
→ identify Protect-70 threat
→ train the smallest responsible capability
→ collect appropriate evidence
→ update forecast
→ advance only when the next phase has real prerequisites
```

Hard constraints:

- Protect 70 work outranks Push 75 upside until the floor is credible.
- Xiao1000 remains full learning material and is not reused as unbiased score calibration.
- Objective maturity does not imply Analysis maturity.
- Analysis may start before later Source arrives, but only with source-grounded stable principles / skeleton / material-binding training.
- current-year exact wording / current affairs / recitation debt waits for approved current-year Source.
- Website executes approved learner actions; Chat owns diagnosis, compression, planning and most Analysis coaching unless real friction proves a Website helper is needed.
- no second Politics scheduler, learner ledger, Memory engine, Home, packet, or runtime ecosystem.

Therefore the maturity program must **not** rebuild these systems merely because later phases are not finished.

## Material remaining gaps

The highest-bar requirements expose three major gaps:

1. **Objective calibration / Forecast**
   - Xiao1000 is intentionally contaminated by learning exposure;
   - Protect-70 reliability therefore needs a separate appropriate evidence source and explicit uncertainty;
   - current progress/evidence can support structural forecasts before it can support a narrow final-score band.

2. **Analysis-output**
   - first-round understanding and objective performance do not prove written-output ability;
   - Principle Retrieval, Skeleton, Material Binding, source-grounded Formulation Retrieval, timed prose and whole-paper delivery need their own training/evidence chain.

3. **Future-source ingestion**
   - handbook / current affairs / Xiao8 / Xiao4 are annual and freshness-sensitive;
   - current-year material is not yet fully available/approved;
   - ingestion, delta, supersession, invalidation and fallback behavior must be ready before arrival without fabricating 2027 content.

These three gaps define the maturity mainline.

# 3. Stage P1 — First-round Objective engine reaches usable structural closure

State: **ACTIVE / mostly existing system; maturity proof still required**

## Goal

Create the smallest first-round engine that can plausibly support the Objective part of Protect 70:

```text
understand relation
→ compress
→ retrieve exact high-value distinctions
→ judge propositions
→ control multi-select boundaries
→ transfer to unfamiliar wording
```

This stage is not complete merely because all Natural Units/pages exist.

## Existing assets to reuse

- Chengfeng Natural Unit path;
- Xiao1000 Workbench;
- refined backside Content;
- Wrong / Uncertain evidence;
- Review → Chat batch diagnosis;
- selective Memory;
- exact Chengfeng return locators;
- current private learner evidence.

## Tasks now

### P1.1 Structural coverage reconciliation

Prove that:

- all required first-round Natural Units are represented;
- every Xiao1000 question has defensible first-ready timing;
- decisive cross-Unit dependencies are not hidden by a current-unit hit;
- question ownership does not create a second learning order.

Output:

- coverage/gap report;
- bounded repairs only where actual missing/incorrect ownership exists.

### P1.2 W/U compression proof

Prove that learner pressure can be compressed from:

```text
many question events
→ few root causes
```

without converting every Wrong / Uncertain question into durable debt.

Required causes must at minimum distinguish:

- conceptual relation failure;
- wording / hat / scope precision;
- chronology / actor / identity;
- multi-select boundary;
- incomplete source coverage;
- careless / execution error;
- unresolved / insufficient evidence.

Do not create a heavyweight taxonomy if current evidence already supports the distinction.

### P1.3 Memory admission audit

Attack:

- candidate = debt leakage;
- unsupported wording entering Memory;
- broad conceptual relations being memorized when reconstruction is cheaper;
- old/stale candidate evidence selecting current tasks;
- Memory volume exploding faster than learning.

Use existing cross-day profile; do not create fixed spaced repetition.

### P1.4 Objective load model

Maintain the real learning load separately for:

- 528 single-choice;
- 620 multiple-choice;
- Natural Unit throughput;
- W/U rate;
- W/U → repair compression;
- Memory admission/retention;
- real Politics minutes.

This is a workload/forecast input, not an exam-score converter.

## Exit gate

P1 exits when:

- first-round coverage has no material structural blind spot;
- multi-select and precision failures are visible in evidence rather than hidden inside aggregate W/U;
- Memory pressure is bounded;
- stable correct work can stay cheap;
- structural progress can be forecast without pretending Xiao1000 predicts final score.

Passing P1 means **Objective engine usable for learning**, not “Objective 40+ proven.”

# 4. Stage P2 — Objective calibration + Protect-70 Forecast

State: **READY TO DESIGN NOW; score evidence activates only when appropriate source exists**

## Goal

Answer, with explicit uncertainty:

> Is Objective performance becoming strong enough to protect the 70-point path, and what exact capability still threatens it?

## P2.1 Calibration-source contract

Define acceptable Objective calibration evidence.

Requirements:

- separate from fully learned Xiao1000;
- representative enough to expose single vs multiple-choice weakness;
- low enough contamination for the intended inference;
- source provenance and exposure history known;
- no conversion of one practice set into a fake national-exam guarantee.

Possible evidence families may include official/current-year mock evidence when available; the exact accepted source must be bound before use.

## P2.2 Forecast model

Forecast must output ranges / states, not fake point estimates.

Early valid outputs:

- Natural Unit structural progress;
- Xiao1000 learning load;
- single/multiple W/U pressure;
- root-cause compression;
- Memory pressure;
- minutes / throughput;
- likely remaining workload under P20/P50/P80 capacity.

Later valid outputs, once calibration evidence exists:

- Objective reliability band;
- Protect-70 threat state;
- Push-75 upside state;
- dominant uncertainty source.

## P2.3 Adversarial parameter grid

At minimum attack:

- Natural Unit pace 30% slower;
- multiple-choice materially weaker than single-choice;
- W/U much higher than expected;
- many W/U collapsing to one root cause;
- Memory relapse;
- 30% capacity day / multi-day bad week;
- missing timer / missing packet fields;
- apparent stability caused by incomplete representative sampling.

For each case record whether the recommended learner action changes.

## Exit gate

P2 does not require a narrow final total-score prediction.

It exits when:

- early Forecast is decision-safe;
- Objective score inference uses an accepted calibration source or remains explicitly UNKNOWN;
- the system can identify what currently threatens Objective contribution to Protect 70;
- conclusion-flip sensitivity is visible.

# 5. Stage P3 — Analysis foundation before current-year recitation Source

State: **READY TO BUILD NOW**

## Goal

Do not wait until late November to discover that written output is weak.

Build low-cost transferable Analysis abilities without fabricating current-year wording.

Training chain:

```text
material cue
→ IDENTIFY owning principle / position
→ SKELETON 3–5 moves
→ MATERIAL BINDING
→ source-grounded formulation retrieval where stable
→ selective timed prose
```

## P3.1 Analysis task geometry

Prepare source-grounded task families:

- Principle Retrieval;
- competing-principle discrimination;
- Skeleton construction;
- Material Binding;
- stable Formulation Retrieval;
- Complete Synthetic Analysis;
- ambiguous/stress variants.

Generated/synthetic tasks require attack for:

- ambiguity;
- answer leakage;
- unnatural material;
- multiple equally valid ownership without rubric support;
- unsupported wording;
- source legitimacy.

## P3.2 Analysis evidence model

Evidence must distinguish:

- first IDENTIFY;
- first SKELETON;
- first Material Binding;
- repaired output;
- new-material transfer;
- exact-formulation retrieval;
- timed full answer;
- whole-paper execution.

Do not reduce these into one mastery score.

## P3.3 Scoring / rubric uncertainty

Before a numeric Analysis score can materially narrow Protect-70 / Push-75:

- bind an accepted rubric / anchor set;
- preserve scorer/model uncertainty;
- prevent one Chat/model score from becoming high-confidence truth.

Early Analysis Forecast may remain capability-level:

```text
UNKNOWN
→ can identify
→ can skeleton
→ can bind material
→ can retrieve exact source
→ can deliver timed answer
```

## P3.4 Surface decision

Default: **Chat-primary**.

Only build Website support if real execution friction appears, for example:

- repeated material segmentation interaction benefits from structured UI;
- handwriting/timed capture needs durable evidence;
- task/answer pairing is materially safer on a surface.

Do not build an Analysis page for architectural symmetry.

## Exit gate

P3 exits when Kian can demonstrate on fresh stable-source material:

- principle identification;
- usable skeleton;
- material binding;
- no dependence on fabricated current-year phrases;

and the evidence chain can represent the result.

This still does not prove current-year Analysis readiness.

# 6. Stage P4 — Current-year handbook / current-affairs delta ingestion

State: **INTERFACE PREP NOW; CONTENT BLOCKED ON REAL SOURCE**

## Goal

Make later Source arrival cheap and safe.

Required flow:

```text
real current-year source
→ provenance bind
→ compare with stable Current + legacy baseline
→ classify stable / updated / new / retired / current-year-only
→ update responsible derived/current-year asset only
→ invalidate superseded derived objects
→ freshness validation
→ Chat training
```

## P4.1 Prepare now

Define, without filling 2027 facts:

- source-family provenance fields;
- revision identity;
- delta classification;
- supersession rules;
- stale-derived invalidation;
- partial/late/low-quality/missing-source fallback;
- second-revision behavior;
- safe “stop waiting” rule.

Historical LEG26 may support geometry/topic skeletons only.

## P4.2 On source arrival

For each new source family:

- ingest real Source;
- compare against stable Current/legacy baseline;
- admit only supported Memory / Analysis formulations;
- mark current-year-only content explicitly;
- rerun affected freshness/derivation checks.

## Exit gate

P4 exits per source family, not all at once.

A source family is ready when:

- provenance is exact;
- revision/supersession behavior is known;
- derived Memory/Analysis/current-affairs assets can be invalidated correctly;
- no legacy wording is masquerading as current-year truth.

## Exit gate

The final maturity question must be answerable:

> What still threatens Protect 70, what is only Push 75 upside, what evidence supports that claim, and what is the smallest next learner action?

# 11. Stop conditions

Do not keep expanding this maturity program when:

- a current learner path is already sufficient and no real score/friction defect is shown;
- the remaining task depends on unavailable current-year Source;
- a proposed new system duplicates existing Review/Memory/Home/packet/runtime state;
- additional schema/detail would not change a learner decision;
- the only justification is “more complete architecture.”

The mature Politics system is not the one with the most machinery.

It is the one that can continuously answer, with current evidence:

> what threatens Protect 70, what is Push 75 upside, what exact capability is weak, what trains it, what evidence would prove improvement, what workload remains, and what Kian should do next.
