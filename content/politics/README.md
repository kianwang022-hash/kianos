## CBA spine

Politics should be recoverable as one exam-learning chain rather than as separate Content / Projection / Website projects.

```text
NEED / OUTCOME
→ score / capability requirement
→ SCORE_ABILITY_MATRIX.md
→ LEARNING_CONTRACT.md + exact subject/content owner

CREATE
→ Source + CONTENT_SEMANTICS_CONTRACT.md + CONTENT_HIERARCHY_CONTRACT.md
→ INTERACTION_CONTRACT.md / CAUSAL_REPAIR_POLICY.md where applicable
→ SURFACE_MAPPING_CONTRACT.md
→ static-web/POLITICS_PRODUCT_BRIEF.md
→ exact subject grammar/surface design
→ accepted learner meaning / product behavior / visual intent

BUILD
→ CURRENT.md
→ exact projection owner
→ actual Politics Runtime / Website consumer
→ local/native proof
→ Candidate Human Gate for material learner-facing UI

AUDIT
→ ACCEPTANCE.md
→ MATURITY_PACKAGE.md only when whole-subject maturity is the claim
→ independent reality attack against the built candidate
→ do not redesign Politics inside Audit

REAL USE
→ private Politics learner/runtime evidence
→ real Wrong / Uncertain / Resume / Return evidence may reopen the earliest responsible owner
```

Rules:
- Source/Content, Learning, Surface Mapping and Product/Visual are different responsibilities but one CBA chain.
- Projection may derive accepted meaning; it may not become a second Politics semantic owner.
- `projection/history/` is the **History subject (史纲)** Current projection, not archival history.
- closed maturity/audit campaigns remain provenance and do not issue new work.

## Zones

### Learning / interaction / repair policy

- LEARNING_CONTRACT.md — durable Politics learning model.
- INTERACTION_CONTRACT.md — interaction semantics.
- CAUSAL_REPAIR_POLICY.md — Politics-specific repair policy.

### Content semantics

- CONTENT_SEMANTICS_CONTRACT.md — semantic-content rules.
- CONTENT_HIERARCHY_CONTRACT.md — content hierarchy / attention ownership.
- learning/ — subject-local canonical learning owners.
- source/ — Source truth and admitted source assets.
- MATERIAL_INVENTORY.md — material inventory.
- SCORE_ABILITY_MATRIX.md — score/ability/material mapping.

### Projection / learner composition

- SURFACE_MAPPING_CONTRACT.md — explicit semantic mapping before UI.
- projection/ — exact derived projection owners. **`projection/history/` means the Politics History subject (史纲), not archival history; it is Current derived input when its chapter owners are Current.**
- derived/ — mechanically/semantically derived assets; not independent truth.

### Later-stage / exam-cycle assets

- later-stage/ — current-year/future-source lifecycle.
- analysis-output/ — Politics Analysis output/training assets.
- mock-final/ — final/mock workflow assets.
- FORECAST_MODEL.md — workload/risk forecast boundary; not a scheduler.

### Acceptance / maturity

- ACCEPTANCE.md — lane-wide claim-scoped Acceptance.
- MATURITY_PACKAGE.md — compact subject-maturity package.
- Closed fresh-independent maturity campaigns remain recoverable from Git history; they do not stay in the Current tree unless a current Acceptance owner explicitly consumes them.

### Runtime support / tooling

- tools/ — Politics-local tooling/validation.
- manifest.json / provenance.json — Current content identity/provenance support.

## Placement rule

Current work state belongs only in CURRENT.md or an explicitly bound active Issue. Product/learning truth stays in its exact owner. Maturity evidence does not become a second Current, and Projection/UI may not invent Politics semantics.

Historical audit or rollout prose is evidence only and must not issue new work.

## Compact rule

**Politics separates Source/Content, Learning, Surface Mapping, Runtime evidence and maturity; Current only routes among them.**
