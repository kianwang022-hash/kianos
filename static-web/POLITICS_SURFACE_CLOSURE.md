## 1 | Closure rule

Every Politics learner capability in #116 / `POLITICS_LEGACY_FUNCTION_PARITY.md` must end in one of these implementation dispositions:

- `KEEP` — accepted Current behavior already exists and must survive materially unchanged;
- `OPTIMIZE` — behavior is correct; geometry / hierarchy / density / typography / visibility can improve with zero semantic diff;
- `RESTORE_FROM_PROJECTION` — accepted compiled Projection already owns a learner-facing object that the current UI drops, flattens or bypasses;
- `DEMOTE` — legitimate capability exists but should not compete with the current learner action;
- `PHASE_OWNED` — real asset/capability, but not a compulsory first-round surface; show only when its phase/Current owner makes it relevant;
- `CONDITIONAL` — render only when an exact reviewed Current owner/asset exists;
- `SUPERSEDED` — historical capability must remain absent.

There is no valid state equivalent to `the asset exists somewhere but the final learner surface has no defined outlet`.

## 4 | Surface audit

### A. Politics Home

Current strengths:

- real `Continue` resolves from browser-local Politics state;
- five subjects remain freely navigable;
- useful Review / handoff exists;
- no fake mastery percentage.

Current convergence debt:

- the page still exposes chapter-count/navigation detail more strongly than the accepted quiet Home direction needs;
- `Copy Today's Handoff` remains visible even when there is no useful evidence;
- `PoliticsHomeTools.astro` still contains 9px / 12px learner-visible text, now inconsistent with the Current visible-text floor;
- normal Home should make `Continue / useful Today attention / five subject entrances` the hierarchy, not a mini course catalogue.

Disposition: `KEEP + OPTIMIZE`.

### B. Xiao1000 Workbench

Current on main. Protected.

Disposition: `KEEP`.

Do not recompose it merely because the cognition workspace is changing.

### C. Five-subject cognition workspace

This is the main product defect.

Current chapter route:

```text
Marxism C00 with Current learning_semantics
→ PoliticsCognitiveWorkspace (Golden)

all other chapters
→ PoliticsChapterRuntime
→ PoliticsCompiledGeometry
```

`PoliticsCompiledGeometry` correctly consumes exact selected Projection values, but presents all `projection_shape` variants through the same generic `primary / secondary / boundary / takeaway / exact` block grammar.

That loses the accepted visible distinction between:

```text
Marxism   relation / topology / reasoning / mechanism / boundary
History   stage / chronology / parallel cause / causal chain / turning point / evaluation
Mao       historical problem / theory response / role / position / sequence boundary
Xi        hierarchy / role / identity / goal / principle / path / exact boundary
Ethics    concept identity / normative boundary / evaluation / situational application
```

This is not missing Content and not a reason to recompile Projection. It is a renderer/consumer defect.

Disposition: `RESTORE_FROM_PROJECTION`.

### D. Chengfeng source handoff

Compiled Projection already owns per-PASS-NU:

- `surface = IPAD_MARGINNOTE`;
- exact `source_owner_ids`;
- optional exact `source_locator`;
- exact Current `look_for` refs.

Current compiled consumer does not expose `chengfeng_handoff`; generic Runtime reconstructs the source region from other adapted fields / source nodes, while Golden C00 reads its separate learning-semantics handoff.

Closure target:

```text
compiled Projection
→ one resolved handoff object
→ final workspace source companion
```

No copied Chengfeng continuous prose.

Disposition: `RESTORE_FROM_PROJECTION`.

### E. Optional closure / recall / exactness

Compiled Projection owns `optional_closure` and `first_round_exact`, but the compiled consumer currently returns only problem / primary / secondary / boundaries / exact / takeaway / next.

Closure target:

- preserve `first_round_exact` as Current-owned first-round exactness;
- expose `optional_closure` when present without making Recall mandatory;
- later-phase Recall/Precision remains phase-owned and must not become a new first-round scheduler.

Disposition: `RESTORE_FROM_PROJECTION + PHASE_OWNED`.

### F. Repair / Return

Current implementation already has strong semantics:

- precise repair payload;
- reviewed current/cross-Unit hits;
- exact source return;
- first-attempt preservation;
- persistence failure stops false advancement;
- repair → exact question / Unit Return;
- stable does not mean mastery.

Closure target is spatial integration and consistent visual weight, not a new repair architecture.

Disposition: `KEEP + OPTIMIZE`.

### G. Review / Chat

Current Review is correctly problem-only and can export a compact packet. It does not create due debt.

Do not add a mandatory Chat→web JSON round-trip simply for symmetry with old implementations. A future return payload is justified only if it changes a concrete Current action while preserving exact return.

Disposition: `KEEP + CONDITIONAL`.
