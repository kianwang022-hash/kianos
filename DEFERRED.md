# KianOS Deferred Work

Canonical lightweight parking lot: GitHub Issue #5 — **KianOS Deferred Queue**.

Use it only when the learner explicitly postpones work that has real future value (`later`, `not now`, `after the mainline`, `keep for future`). Keep each item short and concrete.

Do not use it for ordinary continuation steps, speculative ideas, implementation noise, or private learner state. Active work remains in the relevant Current owner / continuation. When a deferred item becomes active again, move it back into the active lane and check it off in Issue #5.

Rule of thumb: **if postponing it could make us accidentally lose it later, park it in Issue #5.**
