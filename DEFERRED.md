# KianOS Deferred Work

Canonical lightweight parking lot: GitHub Issue #5 — **KianOS Deferred Queue**.

This is a **KianOS-wide rule**, not a LexicalOS-specific rule. It applies to every current or future learning lane, including Xizong, English, Politics, LexicalOS, Astro/runtime, and later modules.

Use Issue #5 only when the learner explicitly postpones work that has real future value (`later`, `not now`, `after the mainline`, `keep for future`). Keep each item short and concrete, and prefix or group it by lane when useful.

Do not create separate backlog systems per lane unless there is a future concrete need. Do not use the Deferred Queue for ordinary continuation steps, speculative ideas, implementation noise, or private learner state. Active work remains in the relevant Current owner / continuation. When a deferred item becomes active again, move it back into the active lane and check it off in Issue #5.

Rule of thumb: **if postponing it could make us accidentally lose it later, park it in Issue #5.**
