# 西综教学交接

状态：已采纳工作方式；具体讲解须按原owner核对。这里是交接和覆盖记录，不是第二教材、第二Learning Contract或学习进度库。

## 目的

Chat 帮助快速理解 Lecture 的机制与结构；网站已有 KP 承接可后置的完整细节、主动回忆和查漏。压缩改变当次展开顺序，不删知识、不把“讲过”当“学完”。

本轮采用**整块备课、逐LG授课**：一次准备完整Block，之后每次只展开Kian选择的一个LG。学习回复集中于医学理解；仓库路径、版本、读取记录和验证过程留在交接文件，保存结果用一句话确认，不让维护工作占据学习对话。后置项放在该LG末尾，指向具体KP，不每次重复全Block覆盖表，也不把提问或Recall变成强制流程。

## 每个 LG 的输出

1. **母线**：本组解决什么问题，核心因果关系和与前后组的连接。
2. **必留**：维持正确理解必需的条件、方向、关键区别与例外，以及现行Learning/Content要求保留的要点。不能只讲一句总纲就称完整覆盖。
3. **可后置**：明确指向现有 canonical KP / 支持资产，并说明随后在哪里补学。至少给出稳定 KP ID 或标题；只有实际核对到精确 Source locator 时才给 Lecture 页码，未核到就明确写“未核”。后置不等于删除、掌握、必修新模块或自动Repair。
4. **短交接**：在交接文件中记录本次讲解覆盖什么、哪些尚未展开、下一步到哪个现有对象；不在每个学习回复里展开这些记录。只记录讲解覆盖，不写入个人已学/评分/完成状态。

讲解可以换措辞和例子；稳定的是结构、覆盖边界和负责位置。不要把每次完整Chat回答堆成多个竞争版本。

## 先读与写回

- 从当前 main 的 AGENTS.md 按学习意图进入，不把工程Current当个人Resume。
- 读 exact Block/Logic Group/KP、当前Learning owner和已有Framework/Guide/support，按需读对应Source。
- GitHub已有骨架与Chat新增教学表达分开标注。没有实际读取Source就写“未核对”，不能声称逐页核验或无损覆盖。
- 核对并采纳后的稳定结构优先写回现有合适owner；更新原位置，保留现有ID、语义、来源和有效内容。
- 形成稳定、可复用的讲解结构或到自然断点时再写回候选分支，并在写后 readback；不要逐条聊天同步，也不声称回复结束后存在后台持续维护。
- 不把长讲稿硬塞进短goal/closure字段，不擅加schema字段或假装网页已消费。如果现有owner/consumer不能表达所需结构，先记录最小候选与缺口，明确采用位置再改。
- 本目录可保存薄交接、覆盖索引和明确标记的未采纳提案；不复制整套Core，不成为新的医学权威。

## 覆盖记录最小格式

- 对象：System / Block / LG / KP稳定ID
- 依据：原负责文件、读取版本；Source实际读取范围或未核对
- 母线与必留：引用现有资产；新教学组织明确标记
- 后置：具体KP/支持位置与补学时机
- 完整性：已核对、未展开、待核；不可用“已学/掌握”代替
- 写回：具体修改、依据、验证、未验证与下一步

## 网页与进度边界

网站应允许先看完整Core补学，再在用户准备好时进入Recall。简略主提示用于提取，不能代替初学解释。讨论这个配合方式不等于现有Runtime已实现新的阶段切换。

严格区分：
- **Chat 已讲解**：只表示本次对话已覆盖某个教学结构；
- **Source 已完成**：只由原生 Source-contact / learner owner确认；
- **learner 已掌握 / Recall 已通过**：只由真实学习与证据链确认。

三者不能互相推断。不因讲完LG、写入教学稿或返回网页，就确认整组/整块已学。真实学习记录、Source完成确认、Recall评分、同步冲突和恢复继续由各原生owner负责。
